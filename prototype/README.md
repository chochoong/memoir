# prototype — 시연용 HTML 화면

테마와 주제를 정하고 목소리나 키보드로 이야기를 나눈 뒤, 나눈 이야기를 그대로 다시 읽는 화면입니다
(업무지시서 03 1차 흐름 · 기본). 예전 흐름(녹음 → 엽서)은 주소 뒤에 `?flow=postcard` 를 붙이면 그대로 돕니다.
`backend-agent` 서버에 연결해서 돌아갑니다. 파일은 `index.html` 하나뿐입니다.

> `frontend-client`(리액트)가 나오기 전까지 시연에 쓰는 임시 화면입니다.
> 시연이 끝나면 리액트로 옮길 예정입니다.

## 실행 방법

`backend-agent` 폴더에서 PowerShell을 엽니다.

**처음 한 번만**

```
pip install -r requirements.txt
copy .env.example .env          ← 열어서 키를 채웁니다 (아래 표 참고)
mkdir web\assets
```

**매번**

```
copy ..\prototype\index.html web\index.html
.\run.ps1 -Dev
```

브라우저에서 `http://127.0.0.1:8010` 을 엽니다. 서버가 켜져 있는 동안 PowerShell 창은 닫지 마세요.

- `web` 폴더는 git이 무시합니다. **원본은 이 `prototype` 폴더에 있는 파일**이고,
  `web`에는 실행할 때 복사만 합니다. 이 파일을 고친 뒤에는 복사를 다시 해야 반영됩니다.
- 파이썬은 3.10 이상이어야 합니다.

## .env 에 필요한 값

| 항목 | 없으면 |
|---|---|
| `AZURE_SPEECH_KEY` | 말을 글자로 바꾸지 못합니다. **이게 없으면 대화가 진행되지 않습니다** |
| `GEMINI_API_KEY` | AI 질문 대신 고정 질문 3개만 나옵니다 |
| Postgres (`PG_*`) | 대화는 됩니다. 하지만 **엽서(서버 글) · 지난 이야기 · 자서전 · 사진 저장**은 DB 에서 회차를 읽어야 해서 안 됩니다. 엽서는 「만들지 못했어요」 안내가 뜹니다 |

**리허설할 때:** 회차는 10분에 10번까지만 열 수 있습니다. 여러 번 돌려 볼 때는
`.env` 에 `CREATE_MAX_PER_WINDOW=0` 을 넣고, **시연이 끝나면 지웁니다.**

`.env` 는 절대 커밋하지 마세요. API 키가 들어 있습니다.

## 1차 인터뷰 흐름 (업무지시서 03 v1.0 · 기본)

1. **인터뷰 준비** — 테마(가족 · 나 · 취미) 하나, 구체 주제 한 줄, 보조 사진(없어도 됨)
   → 둘 다 정해야 **이 기기에서 시작** 이 눌립니다. 사진은 「골랐어요 / 올리는 중 / 올렸어요 /
   올리지 못했어요」 를 글로 따로 보여 줍니다 (고른 것 ≠ 올린 것).
2. **대화** — 캐릭터 위에 고른 테마 · 주제가 작게 보입니다. 아래 **말로 하기 / 글로 쓰기** 로
   같은 질문 · 같은 회차 안에서 바꿉니다. 마이크를 허용하지 않으면 처음부터 글로만 합니다.
3. **인터뷰 마치기** → 마지막 말씀이 저장될 때까지 기다린 뒤 닫고 → **나눈 이야기** 화면.
   질문과 내 답을 순서대로 **읽기만** 합니다. 엽서는 만들지 않습니다.

### 글로 쓰기 — 지금 서버로 되는 만큼

서버는 고치지 않았습니다. 원래 있던 텍스트 경로를 씁니다.

| 동작 | 화면이 하는 일 |
|---|---|
| 「글로 쓰기」 누름 | 모아 둔 말 끝을 먼저 올리고(`flushNow`) 마이크를 닫음 → 올림 줄이 빌 때까지 기다림 → 입력칸 |
| 쓰는 동안 | **아무것도 보내지 않음.** 서버는 낭독 3초 뒤 빈 확정을 한 번 하고 그대로 기다려서, 질문이 넘어가지 않음 |
| 보내기 (Enter) | `POST /speech {text}` → `POST /done`. 연타 · 재전송으로 두 번 들어가지 않게 막음. Shift+Enter 는 줄바꿈 |
| 한글 조합 중 Enter | 보내지 않음 (글자를 확정하는 Enter 라서) |
| 「말로 하기」 로 돌아감 | 써 둔 글은 지우지 않고 입력칸에 남겨 둠 |
| 써 둔 글이 있는데 「인터뷰 마치기」 | 「보내지 않고 마칠까요?」 를 물어봄. 취소하면 계속 |

**서버 쪽에서 정해야 하는 것 (C1, 최충 님)** — 화면이 피해 가고만 있습니다.

- 한 턴에 소리 조각이 하나라도 있으면 서버가 글(`/speech`)을 버립니다 (`controller._transcribe`).
  그래서 앞서 말씀하신 소리가 서버에 남아 있으면(`audio_bytes > 0`) 보내기를 막고
  「앞서 하신 말씀을 먼저 정리하고 있어요」 라고 안내합니다. 9초 넘게 안 비면 「말로 하기」 로 안내합니다.
- 쓰는 동안 타이머를 멈추는 「키보드 모드」 와 요청 번호로 중복을 막는 방법이 서버에 없습니다.
- **시작 입력 (C1 §1, v0.26)** — `theme`(family · self · hobby) · `topic` 을 보냅니다
  (`feature/theme-interview` 8e55163 에서 서버가 받기 시작함. 예전 서버는 모르는 칸을 그냥 버려서 같이 보내도 됩니다).
  theme · topic 은 아직 DB 에 저장되지 않아 `/record` 로 돌아오지 않으므로, 「나눈 이야기」 에 보여 줄
  테마 이름은 `title`, 주제는 `seed`(0번 조각)에도 함께 싣습니다 (`CONFIG.interview.startKeys`).
  서버는 seed 가 topic 과 같으면 한 번만 씁니다. 시작 422(틀린 테마 · 긴 주제)는 「입력을 확인해 주세요」.
- `/abort` 는 받아 적는 중인 마지막 말씀을 버립니다. 그래서 「인터뷰 마치기」 는
  남은 소리 올리기 → (받아 적는 중이면) 저장 기다리기 → `/done` → 저장 기다리기 → `/abort` 순서로 닫습니다.
- 회차가 닫히면 서버가 저절로 엽서를 굽습니다(`postcard.auto`). 화면은 엽서 요청을 하나도
  보내지 않지만, 서버 쪽 자동 굽기는 서버에서 꺼야 합니다.

### 나눈 이야기 (내용 확인)

`GET /api/sessions/{id}/record` 를 읽기만 합니다. 고치기 · 지우기 · 문체 · 엽서 버튼은 없습니다.

| 화면 | 언제 |
|---|---|
| 받아 오는 중 | 화면이 본 마지막 답이 DB 에 닿을 때까지 최대 8초 다시 읽음 |
| 목록 | 질문(회색) / 내 답(흰색). 위에 테마 · 주제 |
| 남은 답변이 없어요 | 답 없이 마쳤을 때 — **「못 불러왔다」 와 다른 화면** |
| 불러오지 못했어요 | 연결 끊김 · 503 · 시간 초과 · 404. 「다시 불러오기」 는 읽기만 함 |

서버가 회차를 먼저 정리한 경우(폴링 404)에는 정상 종료처럼 꾸미지 않고
「서버에서 인터뷰가 먼저 정리되었어요」 를 위에 띄웁니다.

### 앱 모양 / 웹 화면

**녹음 화면(대화 · 정리 중)만 휴대전화 앱 모양**(가운데 430px)으로 두고, 나머지 화면
(인터뷰 준비 · 나눈 이야기 · 지난 이야기 · 자서전 · 엽서)은 **넓은 웹 화면**으로 그립니다.
PC 처럼 폭이 760px 이상일 때만 차이가 나고, 휴대전화에서는 모든 화면이 같은 폭입니다.

- 준비: 왼쪽 테마 · 주제 · 시작 버튼, 오른쪽 보조 사진
- 지난 이야기 · 자서전 고르기: 카드 두 줄
- 아래 버튼은 화면에 고정하지 않고 내용 끝에 가로로 놓습니다
- 전부 앱 모양으로 되돌리려면 `CONFIG.ui.webLayout = false`

### 책장 넘김 시안 (기본 꺼짐)

화면이 바뀔 때 책장이 넘어가는 연출입니다. **팀 합의 전 시안이라 기본은 꺼져 있습니다**
(업무지시서 03 에서 「전체 UI 재디자인」 은 1차 제외).

- **잠깐 켜 보기** — 주소 뒤에 `?book=1` (예: `http://127.0.0.1:8010/?book=1`). 파일은 그대로입니다.
  다른 값과 같이 쓸 때는 `&` 로 잇습니다: `?book=1&flow=postcard`
- **늘 켜 두기** — `index.html` 의 `CONFIG.ui.bookFlip` 을 `true` 로. 주소에 `?book=0` 을 붙이면 그때만 꺼집니다.
- **PC (폭 760px 이상) = 두 쪽 펼침.** 가운데 접힘을 두고 왼쪽 쪽에는 제목 · 안내 · 버튼,
  오른쪽 쪽에는 목록 · 본문이 놓입니다 (준비 · 나눈 이야기 · 지난 이야기 · 자서전 · 엽서).
  화면이 바뀌면 **오른쪽 장이 접힘을 축으로 왼쪽으로 넘어가고**(뒷면에 다음 화면의 왼쪽 쪽),
  그 밑에서 다음 화면의 오른쪽 쪽이 드러납니다. 「돌아가기」 는 거울처럼 왼쪽 장이 넘어옵니다.
  녹음 화면(대화 · 정리 중)은 책이 아니라 앱 모양이라, 그리로 갈 때는 넘기지 않습니다.
- **휴대전화 = 한 쪽 넘김.** 화면 왼쪽 모서리를 축으로 한 장이 넘어갑니다.
- 속도는 `CONFIG.ui.bookSpreadMs` (PC, 기본 750ms) · `CONFIG.ui.bookFlipMs` (휴대전화, 기본 550ms)
- **넘기지 않는 경우** — 대화 화면 안의 버튼(보내기 · 말로/글로), 대화 ↔ 정리 중(녹음 화면끼리),
  기기의 「동작 줄이기」 가 켜져 있을 때. 넘기는 동안에는 버튼이 눌리지 않습니다 (연타 방지).
- 아직 없는 것: 종이가 말리는 효과, 목록이 길 때 왼쪽 쪽(제목 · 버튼)을 따라 내려오게 하기.
- 다음 화면이 아직 불러오는 중이면 넘어가는 장 뒷면에도 「불러오는 중」 모습이 찍힙니다 (넘긴 뒤 곧 채워짐).

## 개발 시안 — 2~7차 「혼자 준비하는 일」 (FE-01~06)

2~7차 통합 업무지시서 v1.1 의 **A(외부 결과 없이 준비)** 작업을 한 화면에 모았습니다.
**합성 자료로만 돌고, 서버에 아무것도 보내지 않으며 저장하지 않습니다.** 평소 화면에는 나오지 않습니다.

- 여는 법: 주소 뒤 `?lab=1` (탭을 바로: `?lab=fe03`) 또는 오른쪽 위 ⚙ → 「개발 시안 열기」
- 각 시안 아래 회색 「시험용」 줄에서 성공/실패 · 빠름/느림 · 상태를 바꿔 볼 수 있습니다.

| 작업 | 시안에서 볼 수 있는 것 | 다음 단계 (규격 필요) |
|---|---|---|
| FE-01 부분 수정 | 답에서 끌어 고른 **그 위치만** 고치기 · 지우기 · 마지막 취소 · 모두 되돌리기. 같은 말 두 번째 · 이모지 · 줄바꿈 · 한글 조합 중 Enter. 질문은 못 고침. 원문은 그대로 | FE-07 범위 단위 · 원문 버전 |
| FE-02 문체 | 구어체(기본) · 소설체 · 싸이월드체. **고른 문체 / 만드는 중 / 지금 보이는 글** 을 따로 표시. 늦게 온 옛 응답 무시 · 실패 시 이전 글 유지 | FE-08 선택값 · 결과 식별 |
| FE-03 로그인 · 링크 | 로그인 성공/취소/실패, 링크 만들기 → 복사 → 쓸 수 없음 (**가짜 주소 · 실제 복사 없음**), 어르신 화면 안내 → 인터뷰 중 → 마침 / 쓸 수 없음. 링크를 열기만 해서는 마이크 안 켬 | FE-09 인증 · 링크 상태 |
| FE-04 사진 · 그림 | 사진 있음 · 없음 · 읽기 실패 · 그리는 중 · 그림 있음 · 생성 실패 · 새 그림으로 바꾸는 중. 「직접 올린 사진」 과 「그린 그림」 표시 구분, 글 버전 ↔ 그림 버전 | FE-10 그림 결과 · 오류 |
| FE-05 목록 정렬 | 기록한 순 / 일어난 순. 「기록한 날」 과 「일어난 때」 라벨 분리, 대략(1990년대) · 모름(따로 묶음) · 읽기 실패 ≠ 빈 목록 | FE-11 시점 · 정렬 책임 |
| FE-06 읽기 화면 | 같은 합성 자서전을 휴대전화 · PC 에 나란히. 두 보기의 문단이 같은지 자동 확인, 태그처럼 보이는 글은 글자 그대로. 만드는 중 · 자료 부족 · 실패 · 이전 결과 | FE-12 본문 · 문단 · 출처 형식 |

정책이 정해지지 않은 것(링크 유효 시간 · 시점 모름의 위치 · 문체 설명 문구 등)은 지어내지 않고 화면에 「임시」 · 「모의」 로 적어 두었습니다.

## 3차 인증 · 인터뷰 링크 (3-C1 초안 · v0.28)

최충 님의 `backend-agent/docs/3-C1_인증_링크_초안.md` 모양대로 만들었고, **서버 코드는 `feature/theme-interview`
(40551ea)에 올라와 있습니다.** v0.30 은 그 서버에 실제로 붙여 로그인 · 링크 발급부터 어르신 링크 끝까지 시험했습니다.

- **기본값(`CONFIG.auth.mode: 'dev'`)은 아직 `X-User-Id: dev-user` 입니다.** develop 서버가 그대로라서입니다.
- **새 서버는 `X-User-Id` 를 읽지 않습니다.** 그 브랜치에 붙일 때는 `?auth=session` 으로 열고,
  develop 에 함께 올릴 때 `CONFIG.auth.mode` 기본값을 `'session'` 으로 바꿉니다.

| 보고 싶은 것 | 주소 |
|---|---|
| 모의 로그인 (구글 · 서버 없이) | `?authMock=ok` · `new`(화자 없음 → 이름 받기) · `cancel` · `invalid_token` · `expired_token` |
| 로그인 모드 (실제 경로) | `?auth=session` — `GET /api/auth/me` 로 시작. 클라이언트 ID 가 없으면 버튼 자리에 「준비 중」 |
| 모의 어르신 링크 | `/i?linkMock=ready` · `in_progress` · `elsewhere` · `ended` · `interrupted` · `expired` · `revoked` · `invalid` |
| 실제 어르신 링크 | `/i#<토큰>` (서버에 `/api/i/*` 가 생기면) |

**로그인 (자녀)**
- Google 로그인 버튼(popup) → `POST /api/auth/google {credential}` → 서버가 `msid` 쿠키. 화면은 토큰 · 쿠키를 저장하지 않습니다.
- 로그인 모드에서는 **`X-User-Id` 를 보내지 않습니다.** 헤더를 붙이는 곳은 `idHeaders()` 한 곳뿐입니다.
- 앱을 열면 `GET /api/auth/me`. 다른 API 가 401 이면 화면 메모리를 비우고(새로 불러오기) 로그인 화면으로.
- 「취소」(popup 닫음)는 서버에 오지 않아 로그인 전 그대로. 401 은 `code` 로 문구를 고릅니다.
- 화자가 없으면(`elders: []`) 「누구의 이야기를 남길까요?」 로 이름 하나만 받습니다 → `POST /api/elders {name}` → 201 `{elder_id, name}`.
  **부를 때마다 새 화자가 생겨서** 연타 · Enter 반복 · 응답 기다리는 중에는 다시 보내지 않습니다 (실패했을 때만 다시 누를 수 있음).
  서버 상한은 1~40자이고 화면은 30자로 막습니다. 띄어쓰기만 적으면 화면에서 막고, 422 가 오면 「이름을 확인해 주세요」.
- 칸 이름: `user {user_id, name, email}` · `elders [{elder_id, name}]`. 위쪽에는 이름(없으면 이메일) · 화자 이름. `elder_id` 는 링크 발급에 씁니다.
- 위쪽에 「이름 · 화자 · 로그아웃」. 로그아웃하면 `POST /api/auth/logout` 뒤 화면을 통째로 비웁니다.
- 실제 로그인에는 `CONFIG.auth.googleClientId` (Google Cloud 웹 클라이언트 ID, 비밀값 아님)가 필요합니다. **최충 님이 만들어 전달** — 받으면 여기에 넣습니다.

**자녀 — 어르신께 링크로 보내기** (로그인 모드에서만)
- 준비 화면(테마 · 주제 · 사진)에서 「어르신께 링크로 보내기」 → `POST /api/links {elder_id, title, seed, theme, topic, photo_id?}`.
  부를 때마다 새 링크라 연타를 막습니다. 회차는 아직 안 열리고, 받은 분이 「시작」 을 누를 때 열립니다.
- **링크 주소(토큰)는 발급 화면에서 한 번만 보입니다.** 「링크 복사」(안 되면 주소를 골라 둠). 나갈 때 한 번 더 묻습니다.
  기록(⚙)에는 남기지 않습니다.
- 「링크 취소」 → `POST /api/links/{id}/revoke` (진행 중이면 인터뷰가 멈춤) → 「같은 준비로 다시 만들기」 → `.../reissue`
  (이전 링크는 자동 취소). 이미 시작한 링크는 다시 만들 수 없어 「새로 준비해 주세요」 (409 `already_started`).
- 링크로 끝난 인터뷰는 자녀의 지난 이야기에 들어갑니다.
- **보낸 링크** (준비 화면 「보낸 링크」 · `GET /api/links`, 기본 20개) — 토큰은 다시 볼 수 없어 상태 · 날짜만 보여 줍니다.

  | 상태 | 표시 | 링크 취소 | 다시 만들기 |
  |---|---|---|---|
  | ready | 시작 전 (○월 ○일까지 열 수 있어요) | ✓ | ✓ |
  | in_progress | 진행 중 | ✓ (인터뷰가 멈춘다고 한 번 더 물음) | — (이미 시작) |
  | ended | 끝남 | — (취소하면 어르신 쪽 읽기까지 410 으로 막힘) | — |
  | interrupted | 연결 끊김 | — | — |
  | expired | 기간 지남 | — | ✓ |
  | revoked | 취소함 | — | 시작 전에 취소한 것만 ✓ |

  다시 만들면 새 주소를 발급 화면에서 한 번 보여 줍니다 (이전 링크는 서버가 자동 취소). 목록을 못 읽으면 「없음」 과 다른 화면.
- 링크 주소: 배포 때 서버가 `PUBLIC_ORIGIN` 으로 완전한 주소를 주면 그대로 쓰고, `/` 로 시작할 때만 지금 주소를 붙입니다.
- 화자는 첫 화자(`elders[0]`)로 링크를 만듭니다. 서버가 만든 순서대로 주므로 늘 첫 화자입니다. 화자 고르기는 나중에 정합니다.

**어르신 링크**
- `/i#토큰` 을 열면 토큰을 읽고 **주소창에서 `#` 부분을 지웁니다.** 토큰은 기록(⚙) · 로그에 남기지 않습니다.
- 미리보기(`GET /api/i/preview`) → 상태별 첫 화면 → **「시작」 을 누를 때만** `POST /api/i/start` (연타해도 한 번).
- 진행은 지금의 대화 화면 그대로(말로 · 글로 · 인터뷰 마치기)이고, 요청은 `/api/i/session/...` 로 갑니다 (`/api/sessions/...` 는 부르지 않음).
- 끝나면 `GET /api/i/transcript` → `{theme, topic, turns:[{question, answer}]}` 로 나눈 이야기를 읽기 전용으로. 앱으로 들어가는 버튼은 없습니다.
  시작 자료와 답하지 않은 마지막 질문은 오지 않습니다(테마 · 주제는 위 칸에만). CLOSED 직후 곧바로 200 이고,
  409 `not_ended` 일 때만 잠깐 다시 읽습니다. 409 `interrupted` 는 다시 읽지 않고 「연결이 끊겼어요」.
- 보조 사진: 미리보기 · 시작 응답의 `photo_url`(`/api/i/photo`, 없으면 `null`). 시작 전에는 링크 쿠키가 없어
  토큰 헤더를 실어 받아(서버 확인) 첫 화면에 캐릭터 대신 보여 줍니다. 못 받아도 화면은 그대로 갑니다.
- 410 · 404 화면에는 주제를 띄우지 않습니다. 문구는 예시이고 대원 님과 맞춥니다.

개발 시안(`?lab=fe03`)의 어르신 화면도 같은 함수(`linkPaint`)로 그립니다.

## 예전 흐름 (`?flow=postcard`)

1. 사진 고르기 (선택)
2. **녹음 시작** → 마이크 허용
3. 캐릭터가 질문을 읽어 주고, 다 읽으면 "듣고 있어요"로 바뀝니다
4. 말을 마치고 조용히 있으면 **약 8초 뒤** 다음 질문이 나옵니다
   (3초 침묵 = 말이 끝남 + 5초 여유)
5. **녹음 정지 · 엽서 만들기** → 서버가 글을 짓는 동안 「정리 중」 → 엽서 → **엽서 저장**

### 지금 녹음 중인지 한눈에

| 상태 | 화면 |
|---|---|
| **녹음 중** | 붉은 점이 뛰는 「녹음 중이에요」 칩 · **이야기 영역을 감싸는 붉은 테** · 목소리 크기 막대 · 캐릭터 뒤 따뜻한 빛 |
| **읽어 주는 중** | 푸른 점 「읽어 드릴게요」 칩 · 테 없음 · 막대 없음 · 캐릭터가 한 걸음 물러남 |
| **정리 중** | 회색 점 「잘 들었어요」 칩 · 캐릭터가 쉼 |

붉은 테와 막대, 캐릭터 뒤 빛은 **실제 목소리 크기에 따라 진해집니다.**
말하는 동안에는 막대 아래 문구가 「잘 들리고 있어요」로 바뀌어, 마이크가
소리를 받고 있다는 것을 글자로도 알려 줍니다.

붉은 테는 **아래 버튼 자리 위에서 끊어집니다.** 화면 끝까지 내리면 테의 아랫변이
「녹음 정지」 버튼을 가로지르는 것처럼 보였습니다 (v0.9.1 에서 고침).

### 녹음 중 버튼

| 버튼 | 하는 일 |
|---|---|
| **녹음 정지 · 엽서 만들기** | 회차를 닫고 엽서를 만듭니다 (`POST /abort`) |
| (소리 없이 넘어가기) | 질문 소리가 안 나올 때**만** 나타납니다 |

**일시정지는 팀 논의로 뺐습니다**(2026-09-23). 코드는 남아 있고,
`CONFIG.ui.showPauseButton` 을 `true` 로 바꾸면 그대로 살아납니다.

> 서버에는 「일시정지」가 없습니다. 3초 동안 아무 소리도 안 올라오면 말이 끝난 것으로
> 보기 때문에, 멈춘 동안에는 아주 짧은 무음을 2초마다 올려 회차를 붙들어 두는 방식으로
> 만들었습니다. 마이크는 실제로 꺼 두므로 그 사이의 말은 녹음되지 않습니다.

**「다 말했어요」**(기다리지 않고 다음 질문으로)는 기본적으로 숨겨져 있습니다.
개발용 패널(⚙)에는 항상 있습니다. 말이 하나도 녹음되지 않은 상태에서 누르면
서버가 조용히 다시 듣기로 돌아가므로, 화면에 안내가 잠깐 뜹니다.

## 엽서 글 (기획서 ④ 카드 작성)

회차가 끝나면 **서버가 저절로 한 번 엽서를 굽습니다**(`postcard.auto`). 화면은 이렇게 받습니다.

| 순서 | 무엇을 | 안 되면 |
|---|---|---|
| ① | `GET /record` — 이미 구워졌는지 본다 | ②로 |
| ② | `POST /postcard` — 직접 굽게 한다 | 「만드는 중」 409면 ③, 그 밖은 ④ |
| ③ | 「만드는 중」이면 `/record` 를 1.5초마다 다시 본다 (최대 40초, `card.waitMs`) | ④로 |
| ④ | **안내 화면** — 실패를 임시 엽서로 덮지 않습니다 (v0.25) | — |

④ 안내 화면은 두 가지입니다.

| 경우 | 화면 | 버튼 |
|---|---|---|
| **자료 부족** — 409 `code: insufficient_material` · `no_answers`(「남은 말씀이 없어요」) | 「엽서를 만들 만큼 이야기가 모이지 않았어요」 | 지난 이야기 보기 · 마치기 (다시 눌러도 같아서 「다시 만들기」 없음) |
| **만들지 못함** — 409 `not_closed`(「인터뷰를 정리하는 중이에요」) · 503 · 502 · 404 · 시간 초과 · 연결 끊김 · 빈 응답 | 「엽서를 만들지 못했어요」 + 이유 한 줄 | **다시 만들기** · 지난 이야기 보기 · 마치기 |

409 `code: busy` 는 실패가 아니라 「굽는 중」 이라 기다립니다. code 는 2-C1 §2 (`feature/theme-interview` 2d7ece0) 이고,
code 가 없는 예전 서버에서는 오류 문구로 가립니다.

서버의 오류 문구(detail)는 화면에 그대로 띄우지 않고 기록(⚙)에만 남깁니다.
예전처럼 실패 때 임시 정리 엽서로 대신하려면 `CONFIG.card.localFallback = true`.
「서버 없이 화면만 보기」(비상 화면)는 서버가 없으니 지금도 임시 정리 엽서입니다.

①을 먼저 보는 것은 **두 번 굽지 않기 위해서**입니다. `POST` 는 이미 있어도 다시 굽습니다.

서버가 주는 것은 `{ url, title, text, caption }` 입니다. **본문 키는 `text` 입니다**(`body` 아님).

> **본문 분량** — 백엔드 `2070c59` 부터 엽서 본문은 **2~4문장 · 120자 이내**입니다.
> 서버가 굽는 그림(1500×1000)에는 사진이 없으면 넉넉히 들어가고, 사진이 있으면 본문 칸이
> 3줄이라 4문장이 오면 아래 여백이 거의 없습니다 (잘리지는 않음). 폰 화면에서는 사진이 있을 때
> 본문이 「엽서 저장」 버튼 아래로 내려가 스크롤해야 보입니다 — NOTES.md 「막혀 있는 것 1」.

완성 화면의 **엽서 저장**을 누르면 이미지 한 장으로 내려받습니다.

파일 이름은 `memoir-postcard-20260923-1830.png` 처럼 영문으로 나갑니다.
한글 이름은 환경에 따라 통째로 버려지는 경우가 있어 기본을 영문으로 두었습니다
(`CONFIG.ui.filenameAscii`).

## 지난 이야기 (보관함)

시작 화면 · 끝 화면의 「지난 이야기」에서 연다. **끝난 회차만** 최근 순으로 20개
(`archive.limit`) 보여 주고, 「이야기 많은 순」으로 바꿀 수 있다. 카드를 누르면 그날의 엽서를
다시 보여 준다 (저장도 된다). 기록이 없으면 「아직 모은 이야기가 없습니다」, 서버에서 못 읽으면
「이야기를 불러오지 못했습니다」로 **다르게** 말한다. 15초(`archive.timeoutMs`) 안에 답이 없으면
못 읽은 것으로 본다. **DB 가 있어야 한다.**

**엽서 없는 회차 (v0.27)** — 자동 엽서가 꺼진 뒤로는 새 회차 대부분에 엽서가 없다.

- 서버가 회차마다 `has_postcard` 를 주면 카드에 「엽서 있음」 / 「아직 엽서 없음」 꼬리표가 붙는다
  (`feature/theme-interview` e1efd0d. 예전 서버는 이 값을 안 줘서 꼬리표가 없다).
- **엽서 없는 회차를 누르면 그 회차의 「나눈 이야기」(질문 · 답, 읽기 전용)가 열린다.** 예전에는
  「아직 엽서가 만들어지지 않았어요」 안내만 떠서 막다른 길이었다. 아래 버튼은 「목록으로」.
- 엽서 있는 회차는 예전처럼 엽서가 열린다. 여기서 엽서를 새로 만들거나 글을 고치지는 않는다 (2차 몫).
- 예전 흐름으로 만든 회차는 테마 · 주제를 따로 적지 않아, 테마 칸에 날짜 제목이 보이고 주제가 「—」 일 수 있다.

## 자서전 만들기 (업무지시서 04 v1.1)

> **2-C1 반영 (v0.26)** — 자서전 API 의 503 은 모델이 「확인이 더 필요하다」(needs_confirmation ·
> needs_context)고 답한 경우뿐이고, 화면 문구는 「지금은 자서전을 만들 수 없어요. 엽서 선택 화면으로 돌아가 주세요.」.
> 자동 엽서가 꺼지면 엽서는 시드 도구(`tools/seed_sessions.py --bake-postcards`)나 「엽서 만들기」 로만 생기고,
> 엽서 없는 회차는 고를 수 없습니다. 고를 엽서는 서버에 **「엽서 있는 회차만」**(`/api/sessions?has_postcard=1&limit=20`)
> 달라고 해서 받습니다 (v0.27). 이 옵션을 모르는 예전 서버는 전부 주므로, 엽서 그림이 404 인 회차를 화면이 뺍니다.

지난 이야기 → 「엽서로 자서전 만들기」. 엽서가 있는 회차를 3~5장 고르면 자서전 초안의 제목 ·
본문을 보여 준다. 저장 · 목록 · 다시 만들기는 이번 범위가 아니다.

- 고를 엽서: `GET /api/sessions` 로 회차를 받고, 회차마다 `GET /postcard` 를 물어 엽서가 있는 것만
  (404 는 빼고, 그 밖의 실패는 「불러오지 못했다」). 썸네일은 그 엽서 그림이다.
- 보내는 값: `POST /api/memoirs/preview` 에 `{"session_ids": [회차 UUID 3~5개]}`.
- **실제 서버를 부른다** (v0.18 부터, main `66acce1` 의 `backend-agent/app/session/memoir.py`).
  기다리는 요청이라 몇 초 걸리고, 그동안 「자서전 초안을 쓰고 있어요」가 뜬다.
- 실패 안내는 HTTP 상태로 고른다. 문구는 서버와 같다.

  | 상태 | 화면 안내 |
  |---|---|
  | 400 | 선택한 엽서를 확인해 주세요. 3~5장을 고를 수 있어요. |
  | 404 | 선택한 엽서를 찾을 수 없어요. 목록에서 다시 골라 주세요. |
  | 422 | 선택한 엽서의 이야기 자료를 불러오지 못했어요. |
  | 502 · 응답 없음 · 그 밖 | 자서전을 만드는 중 문제가 생겼어요. 엽서 선택 화면으로 돌아가 주세요. |
  | 504 · 화면 쪽 60초 초과 | 정해진 시간 안에 자서전을 받지 못했어요. 엽서 선택 화면으로 돌아가 주세요. |

- **서버 없이 화면만 볼 때**는 주소 뒤에 `?memoirMock=ready` 를 붙인다 (`400` · `404` · `422` ·
  `502` · `504` · `invalid` · `timeout` · `insufficient` 도 된다). 이때는 화면 위에 「예시 응답
  모드」가 뜬다. 늘 예시로 돌리려면 `CONFIG.memoir.mock` 에 그 값을 넣는다.

**시험 회차 넣기** — 엽서가 있는 회차가 3개 이상 있어야 고를 수 있다. 합성 자료를 넣는
도구가 백엔드에 있다 (`backend-agent/README.md` 「자서전 초안 · 시험 회차 넣기」). 서버를 켠 채로
`backend-agent` 에서:

```powershell
python tools/seed_sessions.py --input eval/memoir_seed_A.json --manifest eval/memoir_seed_A.ids.json --api-base http://127.0.0.1:8010 --bake-postcards
```

A 세트는 `[A]` 로 시작하는 회차 5개다. **A 와 B 를 섞어 고르지 않는다** — 다른 인물의 자료다.
엽서를 구울 때 모델을 부르므로 Gemini 키가 필요하다. **이 PC 의 DB 에만 넣는다.**

서버 쪽 실패를 일부러 내 보려면 서버를 `MEMOIR_FAIL_INJECT` 를 걸고 띄운다
(`source_material_unavailable` → 422 · `generation_timeout` → 504 · `generation_failed` → 502).
**끝나면 풀고 다시 띄운다.**

## 사진을 보고 먼저 물어보기 (연결됨)

기획서 §2 「사진 분석 에이전트」입니다. 백엔드가 **사진을 올리는 그 자리에서**
분석을 걸어 두고(`photo.analyze_later`), 회차를 열 때 그 단서로 **여는 말을 짓습니다.**

그래서 화면은 이렇게 돕니다.

1. 사진을 **고르는 순간** 서버로 보냅니다 (`POST /api/photos`)
   — 어르신이 사진을 보고 시작 단추를 누르기까지의 몇 초가 분석 시간이 됩니다
2. 시작을 누르면 `POST /api/sessions` 에 **`photo_id` 를 함께** 보냅니다
3. 서버가 단서를 찾으면 **첫 질문부터 사진 이야기**가 됩니다

| 상황 | 여는 말 |
|---|---|
| 사진 없음 | 「오늘은 어떤 이야기를 들려주시겠어요?」 |
| 사진 있음 · 분석됨 | §2 가 만든 **그 사진에 대한 질문** |
| 사진 있음 · 분석 실패·지연 | 「사진 잘 받았습니다. 이 사진은 어떤 사진인가요?」 |

업로드가 실패해도 회차는 평소대로 열리고, 사진은 화면과 엽서에 그대로 들어갑니다.
아직 올라가는 중에 시작을 누르면 최대 8초까지만 기다립니다 (`waitBeforeStartMs`).

> 사진 분석에는 Gemini 키가 필요합니다. 키가 없으면 서버 로그에
> 「GEMINI_API_KEY 없음 — 사진 분석을 건너뛴다」가 찍히고 위 표의 세 번째 줄로 갑니다.

## 알아둘 것

- **엽서 글은 서버의 AI(기획서 ④ 카드 작성)가 씁니다.** 제목·본문·사진 설명이 옵니다.
  서버가 못 만들면(키·글꼴 없음, 말씀이 짧음) **「자료 부족」 / 「만들지 못했어요」 안내**가 뜹니다
  (v0.25 부터. 예전에는 화면 안의 임시 정리 엽서로 대신했습니다).
- **엽서 · 지난 이야기 · 자서전에는 DB가 필요합니다.** Postgres가 없으면 서버가 회차를
  읽지 못해, 엽서는 「만들지 못했어요」 안내가 뜨고 지난 이야기는 「불러오지 못했습니다」가 뜹니다.
- **서버가 꺼져 있으면** "서버 없이 화면만 보기" 버튼이 뜹니다. 미리 넣어 둔 대화로
  화면 흐름을 끝까지 보여줍니다. 시연장 비상용입니다.
- **오른쪽 위 톱니(⚙)** 를 누르면 개발용 패널이 열립니다. 지금 상태, 기록, 그리고
  마이크 없이 글자로 발화를 보내 볼 수 있는 입력창이 있습니다. 시연 중에는 닫아 두세요.
