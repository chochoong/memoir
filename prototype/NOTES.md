## 사용자 피드백에서 정해진 것

프로토타입을 사람들에게 보여주고 받은 피드백이 지금 화면의 근거다.

| 피드백 | 어떻게 반영했나 |
|---|---|
| 마이크 아이콘 대신 사진이 있으면 좋겠다 | 첫 화면을 사진 카드로 바꿈 |
| 제목 입력은 귀찮아서 안 쓸 것 같다 | 제목 입력을 없애고 **자동 생성** |
| 타이머가 돌아가는 건 **심문받는 느낌** | 타이머·파형을 전부 제거 |
| 듣고 있는 **캐릭터**였으면 좋겠다 | 목소리에 반응하는 캐릭터로 대체 |
| 녹음을 다시 확인하는 화면은 빼자 | 확인 화면 삭제, 끝나면 바로 엽서 |
| **다듬어지지 않은 글이 나오지 않는 것이 핵심** | 전사 원문을 그대로 보여주지 않음 |

마지막 줄이 가장 중요하다. 전사 원문("어 그게 그러니까…")은 어디에도 노출하지 않는다.

## v0.10 — 서버 엽서(§4 카드 작성) 연결 (2026-09-29)

백엔드 `9b35402` 로 **카드 작성 에이전트 v3 가 다시 올라왔다.** 이제 엽서 글을 AI 가 쓴다.
화면 안의 규칙 기반 임시 정리(`polish`)는 **실패했을 때만** 쓰는 자리로 물러났다.

### 어떻게 도는가

```
회차가 닫힘 → 서버가 저절로 한 번 굽는다 (postcard.auto)
   ↓
① GET  /record         이미 구워져 있으면 그것을 쓴다
② POST /postcard       없으면 직접 굽게 한다
③ 409「만드는 중」     굽는 중이면 /record 를 1.5초마다 다시 본다 (최대 60초)
④ 그래도 안 되면       화면 안의 임시 정리로 내려간다 — 시연은 멈추지 않는다
```

①을 먼저 보는 이유는 **두 번 굽지 않기 위해서**다. `POST` 는 이미 있어도 다시 굽는다.
그냥 POST 부터 보내면 한 회차에 AI 를 두 번 부르게 된다.

### 확인한 것 (가짜 서버로 네 경우를 돌려 봤다)

| 서버가 이렇게 | 화면은 | 걸린 시간 |
|---|---|---|
| 곧바로 글을 씀 | 서버 글 · 서버 그림(JPG) | 0.3초 |
| 12초 걸려 씀 | 서버 글 · 서버 그림 | 12.2초 |
| 503 (키·글꼴 없음) | 임시 정리 · 화면에서 그린 PNG | 0.3초 |
| 409 (담을 말씀 없음) | 임시 정리 · PNG | 0.3초 |

### 주의 — 409 에 뜻이 두 가지 섞여 있다

- 기다리면 되는 것 — 「엽서를 만드는 중입니다. 잠시 기다려 주세요」
- 기다려도 안 되는 것 — 회차가 안 끝났다 · 남은 말씀이 없다 · 확실한 말씀이 없다

서버가 둘을 구분해 주지 않아 **문구로 가린다**(`/기다|만드는 중|굽는 중/`). 잘못 갈라져도
임시 정리로 내려갈 뿐이라 화면이 멈추지는 않지만, **백엔드에 코드 분리를 요청해 둘 것.**

### 엽서 저장

서버가 구운 그림이 있으면 **그것을 내려받는다**(`.jpg`). 화면에서 다시 그린 것보다
팀이 정한 엽서 모양에 가깝고, 저장한 것과 서버에 남은 것이 같아진다.
없으면 예전처럼 화면에서 PNG 로 그린다.

### 본문 분량 — 팀과 맞춰야 한다

프롬프트는 **500자 이내**로 되어 있는데(`cef02f3`), 실제로 들어가지 않는다.

| | 서버가 굽는 그림(1500×1000) | 폰 화면(430×844) |
|---|---|---|
| 100자 | 들어감 | 스크롤 없이 보임 |
| 150자 | 사진이 있으면 빠듯함 | 마지막 줄이 버튼에 잘림 |
| 500자 | **글이 그림 밖으로 나간다** | 네다섯 화면 |

`postcard.py` 의 `BODY_LINES = 4`, 사진이 있으면 `room = 3` 이다. 가장 작은 글씨에서도
안 들어가면 **자르지 않고 그냥 그린다.** 그래서 넘친 글자가 사라진다.
**100~150자로 줄이자고 요청해 둘 것.**

## v0.9.2 — 씨앗 문장 필드 이름 (2026-09-29)

백엔드 `2cbb124` 에서 `POST /api/sessions` 의 필드가 **`postcard` → `seed`** 로 바뀌었다.
「엽서」라는 말을 진짜 엽서 기능에 쓰려고 이름 자리를 비운 것이다.

v0.9.1 까지는 옛 이름 `postcard` 로 보내고 있었다. 새 서버에서 `seed` 가 필수 필드라면
**회차가 아예 열리지 않는다(422).** 시연이 첫 화면에서 멈춘다.

지금은 **두 이름을 함께 보낸다.** 서버는 모르는 필드를 무시하므로 어느 쪽 서버에
붙어도 돌아간다. 백엔드가 정리되고 나면 `postcard:` 한 줄을 지운다.

```js
seed: CONFIG.session.seed,       // 새 이름
postcard: CONFIG.session.seed,   // 옛 이름 — 나중에 지운다
```

> **확인할 것** — main 의 `StartReq` 가 `extra="forbid"` 라면 옛 이름을 함께 보내는 것이
> 오히려 422 가 된다. 그 경우 `postcard:` 줄을 지워야 한다.

## v0.9.1 에서 고친 것 (2026-09-29)

둘 다 **화면이 겹쳐 보이던 문제**다. 기능은 그대로다.

**1. 시작 화면 — 세로로 긴 사진을 고르면 버전 줄이 「녹음 시작」 버튼에 가렸다.**

사진 카드가 화면 높이의 44%까지 커지면서 아래 내용을 버튼 밑으로 밀어냈다.
`max-height: min(44dvh, calc(100dvh - 478px))` 로 바꿔 **화면이 짧을수록 카드를
먼저 줄이게** 했다. 화면이 넉넉하면 예전과 같다.
(높이 580~896px × 폭 430·900px 에서 확인 — 900×580 한 경우만 스크롤이 필요하다)

**2. 녹음 중 — 붉은 테의 아랫변이 「녹음 정지」 버튼을 가로질렀다.**

원인이 둘이었다.

- `.screen` 의 `animation: … both` 가 애니메이션이 끝난 뒤에도 효과를 붙들고 있어서
  그 화면이 **쌓임 기준(stacking context)** 으로 남았다. 그 안의 버튼(`z-index: 5`)이
  화면 전체에 깔리는 테(`z-index: 4`)보다 **아래**로 내려갔다.
  → `both` 를 **`backwards`** 로 바꿔 끝난 뒤에는 효과가 남지 않게 했다.
  (`backwards` 는 시작 전에만 적용되므로 나타나는 모습은 그대로다)
- 그래도 테가 버튼 뒤로 숨는 모양이 어색해서, **테를 버튼 자리 위에서 끊었다**
  (`inset: 0 0 calc(94px + safe-area)`). 이야기 영역을 감싸는 닫힌 사각형이 된다.

> **z-index 만 올려서는 안 된다.** 쌓임 기준 안에 갇힌 요소는 바깥 요소와
> z-index 를 비교하지 않는다. 화면에 `transform` · `opacity` · `filter` · `animation`
> 을 걸 때마다 이 문제가 되살아날 수 있다.

## 지금 막혀 있는 것

### 1. 사진이 있으면 엽서 본문이 버튼 아래로 내려간다 ← 가장 큰 것

**분량은 해결됐다** — 백엔드 `2070c59` 에서 본문이 120자 이내가 됐고, 말씀을 엮어
쓰되 말씀에 없는 말은 더하지 않는 규칙도 들어갔다 (위 「v0.13」 참조).

남은 것은 배치다. 사진이 있으면 첫 화면에 본문 첫 줄만 보이고 나머지는 「엽서
저장」 버튼 아래에 있다. 스크롤하면 보이지만 어르신이 스크롤할 줄 아신다고
기대하기 어렵다. 사진 칸을 줄이거나, 본문을 사진 위에 얹거나, 버튼을 본문 아래로
내리는 방법이 있다 — 팀에서 정한다.

> **계속 지켜야 할 것** — 말씀을 잇는 것은 되고, 말씀에 없는 사실·감정·장면을
> 더하는 것은 안 된다. 가족이 보는 글이다. 안 하신 말이 엽서에 적히는 것이
> 이 서비스에서 가장 나쁜 실패다.

AI 호출을 프론트에서 하지 않는 이유는 API 키 때문이다. 브라우저 코드에 키를 넣으면
화면을 여는 누구나 볼 수 있다. 사진 분석(§2)도 같은 이유로 서버에서 돈다.

### 2. ~~중단 직후 409 한 번~~ — v0.13 에서 고침

「녹음 정지」를 누른 직후 화면이 `tts-done` 을 한 번 더 보내서 서버가 409 로 거절했다.
이제 정지를 누르면(`stopping`) 낭독이 끝나도 `tts-done` 을 올리지 않는다
(`readQuestion` 참조). **실제 서버로 확인할 것** — 회차를 돌려 보지는 못했고,
화면이 스크립트 오류 없이 뜨는 것까지만 확인했다.

### 3. 이름이 api.ts 와 다른 함수 둘

`uploadPhoto` · `photoUrl` 이 `frontend-client/src/api.ts` 와 이름이 다르다.
기능은 같다. 리액트로 옮길 때 맞추면 편하다. 급하지 않다.

## 알아 두면 좋은 것

- **8초의 정적은 고장이 아니다.** 말을 마치면 3초 뒤 "말이 끝났다"고 판단하고,
  다음 질문까지 5초 여유를 둔다. 어르신이 잠깐 쉬실 때 끊지 않으려는 설계다.
- **회차는 10분에 10번까지.** 서버가 요금 폭주를 막는 상한이다. 리허설을 여러 번
  돌릴 때는 `.env` 에 `CREATE_MAX_PER_WINDOW=0`, **시연 전에 지운다.**
- **사진은 고르는 순간 올라간다.** 서버가 그때 분석을 시작하므로, 고르고 2~3초 뒤에
  시작을 눌러야 첫 질문이 사진 이야기가 된다. 바로 누르면
  "사진 잘 받았습니다. 이 사진은 어떤 사진인가요?" 가 나온다.
- **사진 저장에는 DB 가 필요하다.** Postgres 가 없으면 사진 업로드가 503 으로
  거절되고, 그러면 사진 분석도 안 돈다. 대화와 엽서는 DB 없이도 정상이다.
- **`web/` 은 복사본이다.** 원본은 `prototype/index.html`. 고칠 때마다 다시 복사해야
  화면에 반영된다. 브라우저는 `Ctrl + Shift + R` 로 새로고침.
- **버전을 눈으로 확인할 수 있다.** 시작 화면 아래 회색 글씨(`CONFIG.version`).
  "고친 게 반영이 안 된 것 같다" 싶을 때 이 한 줄부터 본다.
