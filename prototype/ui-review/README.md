# 내말싸미 UI 검토용 시안

## 추가 Git 공유 · 2026-11-10 · 디자인·조작감 정리

앞서 공유한 `c104094` 이후의 흰 바탕·버건디 로즈 색상과 은은한 탄성·하단 아이콘 스냅을 사용자 요청으로 **기존 `codex/frontend-ui-review` 브랜치에 추가 커밋·푸시**합니다. 이번 추가 공유는 UI 디자인·조작감과 관련 결정 문서만 포함하며, 아래의 ‘로컬 변경/커밋·푸시 전’ 설명은 이 추가 공유 이전의 작업 이력입니다.

현재 검증은 **175/175 테스트 · JS/CJS 구문32개 · 서버 기준 소스9개 일치**입니다. 기존 화면 흐름과 서버 연결 준비 범위를 사용하며 실제 로그인·음성 수집·책 저장 연동과 서비스 배포는 후속 작업입니다. 앞서 공유한 PDF 이후의 최신 외형과 움직임은 이 브랜치의 UI를 기준으로 확인합니다.

## 최신 동작 기준 · 2026-11-10 · 은은한 탄성·하단 아이콘 스냅

사용자가 전체의 **은은한 탄성**과 모바일 하단 메뉴의 **아이콘 스냅**을 선택했고, 실제 적용 여부 확인 후 본 UI에 반영했습니다. 비교 화면에만 남겨 둔 상태가 아닙니다.

- `interaction-motion.css`/`.js`를 마지막에 연결했습니다. 일반 버튼의 작은 눌림·복원, 짧은 화면/대화상자 등장, 선택 표시의 작은 탄성을 사용합니다.
- 모바일 메뉴의 선택 배경은 아이콘 뒤에서 즉시 켜집니다. 이동하는 배경은 없으며 링크·글자는 고정하고 아이콘만 약165ms 반응합니다.
- 페이지 독서는 가로 드래그를 따라오고, 짧은 이동·경계·취소에서는 복귀합니다. 기존 넘김 방식과 읽던 위치, 시스템/독서 움직임 줄이기를 사용합니다.
- 로컬 검증: 기존 테스트 **175/175**, JS/CJS 구문 **32개**, 서버 기준 소스 **9개** 일치. Chrome PC/320px에서 메뉴·터치 영역·키보드·팝업·독서 드래그를 확인했습니다. 실제 스마트폰 터치 확인과 서비스 배포는 별도이며 Git 공유는 위 추가 공유 절을 따릅니다.

## 최신 브라우저 확인

- 최신 이름 강조 선택은 특수문자8종의1번 낫표(「 」)로 확정·반영했습니다. `「나」의 기록/자서전`, `「말랑」의 기록/자서전`으로 표시하고 저장 이름·ID·기록 귀속은 유지합니다. PC/320px의 한 글자·일반·긴 이름과 버튼48px·넘침 없음·Enter/Space를 확인했습니다. 현재 반영된 피드백은 확정·반영 완료이며, 추가 필수 디자인 선택은 없습니다.

- 홈 핵심 문구의 가독성 피드백도 반영했습니다. 그 문장만 UI 고딕과 자간-.02em으로 조정하고 크기·색·문구는 유지합니다. 360px 이하에서는 자연스러운 줄바꿈과 카드 최소높이690px로 조정해 320px에서 버튼·안내와 삽화가 겹치지 않습니다. PC1440/390/320px 넘침 없음 확인. 표지의 Noto 명조나 독서 본문은 바꾸지 않았습니다.

- 최신 제목·포인트색 피드백을 반영했습니다. 엽서와 책장은 실제 주인공 이름을 제목에 넣고 바로 옆에 밑줄 ‘변경’을 둡니다. 별도 주인공 줄은 홈에만 남깁니다. 두 제목 영역은 밝은 중성 바탕·먹색 제목·진회색 설명, 이름/변경만 버건디 로즈(#99546D)입니다. 다른 화면 테마·3색 표지·독서 본문은 유지합니다.
- 엽서 선택 모드의 작업 제목과 소유자 안내, 검색·문체 왕복 후 선택3장 보존, 주인공0명 등록 안내, 320px 긴 이름·특수문자 안전 표시·가로 넘침 없음과 제목 초점을 확인했습니다. 현재 자동 테스트104개와 변경 JS 문법 검사를 통과했습니다. 실제 색각이상 사용자/유형별 시뮬레이션 검증은 아닙니다. 추가 백업67파일은 [변경 영향](CHANGE_IMPACT.md)에 기록했습니다.

- 최신 B 피드백: 책장 표지의 미세 질감·무광은 유지하고 제목을 무료 Noto Serif KR 600으로 실제 임베딩했습니다. WOFF2 약1.11MiB, 현대한글11,172자·ASCII 전체, OFL 원문·출처·지원 범위는 [폰트 기록](fonts/PROVENANCE.md)에 있습니다. 표지에만 적용하며 PC1440px/320px·긴 제목에서 기존 치수와 전체 제목 접근을 확인했습니다. 독서 본문·페이지 계산은 변경 전 백업과 같습니다.
- [추가 결정](UI_DECISIONS.md)과 [변경 영향·중간 백업](CHANGE_IMPACT.md)을 분리해 기록합니다. 본문은 기본 명조·기존 글꼴 선택 유지로 확정됐고 기존 코드가 이미 충족함을 확인했습니다. 주인공 변경도 추가 비교2번(이름 옆 순환 화살표+밑줄 ‘변경’)으로 확정돼 홈·엽서·책장에 반영했습니다. 48px 조작 영역·Enter/Space·320px 긴 이름·이름 미등록 상태를 확인했습니다. 표지는 승인된3색을 유지하며 새 색 추가는 향후 선택사항입니다. 백업은 시안 파일용이고 브라우저 탭의 입력 글을 저장하지 않습니다.

- 2026-11-09 연속 작업: 홈의 최근 이야기 행을 아이콘·제목·날짜·빈 공간·화살표를 포함한 네이티브 버튼 하나로 바꿨습니다. Enter/Space 열기, Esc/닫기 후 해당 행 초점 복귀, 중첩 조작 요소 없음, 320px에서 긴 제목 줄바꿈과 가로 넘침 없음을 확인했습니다. 브라우저 자체의 글자 확대 검증은 포함하지 않습니다.
- 이야기 준비 화면에서 계정과 이야기 주인공을 분리해 표시합니다. 이름 하나로 첫 주인공 등록, 기존 주인공 선택·추가, 세 주제 선택 후 같은 기기 시작 또는 예시 초대 준비가 가능합니다. `?speakers=empty#prepare`는 화자 0명 예시입니다. 엽서·미완성 이야기·책을 화자별로 나누며, 작성 중 다른 화자/회차로 옮겨 섞지 않습니다.
- 초대 주소는 발급/재발급 직후 한 번만 표시하고, 떠날 때 화면에서도 제거합니다. 목록에는 상태만 남습니다. 복사 완료는 전달 완료로 표시하지 않습니다. 이전 주소 무효화, 진행 중 취소의 중단 경고, 완료 회차의 취소/재발급 없음, 회차가 있는 초대의 재발급 금지를 확인했습니다. 취소한 회차의 작성글은 준비 화면의 접힌 영역에서 확인할 수 있으며 완료 이야기·엽서로 처리하지 않습니다.
- 초대 진입은 관리자 메뉴 없이 주제 확인→시작 버튼 하나→인터뷰입니다. 완료 이야기는 모으는 사람이 나중에 확인하고 명시적으로 엽서를 만듭니다. 원래 라디오·ON AIR를 재사용하며 입력 크기 0에서도 ON AIR는 켜지고 레벨·파형만 멈춥니다. 실제 음성 입력·재생은 없습니다. 캐릭터·낱말카드·추가 낱말 선택은 넣지 않았습니다.
- 사용자가 버건디·네이비·딥그린 표지 세 가지 순환을 선택했습니다. 무광 표면결·금박/아이보리 제목·얇은 책등 홈을 책장 표지에 적용했으며 기존 표지 치수와 책장·리더 배치를 유지합니다. [원본 후보 비교](cover-comparison/index.html)를 보관했습니다.
- 최신 피드백에 따라 엽서 선택의 「엽서 보기로 돌아가기」는 가로 위치·230.56×48px 크기를 유지하고, 설명 아래/엽서 영역 위 간격을 각각 24px로 맞췄습니다(PC 1440px). 별도 피드백 채팅 「내말싸미 UI · 사용자 피드백」에서 접수할 항목은 [피드백 기록](USER_FEEDBACK.md)에 모읍니다.

- 완료된 연구와 사용자의 최종 선택을 반영했습니다. PC(761px 이상)는 기존 네 메뉴를 상단에 고정하며, 좁은 PC에서는 두 줄로 배치합니다. 모바일의 하단 네 메뉴는 유지합니다. 독서 화면은 이 전역 메뉴 변경에서 제외합니다. 1440px 스크롤 고정, 1024px·761px 경계의 가로 넘침 없음, 모바일 390px의 기존 하단 메뉴, 계정·이용 안내 열기/닫기를 확인했습니다.
- 보기 설정은 글자 크기·줄 간격을 첫 두 항목으로 옮겼습니다. 제목·닫기는 그대로 두고 설정 본문만 스크롤하며, 다시 열면 맨 위에서 시작합니다. 390×568에서 두 설정의 첫 노출과 스크롤 중 제목·닫기 고정을 확인했습니다. 빈 책갈피 목록은 읽는 화면 오른쪽 위에서 추가한다고 안내합니다.
- 유효한 본문 위치가 저장된 책은 기존 「읽기」를 「이어 읽기」로 표시합니다. 표지만 연 기록·깨진 값·본문 변경·저장소 차단은 「읽기」로 복구합니다. 브라우저에서 표지만 열고 돌아오기, 본문 이동 후 표시 전환, 같은 본문 재진입을 확인했습니다.
- 낮은 PC(높이 740px 이하)의 기존 독서 도구를 얕게 배치했습니다. 상단 48px·하단 약 71px이며 페이지 위 여백은 메뉴 상태와 무관하게 일정합니다. 이전 검증에서 1440px 폭의 높이 560/640/720 메뉴 전환 전후 책 좌표·본문·쪽수 일치와 본문 넘침 없음을 확인했습니다. 560px의 화면 맞추기·글자32px/줄2.3, 720px의 기본 비율·글자18px/줄1.6도 확인했습니다. 이번 후속 작업은 리더 배치·페이지 계산을 변경하지 않았습니다.
- 인터뷰는 「마치기 → 이야기 확인하기 → 예시 엽서 만들기」로 나눴습니다. 완료만으로 엽서를 추가하지 않습니다. 「나중에 만들기」로 닫은 이야기는 엽서보기의 접힌 「엽서로 만들기 전의 이야기」에서 다시 열 수 있습니다. 이야기와 새 엽서는 현재 탭 메모리에만 있으며 서버 저장은 연결하지 않았습니다.
- 완료 취소·Esc 후 작성 중인 글과 질문 유지, 제출 답변과 미전송 글의 공백·줄바꿈 보존, 빈 완료 차단, 완료/엽서 만들기 연속 두 번 클릭의 중복 방지, 나중에 재조회, 명시적 만들기 전후 엽서 6장→7장, 새 인터뷰 질문 초기화를 브라우저에서 확인했습니다. 모바일 320×568의 긴 본문은 본문 영역만 스크롤하고 두 확인 버튼이 화면 안에 보입니다.
- 기본 페이지 보기는 책 비율입니다. 단면은 폭/높이 약 0.707, PC 양면은 약 1.414로 화면 안에 맞춥니다. 기존 보기 설정 안의 「화면 맞추기」 체크 한 개를 켜면 넓은 보기가 됩니다. 기본값은 꺼짐이며 기존 독서 설정과 함께 이 브라우저에 저장합니다.
- 상단 제목/뒤로/책갈피와 하단 진행률/목차/책갈피/보기 설정은 책 위에 겹쳐 표시합니다. 메뉴 표시 여부에 따라 책 크기·본문·쪽수가 바뀌지 않으며, 메뉴 전환에는 다시 페이지를 나누지 않습니다. 책 바깥 여유 공간은 메뉴 상태와 무관하게 일정하고 하단에 메뉴 복원 버튼 공간을 둡니다.

## 현재 화면 흐름

PC·모바일은 같은 화면 파일과 자서전 데이터를 사용합니다. 주 메뉴는 **처음가기 · 인터뷰 하기 · 엽서보기 · 자서전 보기** 네 개이며, 모바일은 하단 메뉴를 유지합니다. 개별 책을 읽을 때는 공통 독서 도구를 표시합니다.

1. 인터뷰에서 질문 확인 → 말하기 시작 → 잠시 쉬기·다시 말하기 또는 글로 쓰기를 시험합니다. 실제 소리를 받거나 재생하지 않습니다. 「마치기 → 이야기 확인하기」로 제출 답변과 작성 중인 글을 함께 확인하며, 빈 이야기는 완료하지 않습니다. 「예시 엽서 만들기」를 따로 눌러야 엽서 목록과 자서전 선택 대상에 추가됩니다. 나중에 만들기를 선택해도 현재 탭의 접힌 이야기 목록에서 다시 확인할 수 있습니다.
2. 「엽서보기」는 기본적으로 조회 화면입니다. 검색·분류 후 엽서를 누르면 본문 대화상자가 열리며, 이 단계에는 선택 체크박스가 없습니다.
3. 「자서전 만들기」를 명시적으로 누르면 선택 모드로 바뀝니다. 최소 **3장**을 고르고, 이번 검토 시안에서는 **6장 이상도 선택**할 수 있습니다. 선택 순서와 검색·분류 후 선택을 유지하며, 선택 취소 후 다시 고른 엽서는 마지막 순서가 됩니다.
4. 「엽서 보기로 돌아가기」는 선택 화면 상단 설명 아래의 **높이 48px outline 버튼**입니다. 왼쪽 화살표와 함께 표시하며 하단에는 중복 버튼을 두지 않습니다.
5. 「문체 고르기」에서 네 가지 예시 문체를 비교합니다. 선택한 엽서 본문만 회차 시작 시각 순서대로 모아 목업 초안을 만들며, 실제 AI 문체 변환은 수행하지 않습니다. 제목·본문 수정과 예시 텍스트 내려받기가 가능합니다.
6. 「작은 책으로 보관하기」를 누르면 현재 탭의 책장에 추가하고 「자서전 보기」로 이동합니다. 같은 제목·본문을 다시 보관하면 중복 책을 만들지 않습니다. 서버 저장은 연결하지 않았습니다.
7. 「자서전 보기」는 모아둔 얇은 책의 목록과 열기 기능만 제공합니다. 처음 3권은 가상 예시입니다. 생성·합본 구성 동작은 없으며, 작은 책을 열어 읽고 목록으로 돌아올 수 있습니다.

## 선택 정책과 기존 서버 연동

`memoir-policy.js`는 두 규칙을 구분합니다.

| 구분 | 최소 | 최대 | 적용 범위 |
| --- | --- | --- | --- |
| `reviewPolicy` | 3 | `null` — 개수 상한 없음 | 이 정적 화면의 선택·목업 초안 |
| `legacyPolicy` | 3 | 5 | 원본 프론트의 기존 선택 기준·잘못된 정책 입력의 복구값 |

실제 서버는 최소 3회차를 요구하고 최대값은 환경 설정·엔진·요청 모드에 따라 다릅니다. 화자별 `GET /api/sessions?elder_id=...`에는 이미 `memoir_engine`, `memoir_max`, `memoir_max_chars`, `memoir_enabled`, `memoir_total`이 있습니다. `pipeline`의 `memoir_max:null`은 전체에서 제외하는 요청의 개수 상한이 없음을 나타내며, 명시적인 `session_ids` 요청에는 여전히 `MEMOIR_MAX_SESSIONS` 검사(기본값 5)가 적용됩니다. 배포 환경의 설정값과 계정별 적용 결과는 확인하지 않았습니다.

**이번 작업은 서버 제한을 해제한 작업이 아닙니다.** 정적 시안의 6장 이상 선택을 실제 기능에 연결하려면 기존 서버 메타데이터·엔진·요청 모드를 반영해야 합니다. 서버에는 비동기 생성·상태 조회·취소·중복 실행 방지도 이미 있으며 이번 시안은 이를 호출하지 않습니다.

초안 생성 시 `state.previewRequest.session_ids`에는 회차 UUID를 **클릭한 순서대로** 담되, 예시 본문과 `run.session_ids`는 서버와 같은 **회차 시작 시각 오름차순**으로 구성합니다. 엽서를 만든 시각이나 인생 사건의 연도순이 아닙니다. 시각이 없거나 같아 순서를 확정할 수 없으면 생성을 막습니다. 실제 화자 ID, 직접 고르기와 전체에서 제외하기, 목록에 보이지 않는 오래된 기록의 안내는 [서버 연결 준비서](SERVER_TOMORROW.md)에 정리했습니다.

## PC·모바일 공통 읽기

PC와 모바일은 동일한 리더를 사용합니다. **폭 1100px 이상·높이 560px 이상인 PC 페이지 보기**에서는 좌우 두 면을 펼치고, 좁은 PC·모바일 페이지 보기에서는 한 면을 표시합니다.

| 보기 방식 | 넓은 PC의 좌우 두 면 | 좁은 PC·모바일의 한 면 |
| --- | --- | --- |
| 옆으로 넘김(`slide`) | 기본 방식, 두 면씩 이동 | 기본 방식, 한 면씩 이동 |
| 종이책 넘김(`paper`) | 보기 설정에서 선택, 앞·뒷면이 있는 한 장을 420ms 동안 180도 넘김 | 옵션을 숨기며 종이 넘김 효과를 사용하지 않음 |
| 세로 스크롤(`scroll`) | 같은 본문을 세로로 읽기 | 같은 본문을 세로로 읽기 |

이전·다음 버튼, 스와이프, 방향키·PageUp/PageDown으로 직접 넘깁니다. PC용 `paper` 설정은 저장해 두되, 단면 화면에서는 실제 동작과 선택 표시를 `slide`로 맞춥니다. 다시 넓은 PC 양면 보기로 돌아오면 저장된 PC용 설정을 사용합니다.

글자 크기 기본값은 **24px**, 조절 범위는 **18~32px**입니다. 줄 간격은 **1.6~2.3**, 배경은 화이트·종이·야간, 글꼴은 명조·고딕 계열을 선택합니다. 「넘김 움직임 줄이기」를 켜거나 OS의 움직임 줄이기가 설정되어 있으면 넘김 효과를 재생하지 않습니다. 목차·책갈피·진행률 이동, 설정 변경, 화면 크기 변경에 자동 넘김 효과를 붙이지 않습니다.

페이지는 현재 글자 크기·줄 간격·화면 크기에 맞춰 다시 나눕니다. 읽던 위치와 책갈피는 문단과 글자 위치 비율을 기준으로 해 보기 방식 전환·재배치 후 같은 대목을 찾습니다. 양면의 오른쪽 페이지로 이동한 위치도 보존하며, 현재 펼친 면에 있는 책갈피는 왼쪽·오른쪽 모두 선택 상태로 표시합니다. 마지막 펼친 면은 100%로 표시하고 실제 마지막 쪽까지만 쪽수를 표시합니다.

화면 높이가 **560px 미만**이거나 폭이 **260px 미만**이면 글이 잘리지 않도록 스크롤 방식으로 전환합니다. 본문을 누르면 도구를 접고, 「독서 메뉴 보기」로 다시 표시할 수 있습니다.

보기 설정과 읽던 위치·책갈피는 이 브라우저의 localStorage에 저장합니다. 진행도는 `naemalssami.ui-review.reader.progress.v2.` 키를 사용하며, 책 구분용 해시·숫자 위치·책갈피와 시작 여부만 저장합니다. **자서전 제목·본문·인터뷰 답변은 localStorage에 저장하지 않습니다.** 여러 기기 간 동기화와 실제 책 저장은 연결하지 않았습니다. 저장소가 제한되면 현재 조작은 가능하지만 재접속 후 설정 유지가 되지 않을 수 있습니다.
