# 기존 서버와 연결할 수 있는 시안 구조

2026-11-09 · 사용자 승인: 현재 디자인을 기준으로 호환성을 준비하고, 시안 폴더의 구조 정리와 전달서를 작성한다.

## 목표와 범위

현재 HTML/JS 시안의 메뉴·라디오·책장·리더 배치를 유지한다. 기존 서버의 요청·응답과 화면에 필요한 데이터를 별도 함수로 연결한다. 목업도 이 변환 함수를 사용해 실제 연결 시 형식 차이를 미리 드러낸다.

작업은 `prototype/ui-review/` 안에서 한다. 실제 OAuth·마이크·API·DB 호출, 서비스 배포, 커밋·푸시는 이번 범위에 없다. `.txt`·`.env`·비밀정보는 읽지 않는다. 기존 소스·사용자 작업을 삭제하지 않는다.

## 선택한 접근

현재 HTML/JS를 유지하고 순수 JavaScript 변환 모듈을 둔다. React로의 전체 이식은 운영 원본을 정한 뒤 가능한 별도 작업이다. 지금 화면을 계속 구상할 수 있고, 특정 프레임워크에 묶이지 않은 데이터 변환은 후속 구현에서도 사용할 수 있어 이 방식을 선택했다.

## 경계

- 서버 응답의 `session_id/elder_id`, `text`, `chapters/paragraphs/sentences`, `sources`, `verification`, `run`을 보존한다. 표지·분류·화면 날짜 등 시안 전용 값은 별도 presentation/context 입력이다.
- 서버 결과와 화면의 문단 배열을 함께 보관한다. 편집 시 원래 결과는 보존하지만 현재 글의 출처 대응은 만료 처리하고 검증을 `not_run`으로 돌린다. 원문 출처를 수정 글의 근거로 재사용하지 않는다.
- `job_id`는 임시 생성 작업 식별자다. 책 ID나 영구 저장 성공으로 사용하지 않는다. 목업 보관은 계속 탭 메모리다.
- 화면의 문체 네 가지와 실제 API 문체를 구분한다. 로컬 서버에서 확인한 지원값은 `spoken`뿐이다. 합의되지 않은 문체값을 전송하거나 다른 문체로 조용히 바꾸지 않는다.
- 직접 선택과 전체 제외 요청은 별개다. `memoir_max:null`을 직접 선택 무제한으로 해석하지 않는다. 메타 조회 실패와 기능 비활성도 구분한다. 시안의 최소 3·상한 없음은 검토 정책으로 유지한다.
- 서버 상태와 화면 상태를 대응시키되, 서버의 `done`은 턴 확정이다. 마치기·쉬기·재개는 별도 명령 의미와 미구현 접점을 남긴다.
- 생성 완료·모델 검증·사람 확인을 구분한다. 부분 결과와 잘못된 응답을 완성 책으로 변환하지 않는다.

## 확인 방법

변환·편집·요청 정책의 실제 입력/출력 테스트를 먼저 작성한다. 기존 시안 테스트 전체와 JS 구문 검사를 실행한다. 브라우저에서는 엽서 선택→예시 생성→편집→책장→리더, 화자 전환을 확인한다. 정적 CSP의 네트워크·미디어 차단은 유지한다.
