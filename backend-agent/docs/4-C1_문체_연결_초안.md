## 2. 문체 값 (제안)

| 화면 | 보내는 값 | 비고 |
|---|---|---|
| 구어체 | `spoken` | 기본. 값을 안 보내도 이것이다 |
| 소설체 | `novel` | 4-P1 이 오기 전에는 지원 목록에 없다 |
| 싸이월드체 | `cyworld` | 4-P1 이 오기 전에는 지원 목록에 없다 |

- 키 이름은 `style` 이다. 엽서와 자서전이 같은 이름 · 같은 값을 쓴다. 2차 B 도구도 같은 값을 받는다.
- **값을 안 보내면 `spoken` 이다.** 지금 화면(문체 버튼 없음)은 그대로 돈다.
- **지원하지 않는 값은 거절한다.** 다른 문체로 바꿔 쓰지 않는다 (지시서 S1 「임의 fallback」).
  수필체 · 극본체 · MBTI체는 이번 범위가 아니어서 모르는 값과 같이 거절한다.
- **한 요청에 문체 하나다.** 세 문체를 한꺼번에 만들지 않는다.

### 거절 응답 (강승우 확인)

자서전 라우트에서 422 는 이미 「자료를 못 읽었다」라는 뜻이다. 그래서 문체 오류는 422 로 내지 않는다.

안: 두 라우트 모두 **400** `{"detail": "지원하지 않는 문체예요.", "code": "unsupported_style"}`.

- 엽서는 이미 409 에 `code` 를 싣는다 (2차, 승우 님 요청). 같은 모양이다.
- 자서전 400 은 지금 `{"detail"}` 뿐이고 문구가 「선택한 엽서를 확인해 주세요…」다.
  화면은 `code` 가 있으면 문체 안내, 없으면 지금의 「3~5장」 안내로 나눈다 (강승우). 고른 회차가 틀린 400 에는 `code` 를 붙이지 않는다.

## 3. 어디서 문체를 입히나 — 생성할 때 (제안)

지시서 P4-SV-01 은 「생성 시 반영」과 「기본본을 쓴 뒤 변환」 중 하나를 고르라고 한다. **생성 시 반영**을 기본 경로로 낸다.

| | 생성 시 반영 (제안) | 기본본 뒤 변환 |
|---|---|---|
| 모델 호출 | 지금과 같은 **1번** | 기본본 1 + 변환 1 = **2번** (기본본이 있으면 1번) |
| 출처 검사 위치 | 지금 자리 그대로 (`postcard.checked` · `memoir.check`) | 기본본 뒤 한 번, 변환 뒤 또 한 번. 변환이 문장을 합치거나 나누면 기본본 출처를 다시 맞춰야 한다 |
| 재료 | 유효 원자료 | 기본본 글 + 그 글의 유효 근거. 글만 넘기면 지시서가 막은 「이전 결과를 원자료처럼 변환」이 된다 |
| 문체 바꿔 다시 만들기 | 원자료에서 새로 쓴다 | 기본본이 최신인지 따로 확인해야 한다 |
| 길이 | 문체마다 한도 안에서 바로 쓴다 | 변환이 길이를 늘리면 다시 줄일 데가 없다 |

### 모델에 어떻게 전하나

- **시스템 지시:** 4-P1 이 정한 문체 지시를 실행본(`엽서_v2.md` · `자서전_v2.md` 의 다음 판)에 넣는다. 서버는 지금처럼 roledoc 으로 읽기만 한다.
- **자료 메시지:** 지금의 `[자료]` 앞에 `[작성 설정]` 칸을 따로 둔다. 문체 값은 여기에만 쓰고 자료 JSON 안에는 넣지 않는다.
  모델이 문체 값을 말씀의 사실로 읽지 않게 하려는 것이다.

```
[작성 설정]
style: novel
이 값은 쓰는 방식이다. 인생 사실의 근거가 아니다.

[자료]
… (지금과 같음)
```

- **4-P1 이 들어오기 전**에는 `novel` · `cyworld` 를 지원 목록에서 빼 둔다 (→ 400). 지금 프롬프트가 「선택이나 변환을 요청하지 마세요」라고 하는데 서버가 문체를 보내면 둘이 어긋난다.

### 인칭 · 종결 (미결 — 지시서 §9.1)

소설체 · 싸이월드체에서도 「저 · 해요체」를 지킬지는 김대원 님 예시를 보고 팀이 정한다. 서버는 이 결정을 모른다 — 4-P1 의 문장만 바뀐다.
합의 전까지 기본 규칙(구어체 · 해요체 · 저)은 그대로 둔다.

## 4. 유효 자료와 문체를 섞지 않는다 (P4-SV-02)

- 문체 요청은 `turn.answer` · `turn.decision` · 회차 행을 **바꾸지 않는다.** 저장하는 것은 생성 결과(엽서 행)뿐이다.
- **이전 엽서 글은 재료로 쓰지 않는다.** 문체를 바꿔 다시 만들어도 `postcard.material` 이 DB 기록에서 자료를 처음부터 다시 세운다. 지금 코드가 이미 그렇다.
- 아니라고 하신 사실(`facts_retracted`)은 지금도 자료에서 빠진다. 문체가 바뀌어도 같은 함수를 지나므로 되살아나지 않는다.
- **2차 A 수정본이 생기면** 그 결과가 `material` 에 들어가는 자리는 한 곳이다. 문체 쪽은 그 자리를 건드리지 않는다.
  S4 (수정 · 제외 유지)는 2차 A 없이는 재료가 없어 **확인 불가**로 남긴다.

## 5. 출력 모양과 출처 (P4-SV-03)

- **모델 출력 키는 바꾸지 않는다.** 엽서 8키 · 자서전 7키 그대로다. 문체 값을 모델 출력에 다시 받지 않는다 — 무엇을 요청했는지는 서버가 안다.
- 출처는 **최종 문장 기준**이다. 엽서는 본문을 줄(없으면 마침표)로 나눈 순서, 자서전은 본문 줄 순서가 `sources.sentence` 를 가리킨다. 이전 결과의 `sources` 를 붙이지 않는다.
- 구조 검사(번호 · 실제 턴)와 뜻 검사는 다르다. 구조가 통과해도 「왜곡 없음」이 아니다 — 뜻은 검증_v4 · 김대원 · 안다애 검수다.

### 엽서의 출처 누락 (미결 — 지시서와 지금 코드가 다르다)

`postcard.checked` 는 출처 없는 문장을 **빼지 않고 로그만 남긴 채 굽는다.** 지시서 S5 의 실패 기준 「빈 출처 문장 노출」에 해당한다.
자서전은 같은 경우 502 다.

- 안: 엽서도 출처 없는 문장이 있으면 굽지 않고 실패로 낸다 (자서전과 같은 규칙). 문장을 지우거나 번호를 채워 넣지 않는다.
- 이건 기본 문체에도 걸리는 동작 변경이다. 실제 엽서가 얼마나 걸리는지 먼저 보고 김대원 · 강승우 님과 정한다.

## 6. 최신성 — 늦은 응답 · 실패 · 캐시 (P4-SV-04)

### 엽서 (저장한다)

지금 있는 것:

- **같은 회차는 한 번에 하나만 굽는다** (`postcard._busy`). 굽는 중에 문체를 바꿔 누르면 409 `busy` 다. 그래서 「늦게 온 옛 응답이 새 것을 덮는」 일은 한 서버 프로세스 안에서는 생기지 않는다.
  프로세스를 여러 개 띄우면 이 보장이 없다 — 지금 배포는 하나다 (배포.md).
- 주소 꼬리와 ETag 는 **JPEG 바이트의 해시**다. 글이 바뀌면 바이트가 바뀌고 주소도 바뀐다. 본문(`postcard.text`)과 그림 속 글은 Pillow 가 같은 값으로 얹으므로 글자까지 같다.
- 새로 굽다 실패하면 옛 행이 그대로 남는다. `POST` 는 실패로 답한다.

더할 것 (제안):

- 엽서 행에 `style` · `material_version` · `prompt_version` 세 칸 (마이그레이션 011). 새 표는 만들지 않는다.
  - `material_version` = 모델에 보낸 자료 JSON 의 해시. 원문을 따로 보관하지 않는다 — 판단용 번호일 뿐이다.
  - `prompt_version` = 실행본 파일의 해시.
- `POST` 응답과 회차 기록의 `postcard` 에 `style` 을 싣는다. 화면은 이 값으로 「무슨 문체의 엽서인지」를 보여 준다.
- **실패한 새 문체 요청 뒤에는** 화면이 옛 엽서에 새 문체 이름을 붙이지 않는다. 서버는 옛 행의 `style` 을 그대로 주므로 화면이 그 값을 쓰면 된다.
  화면은 고른 문체 · 만드는 중 · 지금 보이는 글의 문체를 따로 보여 주고, 라벨은 응답의 `style` 로만 단다 (강승우).

#### busy 뒤에 새 결과를 알아보는 법

화면은 409 `busy` 를 받으면 회차 기록의 `postcard` 가 생길 때까지 기다린다. 문체를 바꿔 다시 만들 때는 옛 엽서가 이미 있어서
그것을 새 결과로 착각할 수 있다 (강승우 지적).

- 회차 기록의 `postcard` 에는 **이미 `created_at` 이 있다** (`store.load_session`). 다시 구우면 DB 의 `now()` 로 새로 찍힌다. 주소 꼬리 `?v=` 도 바이트가 바뀌면 바뀐다.
- 화면 시계와 비교하지 않는다. 폰 시계가 서버와 어긋나면 틀린다.
- 화면은 누르기 전에 옛 엽서의 `created_at` (또는 `url`) 을 기억해 두고, **그 값이 바뀌고 `style` 이 요청한 문체와 같을 때만** 새 결과로 받는다.
- 기다린 끝에 다른 문체의 엽서가 오면 (앞 요청이 먼저 끝났다) 새 결과가 아니다. 화면이 그 문체로 다시 요청한다.
- 서버가 더할 것은 위의 `style` 칸뿐이다.

### 자서전 (저장하지 않는다)

- 저장하지 않으니 덮어쓸 것이 없다. 남는 위험은 화면이 늦게 온 응답을 보여 주는 것이다.
- html-prototype 은 이미 요청 번호(`mmReq`)로 늦은 응답을 버린다.
- 응답에 요청받은 `style` 을 함께 돌려준다 (5키 + `style` = 6키). 강승우 확인.

### 모의 경로 (최충 → 안다애)

- 자서전에는 이미 `MEMOIR_FAIL_INJECT` (`generation_failed` · `generation_timeout` · `source_material_unavailable`) 가 있다.
- 엽서에는 없다. 4-C1 이 정해지면 같은 방식으로 실패 · 지연 주입을 더해 S6 를 안다애 님이 재현할 수 있게 한다.

## 7. 권한

- 문체 생성은 **로그인한 자녀만** 쓴다. 엽서 · 자서전 라우트는 이미 `auth.current_user` 와 소유 검사(남의 것은 404)를 지난다.
- 어르신 링크(`/api/i/*`)에는 엽서 · 자서전 생성 라우트가 **없다** (지금 11개: 미리보기 · 시작 · 진행 · 사진 · 읽기 전용 대화). 이번에도 열지 않는다.

## 8. 길이 — 지금 기본 문체의 측정 (P4-SV-06, 최충 측정)

**도구 측정이다. 모델은 부르지 않았다.** 로컬 DB 의 엽서 행과 `postcard._fit` 을 그대로 썼다.

로컬 DB 엽서 (제목이 있는 v3 이후 13장, 기본 문체):

| | 본문 | 한도 |
|---|---|---|
| 대부분 | 4~54자 · 1~3문장 | 120자 |
| B 세트 3장 (10-21) | 54 · 29 · 53자 | |
| **넘은 것 1장** (09-29) | **192자 · 8문장** — 34px 로 줄여도 8줄, 칸(4줄)을 넘는다 | |

배치를 따져 보면 **엽서의 줄 수는 글자 수보다 문장 수가 정한다.** `_fit` 이 문장마다 새 줄에서 시작하기 때문이다.
가로 사진이 칸을 꽉 채운 경우(가장 나쁜 경우)를 합성 글로 놓아 보았다:

| 사진 · 사진 설명 | 날짜 줄(y=940)을 넘기 시작하는 곳 |
|---|---|
| 사진 없음 | 6문장까지 넘지 않는다 |
| 사진 있음 · 설명 없음 | 6문장부터 넘는다 (그림 밖으로 잘린다) |
| 사진 있음 · 설명 있음 | **3문장부터 날짜 글자와 겹친다** · 60자여도 그렇다 |

- 이 겹침은 **지금 기본 문체에도 있다.** 문체 일이 만든 것이 아니다.
- 짧은 문장을 여러 개 쓰는 문체(싸이월드체로 예상)는 더 쉽게 걸린다. 문장을 합치는 문체(소설체로 예상)는 덜 걸릴 수 있다.
- **고치지 않았다.** 자르거나 다시 부르지 않는다는 지시서 원칙대로, 기준(문장 수 상한 · 사진 칸 높이 · 설명 위치) 변경은 김대원 · 강승우 님과 정한다.

### 배치 안 (강승우 제안 · 최충 찬성 · 김대원 확인 전)

- **문장 수를 줄이지 않고 그림 세로를 글 길이만큼 늘린다.** 본문을 잘라 감추지 않는다. 화면이 그리는 저장용 엽서도 이 방식이다.
- 높이 상한이 필요하면 ① 사진 칸을 먼저 줄이고 ② 사진 설명은 사진 아래 한 줄 ③ 날짜는 맨 아래에 고정한다.
- 지금의 1500×1000 (3:2) 고정을 버리는 것이라 엽서 모양이 바뀐다. 응답에는 이미 `width` · `height` 가 있어 계약은 그대로다.
- 김대원 님 확인 뒤에 구현한다.
- 문체별 실제 길이는 4-P1 이 온 뒤 모델을 불러 다시 잰다 (비용이 드니 그때 횟수를 정한다).

## 9. 자서전 화면 연결 (P4-SV-05)

- html-prototype `461dc6f` 의 `memoirPreview` 는 `POST /api/memoirs/preview` 에 `{"session_ids": [...]}` 를 보낸다. 지금 서버 계약과 같다.
- 다만 이 판은 `X-User-Id` 헤더로 신원을 보낸다. feature/theme-interview 서버는 이 헤더를 더 읽지 않는다 (3차).
- **프론트는 HTML (`prototype/index.html`) 로 확정이다** (강승우). React `frontend-client` 에는 자서전 호출을 더하지 않는다.
- 지금 판 v0.31 은 로그인 모드에서 `X-User-Id` 를 보내지 않고, 3차 서버 (`1730c17`) 에서 자서전 · 엽서 · 링크까지 확인했다고 한다 (강승우 실행).
  아직 html-prototype 브랜치에 없다 (2026-10-21 `origin/html-prototype` = `461dc6f`). 올라오면 최충이 다시 확인한다.
- 문체는 본문에 `"style"` 하나를 더한다. 안 보내면 `spoken` 이다.

## 10. 팀 확인이 필요한 것

| 항목 | 누구 | 이 문서의 안 |
|---|---|---|
| 문체 값 · 키 이름 | 김대원 · 강승우 | `style` = `spoken` · `novel` · `cyworld`, 없으면 `spoken`. **강승우 확인** |
| 적용 위치 | 김대원 · 최충 | 생성할 때 · 호출 1번 (§3) |
| 인칭 · 종결 | 김대원 예시 → 팀 | 미결. 합의 전엔 기본 규칙 유지 |
| 문체 오류 응답 | 강승우 | 400 + `code: unsupported_style`. **확인** |
| 응답의 문체 표시 | 강승우 | 엽서 응답 · 기록에 `style`, 자서전 응답에 `style` (6키). **확인** |
| busy 뒤 새 결과 판단 | 강승우 | 옛 `created_at` 과 다르고 `style` 이 같을 때만 (§6). 답 대기 |
| 엽서 출처 누락 처리 | 김대원 · 강승우 | 미결. 안: 자서전처럼 실패 (§5) |
| 엽서 배치 · 길이 기준 | 김대원 · 강승우 | 그림 세로를 늘린다 (강승우 제안 · 최충 찬성). **김대원 확인 전** (§8) |
| 자서전 프론트 | 강승우 | HTML 로 확정. v0.31 올라오면 재확인 (§9) |
| 유효 수정본 (2차 A) | 담당 확인 | 없다. S4 는 그때까지 확인 불가 |
