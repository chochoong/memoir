## 1. 시작 입력 — `POST /api/sessions` (SV-02, 구현됨)

| 키 | 형 | 필수 | 허용값·처리 |
|---|---|---|---|
| `title` | 문자열 | 예 | 지금과 같다 |
| `theme` | 문자열 | 아니오 | `family`(가족) / `self`(나) / `hobby`(취미). 그 밖의 값은 **422** |
| `topic` | 문자열 | 아니오 | 구체 주제 하나. 앞뒤 공백은 서버가 지운다. 100자 넘으면 **422** |
| `seed` | 문자열 | 아니오 | 가족이 적은 설명. 예전에는 필수였다. 지금 화면처럼 이것만 보내도 열린다 |
| `photo_id` | 문자열 | 아니오 | 보조 사진. 지금과 같다 |
| `pace`, `max_turn` | | 아니오 | 지금과 같다 |

```json
{ "title": "이사", "theme": "family", "topic": "가족과 함께 이사한 기억",
  "seed": "아버지가 트럭을 빌려 오셨대요", "photo_id": "…" }
```

**빈 값 처리**

- `theme` 없음: 모델에게 테마를 아예 적지 않는다. 「모름」으로도 적지 않는다(P1: 테마를 추측하지 않는다).
- `topic` 없음: 주제 자리는 `seed` 가 대신한다(지금 화면 호환). 둘 다 없으면 시작 자료 없이 연다.
- `seed` 가 `topic` 과 같으면 한 번만 싣는다.

**모델에게 가는 모양.** 시작 자료는 대화 기록과 **따로** 간다. `seed` 를 「어르신:」 으로 적지 않는다.
대화 창(최근 6턴)이 잘려도 이 블록은 매 턴 실린다.

```
[시작 자료 — 가족이 정한 질문 방향입니다. 사용자의 말이 아닙니다]
테마: 가족
주제: 가족과 함께 이사한 기억
가족이 적은 설명: 아버지가 트럭을 빌려 오셨대요

[지금까지의 대화]
질문: …
어르신: …
```

공유 상태의 `current_topic` 도 `topic`(없으면 `seed`)으로 채운다.

**여는 말.** 여기서는 모델을 부르지 않는다.

| 조건 | 여는 말 |
|---|---|
| `topic` 있음 | 「오늘은 「{topic}」 이야기를 나눠 볼까요? 떠오르는 것이 있으면 편하게 들려주세요.」 (사진이 있으면 앞에 「사진 잘 받았습니다.」) |
| `topic` 없음, 사진 단서 있음 | 사진 분석이 낸 질문. 감각을 묻는 후보는 버리고 아래 고정 문장으로 |
| `topic` 없음, 사진만 | 「사진 잘 받았습니다. 이 사진은 어떤 사진인가요?」 |
| 아무것도 없음 | 「오늘은 어떤 이야기를 들려주시겠어요?」 |

여는 말 문구는 김대원 님 검토 전이다.

**사진이 실패할 때.** 없는 `photo_id`, 남의 사진, 분석 실패 모두 **회차는 열린다**(200).
단서 없이 가고, 여는 말은 위 표를 따른다. 화면이 따로 처리할 오류는 없다.

**오류 형식.** FastAPI 기본 형식 그대로다. 새 오류 객체는 만들지 않았다.

- 422: `detail` 이 **배열**이다(어느 필드가 왜 틀렸는지). 화면에서는 「입력을 확인해 주세요」 정도로 받으면 된다.
- 429·503: 지금과 같다. `detail` 이 문자열이다.

**아직 하지 않은 것**

- `theme`·`topic` 은 **회차 메모리에만** 있고 DB 에는 저장하지 않는다. 서버를 다시 띄우거나
  지난 회차를 읽을 때는 남지 않는다. SV-06(종료 후 읽기)에서 저장 위치를 정한다.
- `seed` 는 지금처럼 0번 조각(`fragments[0]`)으로 저장되고 스냅샷에도 보인다. 답변 목록에서
  빼는 일은 SV-06 에서 한다.

## 2. 입력 전환 — 음성 ↔ 키보드 (SV-04, 합의 전)

정할 것: 전환 요청 → 승인 → 전송 완료 순서와 접점, 전환 전 미확정 발언을 어디에 붙일지,
중복 전송 방지, 보내지 않은 텍스트 처리. 지금 `/speech` 와 `/speech/audio` 만으로는
타이핑하는 동안 다음 질문이 보류되지 않는다.

## 3. 종료 (SV-05, 합의 전)

정할 것: 「종료 승인」과 「내용 준비 완료」를 화면이 구분하는 방법. 이 둘은 같은 뜻이 아니다.
`CLOSED` 상태만으로는 마지막 전사가 끝났는지 알 수 없다.

## 4. 조회 (SV-06, 합의 전)

정할 것: `/record` 의 질문·답변 구분 형식, 처리 중·조회 실패·실제 빈 대화를 서로 다르게 알리는 방법.
