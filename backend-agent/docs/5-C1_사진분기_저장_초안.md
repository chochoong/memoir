# 5-C1 — 사진 분기 · 저장 초안 (P5-SV-01)

작성 최충 · 받는 사람 안다애 (P5-QA-02) · 김대원 (DW-11) · 강승우 (FE-10)
기준 서버 `feature/theme-interview` `ad797ec` 뒤 · 2026-10-22

**현행을 적은 것이다. 그림 생성은 아직 없다** — 지금 `image_model` 은 늘 `None` 이고, 엽서는 사진 또는 종이 바탕에
Pillow 로 글을 얹은 것이다. 이것을 새 그림 생성 완료로 보지 않는다.

## 1. 지금 경로

```
POST /api/sessions/{id}/postcard
  → postcard.make      주인 · 닫힘 · 말씀 · busy 확인 (아니면 404 / 409)
  → _make
      _photo(rec.photo_id)            사진 바이트 · 분석 단서, 또는 None
      write(material(...))            글 (실제 모델)
      _compose(사진 or None, 글)      1500×1000 JPEG — 사진이면 위에 붙이고, None 이면 종이 바탕
      photostore.put(새 키)            엽서 바이트 (키 = 회차 + 바이트 해시)
      store.save_postcard(행)          실패하면 방금 넣은 바이트만 지운다
      옛 키 삭제                        다시 구운 경우
GET  /api/sessions/{id}/postcard?v=…  주인만 · 저장 키는 밖에 안 나간다
```

- 원본 사진은 `photo` 표 · 사진 저장소에 따로 있고, 엽서가 덮어쓰지 않는다.
- 엽서 행의 `photo_id` 는 사진을 실제로 썼을 때만 채운다.

## 2. 사진 분기 — 어디서 무엇이 되나

`tests/test_postcard.py` `[1b] 사진 분기` 로 현행을 고정했다 (모의 · 6건 통과).

| 상황 | 결정되는 곳 | 지금 결과 | 그림 생성을 붙이면 |
|---|---|---|---|
| 정상 사진 | `_photo` | 사진 + 단서로 굽는다 | **호출하지 않는다** (P5-T01) |
| 회차에 사진 없음 (`photo_id` 없음) | `_photo` 첫 줄 | `None` → 종이 바탕 | **여기만 그림 생성 대상** |
| 사진 행 없음 · id 형식 이상 | `store.load_photo` | `None` → 종이 바탕 (로그 없음) | 생성하지 않는다 — 가리키던 사진이 사라진 것 |
| 사진 행 읽기 실패 (DB) | `_photo` 의 `except` | `None` → 종이 바탕 + 경고 로그 | 생성하지 않는다 — 실패 |
| 사진 바이트 읽기 실패 (저장소) | 같음 | `None` → 종이 바탕 + 경고 로그 | 생성하지 않는다 — 실패 |
| 바이트는 왔는데 깨짐 | `_mounted` (`postcard.py:613`) | `PostcardUnavailable` → **503**, 엽서 없음 | 생성하지 않는다 — 실패 |
| 다른 사람 사진 | 해당 없음 | 회차의 `photo_id` 만 읽고, 회차는 주인 확인을 지난 뒤다 | 같음 |

**문제: 위 표의 2~5행이 모두 같은 `None` 이다.** 「사진 없음」에 그림 생성을 걸 때 `None` 에 걸면
읽기 실패에도 그림을 만든다 (지시서 P5-T03 의 실패 조건). 그래서 `_photo` 가 `None` 대신
세 가지를 돌려주게 나눈다 (P5-SV-03 에서 고친다, 지금은 고치지 않았다).

| 돌려줄 값 (안) | 뜻 | 그림 |
|---|---|---|
| `photo` | 정상 | 안 부름 |
| `none` | 회차에 사진이 없다 | 부름 (승인된 기본형만) |
| `unavailable` | 있어야 할 사진을 못 읽었다 (행 없음 · DB · 저장소 · 깨짐) | 안 부름 — 처리 정책은 §4 미결 |

## 3. 그림 도구와 주고받을 것 (초안 — 다애 님 · 대원 님 답을 받아 고친다)

| 방향 | 항목 | 비고 |
|---|---|---|
| 서버 → 도구 | 회차 id · 그림 재료 (대원 5-P1/material) · 제외 범위 | 제외된 원문은 다시 싣지 않는다 |
| 도구 → 서버 | 이미지 바이트 · 실제 MIME · 가로 × 세로 · 실행 식별 · 모델 이름 | 서버가 다시 열어 MIME · 치수를 확인한다 |
| 서버 저장 | 엽서 바이트 · 행. `image_model` 칸 (이미 있음, 지금 `None`) 에 그림 모델 | **생성 그림 원본을 따로 오래 둘지는 미결** |
| 서버 → 화면 | 지금과 같은 엽서 GET 주소 · 「그린 그림」인지 「사진」인지 표시용 값 | 새 칸이 필요하면 승우 님과 합의 |

단계는 **생성 중 → 생성 성공 → 저장 성공** 을 나눈다. 생성은 됐는데 저장이 실패하면 새 결과로 보이지 않고,
옛 엽서가 그대로 남는다 (지금 다시 굽기 실패와 같은 규칙 — 4-R1 R1-02).

### 3-1. 화면 표시용 `image_kind` (승우 님 FE-04 회신)

`/record` 의 `postcard` 와 `POST /postcard` 200 에 `image_kind: "photo" | "drawn" | "paper"` (이름은 임시).

| 값 | 지금 알 수 있나 |
|---|---|
| `photo` | **있다** — 엽서 행의 `photo_id` 는 사진을 실제로 썼을 때만 채운다 (§1) |
| `paper` | **있다** — `photo_id` 가 없고 `image_model` 이 없음 |
| `drawn` | 그림 생성이 붙은 뒤 — `image_model` 이 채워진 행 |

새 DB 칸 없이 기존 칸으로 만든다.

**사진을 못 읽어 종이로 구운 경우 (`unavailable`)** 는 다르다:

- `_photo` 분리 (§2) 가 먼저다.
- 저장된 행으로는 「사진이 원래 없음」 과 「못 읽음」 이 같은 `paper` 다. 그래서 `photo_status: "unavailable"` 은
  **구운 직후 `POST` 응답에는 실을 수 있지만, 나중에 기록을 열 때는 알 수 없다** — 남기려면 칸이 하나 필요하다.
- 실패로 멈추는 쪽 (태헌 님 결정 ②) 이면 칸 대신 `code: photo_unavailable` 하나로 된다.
- 화면 쪽 의견: ① 종이로 굽고 「사진을 불러오지 못해 사진 없이 만들었어요. 다시 만들 수 있어요.」 안내. 결정은 태헌 님.

## 4. 미결

| 항목 | 담당 · 결정 |
|---|---|
| `unavailable` 일 때 종이 바탕으로 구울지, 실패로 멈출지 · 종이라면 그 사실을 행에 남길지 | 충 + 다애 + 승우 (① + 안내) → 태헌 |
| 그림 재시도 횟수 · 시간 한도 · 비용 | 다애 (도구) → 태헌 |
| 그림 재료 기준 (자주 나온 것 vs 중요한 것 vs 제외) | 대원 + 다애 → 태헌 |
| 생성 그림 원본 보관 여부 | 태헌 (새 보관 기능은 범위 밖) |
