# 목차별 자동 삽화 — 사용 · 연결 안내

> **지금 상태 (2026-11-18 · 목차 주제 삽화 v2 — 낱말 검사 차단을 걷어냄)**
> - **기본 방식은 목차 주제 삽화(`chapter_theme_v2`)다.** 장 전체의 중심 주제와 분위기를 나타내는 그림 한 장을 만든다 — 아래 「1. 동작」.
> - **뜻은 모델이 판단하고, 코드는 낱말로 막지 않는다.** 앞선 판(`chapter_theme_v1`)은 「안 · 못 · 없」 부정 문형 · 반복 · 관계 낱말로 소재를 빼고
>   생성을 막았다(「세계를 안고 있었다」 의 「안고」 를 부정으로 읽어 막은 일이 있었다). v2 는 그 차단을 모두 걷어냈다. 코드는 응답 모양 ·
>   주제와 소재가 있는가 · 지시문이 조립되는가 · 사진 유무 · 중복 호출 · 저장 · 삽입만 본다. 결과에 「코드가 뜻을 검증하지 않았다」 고 적는다.
> - v1 로 만든 기록은 v1 이름 그대로 남는다. v1 으로 실패한 장은 운영자가 장을 이름 대야(`--chapter`) v2 로 한 번 다시 한다 (10절).
> - 운영에서는 v1 이 실제 모델로 돌았다(그 기록은 운영 DB 에만 있다). v2 는 아직 **실제 모델로 부르지 않았다** — 모의 계획 · 모의 그림으로만 확인했다.
>
> **(2026-11-16 · 서비스 연결)**
> - **기존 자서전 만들기에 연결됐다.** 화면의 「자서전 만들기」(`POST /api/memoirs`) 작업이 자서전을 DB 에 저장하면
>   사진 없는 장의 삽화가 뒤에서 저절로 만들어지고, 그림은 사진 저장소에 · 상태는 `memoir.illustrations`(017)에 남고,
>   초안 화면과 책 화면(이북)의 그 장 문단 뒤에 보인다. 별도 버튼 · 선택 · 승인 단계는 없다 — 아래 「10. 서비스 연결」.
> - 공유 링크 화면(`/b`) · PDF 저장에는 아직 그림이 나오지 않는다(글만). 이 기기에서 글을 고친 책에도 그림을 붙이지 않는다.
> - 사람이 장면을 고르거나 항목마다 승인하는 단계가 없다(자동). 자동 검사는 사람의 확인을 대신하지 않는다.
> - 검증: 합성 자료의 모의 시험(비용 없음) — 삽화 시험 327개 통과, 알려진 한계 3개는 「실패 예상」(xfail)으로 표시. 실제 모델 호출은 실험 단계에서만 했다.
>   장면 선정은 실제 원문 한 항목(비공개)과 합성 목차 5개로 해 봤다(5개 모두 그림을 골랐다 — 아래 「알려진 제한」).
>   그림 모델은 실험에서 한 번 불렀다. 실제 원문 · 실제 응답 · 생성 그림은 저장소에 없다.
> - 서비스 연결 확인 (2026-11-16, 로컬 서버 · 확인 전용 DB · 합성 회차 3개 · 집필 모델 대신 이미 완성된 합성 책):
>   화면에서 자서전 만들기 → 1 · 3장은 회차 사진(호출 0) · 2장만 장면 선정 1회 + 그림 1회(실제) → 초안 · 책 화면에 표시 →
>   서버를 다시 켜고 책장에서 열어도 그대로(호출 0). 모의로 그림 실패 시 본문 유지 · 「그림을 넣지 못한 장」 안내도 확인했다.

자세한 입력 · 출력 칸은 [규격 문서](../첨부프롬프트_md/삽화/4_목차별자동삽화_규격_v1.md)에 있다. 이 문서는 그 요약과 쓰는 법이다.

## 1. 동작

자서전 본문이 다 만들어진 뒤, **목차 항목(`memoir.chapters` 하나)마다** 본다.

| 그 항목의 사진 | 처리 |
|---|---|
| 한 장이라도 놓여 있다 (`has_photo`) | 사진을 그대로 두고 삽화를 넣지 않는다 |
| 없는 것이 확인됐다 (`no_photo_confirmed`) | 그 항목을 대표하는 삽화 **한 장**을 만들어 그 본문에 넣는다 |
| 있는지 모른다 (`unknown`) | 만들지 않는다 — 「자료 부족」. 없다고 짐작하지 않는다 |
| 이미 삽화가 들어 있다 | 다시 만들지 않는다 |

책 전체에서 몇 장까지라는 한도는 없다. 사진 없는 항목 하나의 흐름 — **기본: 목차 주제 삽화** (`chapter_theme_v2` · `app/session/memoir_illust_theme.py`):

1. **장 전체 읽기 · 계획** — 모델 1회(`gemini-3.5-flash-lite`, 지시문 [v8](../첨부프롬프트_md/삽화/1_목차주제_v8.md) · 2026-11-25 ~.
   v7 과 다른 점은 그림 재료(수채화)를 적지 않는 것뿐이다 — 계획은 삽화 그림체와 상관없이 같다).
   제목 · 장 본문 전체(문단 번호)와 그 장의 원문 말씀(참고)을 주고, **주제 · 분위기 · 뒷받침 내용 · 그릴 소재 · 구도**를 받는다.
   지시문이 모델에게 맡기는 것 — 한순간을 정확히 복원할 필요가 없고 일반화된 삽화면 충분하다 · 실제 경험과 부정 · 가정 · 희망으로 말한 일을
   문맥으로 가린다 · 본문과 반대되는 경험이나 새 사건 · 관계를 사실처럼 그리지 않는다 · 옷차림 · 빛 · 색감 · 질감 · 일반적인 인물 · 구도는
   표현으로 허용한다 · 얼굴 · 건물 · 장소를 실제와 똑같이 되살렸다고 하지 않는다.
2. **검사** — 코드. 모양과 존재만 본다 (`theme_checks_v2`).
   - 응답이 JSON 계획인가(아니면 `model_output`) · 주제와 소재가 있는가(없으면 `empty_plan`) · 지시문이 조립되는가(넘치면 `prompt_too_long`).
   - **낱말로 막지 않는다** — 「안 · 못 · 없」 · 반복 횟수 · 짧은 인용 · 참여 인물 · 관계 낱말 · 제목에만 있는 낱말로 소재를 빼거나 실패시키지 않는다.
     중심 소재는 모델이 `main` 으로 적은 것(없으면 적은 순서의 앞)이다.
   - 모델이 적은 본문 낱말(anchor)이 어디에 나오는지는 `anchor_reference` 로 **참고만** 남긴다(막지 않는다 · 뜻을 검증한 것이 아니다).
3. **그림 만들기** — 모델 1회(`gemini-3.1-flash-image`, 1K · 5:4). 계획의 소재 · 구도 + 공통 양식([2_그림양식_v3](../첨부프롬프트_md/삽화/2_그림양식_v3.md))
   + **그 책의 삽화 그림체 하나**(아래 「삽화 그림체」)로 코드가 한국어 지시문을 조립한다. 모델이 「본문에 없다」 고 적은 것(`not_in_story`)은 지시문에 넣지 않는다.
4. **넣기** — 장의 첫머리(30자 이상인 첫 문단 뒤). 원고는 건드리지 않는다.

결과에 `policy`(`chapter_theme_v2`) · `checks_version`(`theme_checks_v2`) · 한 검사 · 하지 않은 검사(뜻) · `meaning_verified_by_code: false` · 지시문 해시를 남긴다.
사람의 확인 상태(`human: not_reviewed`)는 바꾸지 않는다.

**삽화 그림체** (2026-11-25) — 책마다 하나를 자서전 만들기 화면(「문체 선택」 아래 「삽화 그림체」)에서 고른다. 고르지 않으면 수채화다.

| 화면 이름 | `illust_style` | 그림체 파일 | 표현 |
|---|---|---|---|
| 수채화 (기본) | `watercolor` | [2_그림체_수채화_v1](../첨부프롬프트_md/삽화/2_그림체_수채화_v1.md) | 앞선 그림 양식 v2 의 수채화 문구 그대로 — 물 번짐 · 종이결 · 절제된 색 · 가장자리가 옅게 풀림 |
| 연필담채화 | `pencil_wash` | [2_그림체_연필담채화_v1](../첨부프롬프트_md/삽화/2_그림체_연필담채화_v1.md) | 연필 선 · 명암 위에 옅은 색. 흑백 연필화로 그리지 않는다 |
| 유화 | `oil_painting` | [2_그림체_유화_v1](../첨부프롬프트_md/삽화/2_그림체_유화_v1.md) | 붓 자국 · 겹친 물감 · 깊이 있는 색감. 수채 표현(「수채」 낱말도)을 넣지 않는다 |

- 지시문 순서 — 공통 양식 → [그림체] → 이 장의 주제 · 그릴 것 → 인물 표현 → 넣지 않는 것 → [이 그림체에서 피할 것]. **그림체가 달라도 주제 · 그릴 것은 같다**
  (계획 지시문 v8 에 그림체를 알리지 않는다). 그림체 때문에 원문에 없는 사건 · 인물 관계를 더하지 않는다 — 공통 양식이 그대로 금지한다.
- 흐름 — 화면 `POST /api/memoirs {…, style, illust_style}` → `memoir_jobs.start` → `keep` → `memoir_illust_service.schedule(…, art_style)` →
  `run` 이 책 기록 `memoir.illustrations.art_style` 에 적는다 → 장마다 `select.art_style · art_style_hash`, `image.art_style · style_id`(`<그림체>-recall-v3`).
  화면 응답(`GET …/illustrations`)은 `art_style {id, label}` · 장 · 삽화마다 `art_style`.
- 문체(`style` · `memoir.style`)와 따로다 — 덮어쓰지 않는다. 사진 장은 그림체와 상관없이 원본 사진이다. 장마다 고르거나 승인하는 단계는 없다.
- 모르는 값은 400 `unsupported_illust_style`(키가 없을 때만 수채화 · 빈 문자열 · 대소문자만 다른 값도 거절). 받은 문자열을 지시문에 넣지 않는다.
- **다시 처리 · 이어서 처리는 책에 적힌 그림체를 쓴다.** 그림체 칸이 없는 앞선 책은 수채화다. 저장된 그림은 다시 그리지 않는다. 기존 책의 그림체를 바꾸는 기능은 없다.
- 장면 방식(`scene_v5`)은 그림 양식 v1(수채화)만 그린다 — 다른 그림체의 책을 장면 방식으로 돌리면 부르기 전에 `art_style_not_in_policy` 로 실패한다.
- **실제 그림으로는 아직 확인하지 않았다** — 연필담채화가 흑백으로 나오지 않는지, 유화에 수채 느낌이 섞이지 않는지는 유료 생성으로 견본을 봐야 안다.

**앞선 방식 — 장면 재현** (`scene_v5`, `MEMOIR_ILLUST_POLICY=scene` · 실행기 `--policy scene`):

1. **장면 선정** — 모델 1회(`gemini-3.5-flash-lite`, 지시문 [v5](../첨부프롬프트_md/삽화/1_장면선정_v5_목차중심.md)).
   모델은 이 항목의 중심 내용(`focus`)과 그림 후보를 원문 인용과 함께 낸다.
2. **자동 검사와 대표 그림 고르기** — 코드. 인용을 원문과 대조하고, 사람을 그리는 후보는 관계 · 근거 · 함께 한 사람의 누락 · 부정 · 전언 표지를 본다.
   통과한 후보(사람을 뺀 그림 포함) 가운데 **이 목차의 중심 요소를 가장 많이 담은 것**을 고른다. 배경 · 주변 소재만 남은 후보는 고르지 않는다.
3. **그림 만들기** — 모델 1회(`gemini-3.1-flash-image`, 1K · 5:4). 그림 지시문은 확인된 요소와 고정 양식([2_그림양식_v1](../첨부프롬프트_md/삽화/2_그림양식_v1.md))으로 코드가 조립한다.
4. **넣기** — 그 장면의 문단 뒤. 문단을 찾지 못하면 항목의 끝. 원고는 건드리지 않고 별도 결과를 만든다.

## 3. 비용 없이 돌려 보기

`backend-agent` 에서:

```bash
python -m pytest tests/test_memoir_illust.py tests/test_memoir_illust_book.py tests/test_memoir_illust_image.py tests/test_memoir_illust_types.py tests/test_memoir_illust_select_trial.py -q
```

```bash
python tools/memoir_illust_book.py --input eval/illust_book_seed_B.json --out eval/runs/illust-book-B-mock --dry-run
```

```bash
python tools/memoir_illust_book.py --input eval/illust_book_seed_B.json --out eval/runs/illust-book-B-mock --mock-select eval/illust_book_mock_B.json --mock-images
```

- `--dry-run` 은 목차 · 사진 상태 · 대상 수 · 부를 횟수 · 보낼 글자 수만 보인다. 아무것도 부르지 않는다.
- `--mock-select` 는 손으로 쓴 후보를 모델 자리에, `--mock-images` 는 「MOCK」 자리 표시 그림을 그림 모델 자리에 끼운다. 결과에 모의라고 적힌다.
- 결과는 `eval/runs/…`(git 제외)에 생긴다. `preview.html` 을 열면 사진 · 삽화가 든 책을 볼 수 있다.
- 목차 유형별 선정 결과는 `eval/illust_types_C.json`(목차 11개) · `eval/illust_types_C_cases.json`(사례 26개)과 `tests/test_memoir_illust_types.py` 로 본다.

실행기는 안전장치로 `"synthetic": true` 인 합성 자료나 `eval/exp/`(git 제외) 아래 파일만 받고, 결과는 `eval/runs/` 아래에만 쓴다.
서비스는 실행기를 쓰지 않는다 — `memoir_illust_service.py` 가 `memoir_illust_book` 의 함수를 직접 부른다(10절).

## 4. 입력 — 서비스가 넘겨야 하는 것

형식은 `illust-input-v1`(규격 문서의 「입력」 절). 꼭 필요한 것:

| 칸 | 뜻 | 지금 서비스 자료 |
|---|---|---|
| `memoir.chapters[]` | 목차 항목 하나 = 하나. `no` · `chapter_key`(있으면) · `title` · `paragraphs[].sentences[]{text, turns}` | 자서전 응답에 있다(식별자는 `no` 뿐) |
| `chapters[].photos` | **그 항목 본문에 놓는 사진 목록.** `[]` 은 「없다」, 칸이 없으면 「모른다」 | 서비스 연결부가 회차 사진으로 채운다 (9절 규칙) |
| 사진의 `path` 또는 `url` · `after_paragraph` | 파일을 읽을 길 · 놓을 문단(0부터) | `path` 는 입력 파일 폴더 기준으로 읽는다. `url` 은 가 보지 않는다 |
| `source.utterances[]{turn, session_id, asked, elder}` · `turn_map` | 원문(어르신 말씀)과 전역 턴 ↔ 회차 턴 | 자서전을 만들 때의 합치기 결과(`turn_map`)와 같다 |
| `photos[]` · `photo_placement.complete` | (선택) 책 전체 사진 목록에서 `chapter_keys` · `chapter_nos` 로 항목을 가리키는 방식 | — |

같은 회차에 사진이 있다는 것만으로는 그 항목에 사진이 있다고 보지 않는다 — 서비스가 「놓았다」 고 적어 줘야 한다.

## 6. 실패 · 자료 부족 · 다시 돌리기

- **실패는 다시 부르지 않는다.** 호출 오류 · 형식 불일치 · 후보 없음 · 대표 그림 없음(`no_representative_candidate`)은 그 항목을 `failed` 로 남긴다. 지어내서 채우지 않는다.
- **사진 정보가 없으면** 그 항목은 `photo_unknown` 이고 책은 `complete` 가 아니다.
- **사진 파일을 읽지 못하면** 오류로 남기고 사진은 빼지 않는다. 자리가 맞지 않으면 항목 끝으로 옮기고 까닭을 적는다.
- **같은 `--out` 으로 다시 돌리면** 장면을 다시 묻지 않고, 그림을 다시 만들지 않고, 삽화가 두 번 들어가지 않는다. 결과 책은 매번 원고와 상태에서 새로 조립한다.
- 앞선 결과가 기대던 것(그 장면의 원문 · 문단 · 지시문 · 양식 · 그림 설정)이 바뀌면 그 그림을 넣지 않고 `needs_reprocess` 와 까닭을 남긴다. `--reprocess-stale` 로 그 항목만 다시 처리한다(앞선 파일은 `items/_stale/` 에 남는다).
- 모의 실행 폴더와 실제 실행 폴더는 섞지 않는다 — 다른 모드로 다시 쓰려 하면 부르기 전에 멈춘다.

## 7. 실제 호출 (돈이 든다 · 승인 뒤에만)

`--live` 는 `--confirm`(dry-run 이 보여 준 확인값) · `--env-file`(키 `GEMINI_API_KEY` — 찍지 않는다) · `--authorized-by` · `--authorization-note` 가 모두 있어야 돈다.
항목마다 장면 선정 1회 + 그림 1회다. 재시도는 끈다.
참고 비용(호출 전 공식 단가를 다시 확인한다): 장면 선정 한 항목 약 $0.002 ~ 0.004(2026-11-16 기록, 입력 $0.30 · 출력 $2.50 / 100만 토큰), 그림 1K 한 장 약 $0.067.

## 8. 알려진 제한

코드가 보는 것은 **글자 일치 · 표지 낱말 · 문장 비율**까지다. 그 사람이 정말 그 행동을 했는지, 무엇이 정말 중심인지는 보지 못한다.

- **짧은 인용** — 요소의 인용이 4글자 미만이면 원문 근거로 치지 않는다. 합성 시험에서 모델이 「나」 의 인용을 「저는」 으로만 적자
  사람 장면이 막히고 사람을 뺀 그림(트럭)이 골라졌다. 같은 사람의 관계 근거 인용은 문장 전체로 맞았는데, 코드는 그것을 보지 않는다.
- **풍경 · 사물 분류** — 같은 풍경을 모델이 장소(place)로 적으면 「신호 둘」 규칙을 타서 비유 제목 · 문장마다 다른 이름(바다 · 물결 · 수평선)이면 실패한다.
  사물(object)로 적으면 모델 focus 로 통과하지만, 그림 지시문이 그것을 「화면 중심의 사물」 로 다루고 「넓은 풍경이 주제가 되지 않게」 적는다.
- **대체 후보 부족** — 중심 근거가 사람에게만 있는 항목(「어머니와 김장하던 날」 의 어머니)은 사람 장면이 막히면 대신할 그림이 없다(사람을 뺀 그림의 배추는 「딸린 것」).
  실제 시험에서 모델은 항목마다 후보를 하나씩만 냈다(지시문은 3개까지) — 후보 비교가 거의 일어나지 않았다.
- 제목이 비유이고 모델 focus 가 없으면, 본문 전체가 풍경이어도 신호가 하나뿐이다.
- 제목의 말이 요소 이름의 일부로만 겹치면(김장 · 김장독) 잇지 못한다.
- 함께 한 사람이 본문에 한 번만 나오면 대표성 등급은 낮다(사람 장면에서 빼지는 않는다 — 시험으로 확인했다).
- 두 문장짜리 글에서는 한 번 나온 것도 본문 절반이라 중심이 된다.
- 모델이 중심 사물을 후보와 focus 어디에도 적지 않으면, 코드는 그것이 있다는 것을 모른다.

## 9. 서비스 연결에서 정한 것

- **장의 사진** (2026-11-24 고침) — 회차에 붙은 사진(`session.photo_id`)을 그 회차 말씀이 쓰인 장 가운데 **대표 장 한 곳**에 놓는다
  (그 장에서 그 회차 말씀이 처음 나오는 문단 뒤). 대표 장 = 그 회차의 서로 다른 턴을 가장 많이 쓴 장
  → 같으면 그 회차의 가장 앞 턴이 나오는 장 → 그래도 같으면 앞 장. 같은 턴이 여러 문장에 쓰여도 한 번으로 센다. 근거는 그 장의 `photo_basis` · 사진의 `placement`.
  같은 사진이 다른 회차에도 붙어 있으면 회차마다 따로 놓는다 — 같은 장에 두 번 놓이면 한 장으로 합치고 회차를 `sessions` 에 모두 적는다.
  앞선 규칙(말씀이 **한 장에만** 쓰였을 때만 놓기)은 여러 장에 걸친 회차의 사진을 빼고, 그 장을 「사진 없음 확인」 으로 보아 AI 삽화를 그렸다.
- **놓지 못한 사진** — 회차 말씀이 어느 장에도 쓰이지 않았으면(`session_not_cited`) 억지로 놓지 않고 까닭(`diagnosis`)과 함께 `unplaced_photos` 에 적는다.
  사진 줄이 없거나 · 주인이 다르거나 · 저장되지 않았으면(`photo_missing` · `photo_not_owned` · `photo_not_stored`) 역시 적고, 그 회차의 대표 장은 「사진 정보 모름」 이다.
  놓지 못한 사진이 있으면 근거 턴이 하나도 없는 장도 「모름」 이다. 「모름」 장은 AI 삽화를 만들지 않는다 — 나머지 장은 「사진 없음 확인」 으로 그대로 그린다.
- **이미 만든 책** — 저절로 바꾸지 않는다. `tools/memoir_illust_reprocess.py --memoir <id> --refresh-photos` 로 보고 `--apply` 로 적는다(모델 호출 0).
  사진이 새로 놓인 장은 photo 가 되고, 앞서 만든 AI 삽화 기록 · 그림은 지우지 않는다(`photo_over_illustration`). 「모름」 으로 바뀌어도 이미 넣은 삽화는 숨기지 않는다.
- **저장** — 그림 바이트는 사진과 같은 저장소(`photostore`, 기본 `photo_blob`), 키 `illusts/YYYY/MM/<memoir_id>/c<장>-<해시>.jpg`. 상태는 `memoir.illustrations`.
- **호출 승인** — 서비스에서는 로그인 · 책 주인 확인과 서버 설정(`MEMOIR_ILLUST` · `GEMINI_API_KEY`)으로 자동이다. 실행기의 확인값은 운영 절차가 아니다.

**실패 · 다시 돌리기**

- 자서전 작업 · 본문은 삽화를 기다리지 않는다. 삽화가 실패해도 책은 열린다. 실패 · 보류 · 자료 부족은 그 장의 `state` · `failure` 로 남고, 초안 화면에 「그림을 넣지 못한 장」 으로 보인다.
- 장마다 장면 선정 1회 · 그림 1회. 부르기 **전에** DB 에 「불렀다」 를 적는다 — 서버가 그 사이에 꺼지면 그 장은 `select_attempt_without_result` · `image_attempt_without_result` 실패로 남고 다시 부르지 않는다.
- 같은 책을 다시 돌려도(서버 재시작 뒤 화면이 책을 열면 `running` 으로 멈춘 책은 남은 장만 이어서 한다) 이미 넣은 그림은 넣을 자리만 다시 정한다 — 호출 · 중복 삽입 없음.
- 실패한 장을 다시 만드는 버튼 · 자동 재시도는 없다(과금).

  - `--prepare` 는 `--chapter` 로 이름을 댄 장만 「지금 판으로 다시」 로 표시하고(앞선 기록은 그 장의 `history` 로 옮긴다) 책 상태를 `running` 으로 둔다.
    **부르지 않는다.** `--chapter` 없이 `--prepare` 하면 거부한다(실패한 장을 모두 저절로 다시 부르지 않는다).
  - 실제 처리는 **새 코드로 다시 켠 서버**가 그 책을 다음에 열 때(책 주인이 「자서전 보기」 에서 펼칠 때) 그 장들만 한다 — 장마다 선정 1 · 그림 1.
  - 다시 할 수 있는 장: **실패한 장 가운데 지금 판으로 한 번도 부르지 않은 장.** 판이 바뀌면(v1 → v2) v1 으로 실패한 장은 v2 로 한 번 다시 할 수 있다.
    v2 로 이미 부른 장 · 사진 장 · 넣은 삽화 · 보류 · 사진 정보를 모르는 장은 이름을 대도 거부하고 까닭(`refused`)을 보인다. 앞선 기록 · 호출 수는 지우지 않는다.

**주제 방식의 알려진 제한 (v2)**

- 그림이 장에 맞는지(뜻)는 모델의 판단이다. 코드는 검증하지 않는다 — 모델이 부정 · 가정 · 희망을 잘못 읽거나 본문에 없는 관계를 계획에 넣으면 그대로 그려질 수 있다.
  지시문 v7 · v8 · 그림 양식 v2 · v3 가 금지할 뿐이다. 실제 모델로는 아직 확인하지 않았다.
- 고유한 인물 이름 · 상표 · 랜드마크는 코드가 찾지 못한다.
- v1 의 낱말 경계 셈은 참고 정보(`anchor_reference`)에만 남았다 — 붙은 말(배낭여행)은 그 낱말로 세지 않고, 뜻이 다른 같은 낱말(말)은 가리지 못한다.
