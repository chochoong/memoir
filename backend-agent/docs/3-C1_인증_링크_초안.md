## 1. 누가 무엇인가

| 이름 | 무엇 | 지금 저장소 |
|---|---|---|
| 자녀 | 구글로 로그인해 기록을 관리하는 사람 | `app_user` (003, 비어 있음) |
| 화자 | 이야기의 주인공 (어르신) | `elder` (003, 비어 있음) |
| 자녀–화자 | 이 자녀가 이 화자를 관리한다 | `user_elder` (003, 비어 있음) |
| 회차 | 인터뷰 한 번 | `session` (`user_id` TEXT · 지금은 헤더 값) |
| 앱 세션 | 자녀 로그인 상태 | `login_session` (003, 비어 있음) |

- 003 의 네 표는 로컬 DB 에 만들어져 있고 0행이다. 쓰는 코드는 없다. Supabase DB 적용 여부는 **미확인**.
- 링크를 가진 사람이 실제 부모님이라는 보증은 하지 않는다. 링크는 「이 회차를 진행해도 된다」는 권한일 뿐이다.

## 2. 소유 관계 (제안)

```
app_user ──< user_elder >── elder
   │                          │
   │ 발급·소유                  │ 화자
   ▼                          ▼
interview_link ──(시작 시 1:1)── session ──< turn
                                  │
                                  ├── photo (보조 사진)
                                  └── postcard
```

- **회차의 관리 주인은 발급한 자녀 한 명이다.** `session.user_id` 에 내부 `app_user.user_id` 를 넣는다.
  형제 공동 관리(같은 화자를 두 자녀가 보기)는 이번 범위가 아니다 — 표 구조는 막지 않는다.
- **회차에 화자를 적는다.** `session.elder_id` 를 새로 둔다 (NULL 허용 — 기존 dev-user 행 때문).
  자서전 「같은 화자의 회차만」 검사가 지금은 user_id 로 대신하고 있는데, 이것이 진짜 화자 기준이 된다.
- 이름이 같다는 이유로 기존 화자에 붙이지 않는다. 화자는 자녀가 직접 만든다 (§3).
- 사진 · 엽서는 지금처럼 `user_id`(= 소유 자녀) 로 소유를 본다. 회차와 따로 올린 사진도 같다.

## 3. 첫 로그인과 첫 회차 준비 (제안)

1. 자녀가 구글로 로그인한다 → `app_user` 한 줄 (처음이면 생성, `provider='google'`, `subject=sub`).
2. 화자가 없으면 화면이 「누구의 이야기를 남길까요?」로 화자 이름 하나를 받는다 → `elder` + `user_elder`.
   자동 생성 · 이름 매칭은 하지 않는다. 상세 프로필(생년 등)은 받지 않는다 (`born_year` 는 비워 둔다).
3. 자녀가 회차를 준비한다 — 테마 · 주제 · (선택) 사진 → `interview_link` 발급, 토큰을 한 번만 돌려준다.
4. 자녀가 링크를 복사해 보낸다. **서버는 SMS · 카카오로 보내지 않는다.**
5. 자녀가 같은 기기에서 바로 진행하는 길(지금 방식)은 남긴다 — 자녀 세션으로 `POST /api/sessions`.

## 4. 로그인 경로 (P3-SV-02, 제안)

**Google Identity Services 「Google 로그인」 버튼 · popup · JS 콜백.**

- 지금 화면은 SPA 이고 서버가 같은 출처로 화면을 낸다. redirect(data-login_uri) 보다 popup + JS 콜백이 화면 이동이 없다.
- 콜백이 받은 ID 토큰(credential)을 `POST /api/auth/google` 본문으로 보낸다.
- 서버는 공식 라이브러리 `google-auth` 의 `id_token.verify_oauth2_token` 으로 서명 · `aud`(= 우리 클라이언트 ID) · `iss` · `exp` 를 확인한다.
  **새 의존성 하나** (`google-auth`). 직접 JWT 를 풀어 믿지 않는다.
- 계정은 `sub` 로 찾는다. 이메일은 표시용이고 식별에 쓰지 않는다.
- **제공자 검증과 앱 세션은 다르다.** 검증이 끝나면 서버가 새 무작위 값(32바이트)을 만들어 앱 세션 쿠키로 준다.
  ID 토큰을 쿠키에 넣거나 앱 세션으로 다시 쓰지 않는다.

| 항목 | 값 (제안) |
|---|---|
| 앱 세션 쿠키 | `msid` · HttpOnly · SameSite=Lax · Path=/ · https 면 Secure (지금 `uid` 쿠키와 같은 규칙) |
| DB | `login_session(kind='web')` 에 sha256 만 |
| 요청 위조 방지 | 상태를 바꾸는 요청(POST 등)은 `Origin` 이 허용 목록과 같아야 한다 + SameSite=Lax. popup 모드는 `g_csrf_token` 이중 제출이 없다 (redirect 모드 전용) |
| 앱 세션 수명 | **미결** — 값은 팀 확인 후 |

| 경로 | 결과 |
|---|---|
| `POST /api/auth/google` | 200 `{user, elders}` + 쿠키 · 401 `invalid_token` (서명·aud·iss 틀림) · 401 `expired_token` |
| `GET /api/auth/me` | 200 `{user, elders}` · 401 `login_required` · 401 `session_expired` |
| `POST /api/auth/logout` | 204. 표에 `revoked_at` 을 찍고 쿠키를 지운다 |

- 「취소」는 서버에 오지 않는다 (화면이 popup 닫힘을 받는다). 화면은 로그인 전 상태 그대로다.
- 로그 · 오류에 ID 토큰 · 쿠키 값 · 이메일을 남기지 않는다. 남기는 것은 내부 user_id 뿐이다.

## 5. 인터뷰 링크 (P3-SV-04 · 05, 제안)

### 5-1. 모양

```
https://<고정 주소>/i#<토큰>
```

- 토큰은 `#` 뒤(fragment)에 둔다. **브라우저가 서버로 보내지 않는다** — 프록시 · 서버 접근 로그 · Referer 에 남지 않는다.
  화면이 읽어서 API 요청 헤더로 보낸다.
- 메신저 미리보기 봇이 링크를 열어도 `/i` 화면 HTML 만 받는다. 토큰이 서버에 닿지 않으니 아무것도 소모되지 않는다.

### 5-2. 흐름

| 단계 | 요청 | 상태 변경 |
|---|---|---|
| 미리보기 | `GET /api/i/preview` (헤더 `X-Interview-Token`) | **없음.** 테마 · 주제 · 링크 상태만 준다. 몇 번 열어도 같다 |
| 명시 시작 | `POST /api/i/start` (같은 헤더) | 처음이면 회차 생성 · `session_id` 기록 · 인터뷰 쿠키 발급. **이미 시작했으면 같은 회차를 돌려준다** (연속 클릭 · 재시도 = 한 회차) |
| 진행 | `/api/i/session/...` (§6 의 인터뷰 동작만) | 인터뷰 쿠키로 권한 확인 |
| 종료 | `POST /api/i/session/done` 등 | 회차 종료 · `ended_at` |

- 인터뷰 쿠키 `mlink` 는 Path=/api/i · HttpOnly. `<img>` · `<audio>` (질문 음성 · 보조 사진)가 헤더 없이도 권한을 가져가게 한다.
- **권한을 합치지 않는다.** `/api/i/*` 는 링크 권한만 본다 (`msid` 를 무시). 자녀 관리 경로는 `msid` 만 본다 (`mlink` 를 무시).
  같은 브라우저에 둘 다 있어도 한 요청은 한 주체다.
- 링크 요청 본문의 `session_id` · `user_id` · `elder_id` 는 받지 않는다. 회차는 링크가 정한다.
- 지금의 `/api/sessions/{id}/...` 진행 라우트는 자녀가 직접 진행할 때 쓰고, 소유 검사를 붙인다 (§7).
  `/api/i/*` 는 같은 처리 함수를 부르는 얇은 입구다 — 인터뷰 로직을 두 벌 만들지 않는다.

### 5-3. 링크 상태와 응답

| 상태 (C1 의미 — DB enum 아님) | 판단 | 미리보기 | 시작 · 진행 |
|---|---|---|---|
| 시작 전 | 유효 · `session_id` 없음 | 200 `state: ready` | 시작 가능 |
| 진행 중 | 회차가 메모리에 살아 있음 | 200 `state: in_progress` | 같은 기기(`mlink` 있음)면 이어서 · 없으면 409 `code: in_progress_elsewhere` (D5) |
| 종료 | `ended_at` 있음 | 200 `state: ended` | 409 `code: ended` · 대화는 §5-4 읽기 전용으로 |
| 끊김 | 시작했는데 회차가 메모리에 없음 (서버 재시작) | 200 `state: interrupted` | 409 `code: interrupted` |
| 만료 | `expires_at` 지남 | 410 `code: expired` | 410 `code: expired` |
| 회수 | `revoked_at` 있음 | 410 `code: revoked` | 410 `code: revoked` |
| 잘못된 링크 | 해시가 없음 | 404 `code: invalid_link` | 404 `code: invalid_link` |

- 오류 본문은 2차 엽서 409 와 같은 `{"detail", "code"}` 이다. detail 문구는 김대원 님과 맞춘다.
- 410 · 404 에는 주제 · 화자 · 발급자 정보를 싣지 않는다.
- **끊김은 지금 구조의 한계다.** 진행 중 회차는 서버 메모리에만 있다. 재시작하면 회차가 사라지고 DB 에는 닫히지 않은 회차와 그때까지의 턴이 남는다. 새 저장소는 만들지 않는다 (지시서 P3-SV-06).

### 5-4. 종료 뒤 읽기 전용 대화 (D6)

`GET /api/i/transcript` (헤더 `X-Interview-Token`) — 종료된 링크에서만 200.

- **싣는 것:** 그 회차의 질문과 답(말씀) 차례대로. 첫 화면의 테마 · 주제.
- **싣지 않는 것:** 자녀의 원문 편집 결과 · 엽서 · 자서전 · 다른 회차 · 화자 · 발급자 정보 · 모델 판단(내부 상태).
  자녀가 2차 A 로 고친 문장이 나오지 않으므로 「어르신이 그때 하신 말씀」 그대로다.
- **수정 · 삭제 · 생성 동작은 없다.** 읽기만.
- 기간: 링크가 살아 있는 동안. 만료 · 회수 뒤에는 410 이고 대화를 주지 않는다.
- 자녀가 결과 사용 제외 · 영구 삭제한 말씀을 여기서 계속 보여 줄지는 2차 A 의 통제 구분이 정해진 뒤 맞춘다 (**미결**).
- 링크가 새면 대화가 보인다 — D6 을 고른 대가다. 자녀가 회수하면 바로 닫힌다.

## 6. 자원별 허용 (지시서 6.1 을 실제 라우트에 맞춤)

| 자원 · 동작 | 지금 라우트 | 자녀 (`msid`, 자기 것) | 링크 (`mlink`, 지정 회차) | 다른 계정 · 미인증 |
|---|---|---|---|---|
| 회차 목록 | `GET /api/sessions` | 허용 | 불가 | 401 |
| 지난 회차 기록 | `GET /api/sessions/{id}/record` | 허용 | 불가 | 404 |
| 회차 열기 (직접 진행) | `POST /api/sessions` | 허용 | 불가 (링크는 `/api/i/start`) | 401 |
| 진행 상태 · 말 · 음성 · 종료 · 중단 | `GET /api/sessions/{id}` · `speech` · `speech/audio` · `tts-done` · `question/audio` · `done` · `abort` | 허용 | `/api/i/session/...` 로 지정 회차만 | 404 |
| 지연 계측 | `GET /api/sessions/{id}/latency` | 허용 | 불가 | 404 |
| 사진 올리기 | `POST /api/photos` | 허용 | 불가 (보조 사진은 자녀가 준비) | 401 |
| 사진 바이트 | `GET /api/photos/{id}` | 허용 | 링크에 지정된 사진만 | 404 |
| 엽서 만들기 · 엽서 JPEG | `POST`·`GET /api/sessions/{id}/postcard` | 허용 | 불가 | 404 |
| 자서전 미리보기 | `POST /api/memoirs/preview` | 허용 | 불가 | 404 |
| 원문 편집 (2차 A) | 아직 없음 | 허용 | 불가 | — |
| 링크 발급 · 회수 · 목록 | 새로 | 허용 (자기 화자만) | 불가 | 401 |
| 링크 미리보기 · 시작 | 새로 `/api/i/*` | — | 허용 | 토큰 없으면 404 |
| 종료 뒤 대화 읽기 | 새로 `GET /api/i/transcript` | (자녀는 record 로 본다) | 종료된 지정 회차만 · 읽기 전용 | 404 |

- **남의 것은 403 이 아니라 404 다.** 지금 record · 사진 · 엽서의 규칙을 그대로 넓힌다.
- 검사는 자료를 읽거나 만들기 **전에** 한다. 304 · 바이트 · 외부 모델 호출이 검사 뒤에만 나간다.
- 로그아웃 · 회수 · 만료 뒤의 **새 요청**은 다시 검사한다. 이미 내려받은 파일 · 브라우저 캐시를 지웠다고 약속하지 않는다.

## 7. P3-SV-03 — 지금 라우트의 신원 경로 (코드 확인 결과)

`main.py` 기준. 「지금 검사」는 위조 가능한 값과 비교하는 것까지 포함한다.

| 라우트 | 신원을 어디서 | 지금 검사 | 바꿀 것 |
|---|---|---|---|
| `GET /api/health` | — | — | 공개 범위 (민감 자료 없음) |
| `POST /api/sessions` | 헤더 `X-User-Id` (기본 `dev-user`) | 없음. `photo_id` 는 controller 가 사진 주인과 대조 | 앱 세션 필수 · 화자 소유 확인 |
| `GET /api/sessions/{id}` | 없음 | **없음** (`session_id` 만 알면 보임) | 소유 확인 |
| `POST …/tts-done` · `speech` · `speech/audio` · `done` · `abort` | 없음 | **없음** | 소유 확인 |
| `GET …/question/audio` | 없음 | **없음** | 소유 확인 (`<audio>` 라 쿠키) |
| `GET …/latency` | 없음 | **없음** | 소유 확인 |
| `GET /api/sessions` | 헤더 (기본 `dev-user`) | user_id 로 거름 | 앱 세션 |
| `GET …/record` | 헤더 (기본 `dev-user`) | user_id 비교 · 남의 것 404 | 앱 세션 |
| `POST /api/photos` | `uid()` (헤더 → 쿠키 → `dev-user`) | 살아 있는 회차면 주인 비교 | 앱 세션 |
| `GET /api/photos/{id}` | `uid()` | 주인 비교 → 304 → 바이트 (순서는 맞음) | 앱 세션 또는 링크 지정 사진 |
| `POST`·`GET …/postcard` | `uid()` | 주인 비교 | 앱 세션 |
| `POST /api/memoirs/preview` | `uid()` | 회차마다 주인 비교 | 앱 세션 · 같은 화자를 `elder_id` 로 |
| 미들웨어 `mirror_uid` | 헤더를 `uid` 쿠키로 복사 | — | **제거** |
| SPA `/{path}` · `/assets` | — | — | 공개 범위 (정적 파일) |

- 신원 함수는 `uid()` 하나가 아니다. 헤더 직접 받기 3곳 · `uid()` 5곳 · 신원 없음 8곳이다. 전부 같은 검사 하나로 모은다.
- 프론트 `frontend-client/src/api.ts` 에 `'X-User-Id': 'dev-user'` 3곳 · `prototype/index.html` 에도 같은 헤더가 있다 → 강승우 님.
- **dev-user 우회를 끄는 방법:** 헤더 · 쿠키 신원을 아예 읽지 않는다. 개발 편의 스위치(환경 변수로 다시 켜기)는 두지 않는다 —
  시험은 FastAPI 의존성 교체로 계정을 꽂는다. 지금 테스트 다수가 `X-User-Id` 로 돌아서 함께 고친다.
