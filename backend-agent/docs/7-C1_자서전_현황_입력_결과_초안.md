# 7-C1 — 자서전 현황 · 입력 · 결과 계약 초안 (MEM-SV-01 · 02 · 04)

작성 최충 · 받는 사람 김대원 · 강승우 · 안다애 · 확인 태헌
기준 서버 `feature/theme-interview` `ad797ec` 뒤 · 배포 화면 html-prototype `51c7de4` (v0.38) · 2026-10-22

**이 문서에서 실행한 것은 코드 읽기와 `tools/memoir_input.py` (모델 호출 없음) 뿐이다.** 자서전 모델은 부르지 않았다.
§3 의 결과 구조는 **합의안**이다 — 지금 API · DB 에 있는 칸이 아니다.

**새 구조로 가면 바뀌어야 하는 곳 (충돌 목록)**

1. `check` 의 「한 줄 = 한 출처 · 소제목 금지」는 장 구조와 맞지 않는다 → §3 의 장 · 문단 · 문장 검사로 바꾼다. 출처 없는 연결 문장을 허용할지는 미결 (§4).
2. `roledoc` 은 역할 절 하나만 싣는다 → 다섯 역할이면 역할마다 절 번호가 필요하다. 대원 님 P1 의 절 구성을 받아야 정한다. 파일 이름만 바꿔서는 적용되지 않는다.
3. 단일 호출 · 기다리는 요청 → 다섯 단계면 시간이 길어진다. 지금 요청 방식으로 될지 대원 님 실제 시간을 보고 정한다 (MEM-SV-06).
4. 선택 3~5개 · 엽서 필수 → 「전체 선택 후 제외」가 최신 결정인지 태헌 확인 (§4).
5. ~~오류에 `code` 가 없다~~ → 더했다 (§3-4). 일부 장 실패 (`partial`) 는 오류가 아니라 200 의 `status` 다.

## 2. C1/input — 초기 실제 함수 출력 (MEM-SV-02)

**새로 만들지 않고 `docs/2-C1_B_자서전_실제입력.md` 를 그대로 쓴다.** 오늘 다시 뽑아 그 파일과 비교했다.

```
python tools/memoir_input.py --manifest eval/memoir_seed_B.ids.json --aliases s-r1,s-r2,s-r3 --out <임시>
→ 회차 3개 · 말씀 7턴 · 사실 6개
```

`input` · `input_alias` · `turn_map` · `turn_map_alias` · `session_ids` 가 10-20 에 올린 파일과 **모두 같다** —
그 뒤 코드가 바뀌었어도 자서전 입력 조립은 그대로다.

| 항목 | 값 |
|---|---|
| 자료 | 합성 세트 B (memoir-seed-v1.1) — `[B] 딸 입학 원진술` · `[B] 꽃집과 제외 요청` · `[B] 입학 연도 정정` |
| 출력 | 실제 함수 (`check_selection` → `merge`) 출력. alias 판은 비교용 사본 |
| 턴 대응 | 전역 턴 7개 ↔ (회차, 회차 안 턴) — 2-C1/B §5 |
| 모델 | 부르지 않음 |
| 화자 | 같은 `user_id` (`dev-user`) 라서 같은 화자로 본 것이 아니다 — 세트 B 가 한 화자로 설계된 합성 자료다 |

주의.

- 도구는 3~5개만 본다. **엽서 유무는 보지 않는다** — 서비스 (`/api/memoirs/preview`) 는 엽서 없는 회차를 404 로 막는다.
  세트 B 의 `dev-user` 판은 엽서가 없어 서비스로는 못 돌린다. 같은 세트를 실제 계정에 넣은 판 (엽서 있음) 이 이 DB 에 따로 있다.
- 세트 A (5회차, `eval/memoir_seed_A.json`) 는 DB 에 넣지 않았다. 다애 님 대표 범위 (MEM-QA-01 D1) 가 오면 그 범위로 넣고 같은 명령으로 뽑는다.
- 정정 · 제외가 반영된 **C1/수정본**은 실제 수정 경로 결과가 와야 만든다 (MEM-SV-03).

## 3. C1/result — 결과 계약 초안 (MEM-SV-04, 합의안)

원칙: **기존 화면이 읽는 `title · body · sources` 는 그대로 나온다** (어댑터). 장 구조는 그 위에 더한다.
아래 예시의 문장 · 턴 번호는 **설명용으로 지어낸 것**이다 — 모델 출력도 실제 함수 출력도 아니다.

### 3-1. 정상

```json
{
  "status": "ready",
  "style": "spoken",
  "title": "꽃집 앞에서 보낸 봄",
  "chapters": [
    {"no": 1, "title": "딸의 입학", "status": "ready",
     "paragraphs": [
       {"sentences": [
         {"text": "저는 그해 봄 딸의 입학식에 갔어요.", "turns": [1]},
         {"text": "그날은 오래 기억에 남았어요.", "turns": [2]}
       ]}
     ]},
    {"no": 2, "title": "꽃집", "status": "ready",
     "paragraphs": [
       {"sentences": [{"text": "그 뒤로 저는 꽃집을 열었어요.", "turns": [4]}]}
     ]}
  ],
  "to_confirm": [],
  "body": "저는 그해 봄 딸의 입학식에 갔어요.\n그날은 오래 기억에 남았어요.\n그 뒤로 저는 꽃집을 열었어요.",
  "sources": [{"sentence": 0, "turns": [1]}, {"sentence": 1, "turns": [2]}, {"sentence": 2, "turns": [4]}],
  "run": {"session_ids": ["…", "…", "…"], "chapters_requested": 2}
}
```

- `body` · `sources` 는 장 · 문단 순서대로 문장을 펼친 것 — 서버가 만든다. 모델에게 두 번 쓰게 하지 않는다.
- `turns` 는 이 요청의 전역 턴 (C1/input 의 `turn_map`). 다른 실행의 턴을 섞지 않는다.
- `run` 은 화면이 늦게 온 응답을 알아보는 데 쓴다 (지금 `style` 이 하는 일과 같다).
  **장 구조를 켤 때 `run` 은 반드시 싣는다** — v0.39 는 `run.session_ids` 가 보낸 회차와 다르면 버린다.
- 화면 v0.39 (승우 님 회신): `chapters` 가 있으면 `body` 를 읽지 않고, 없으면 지금처럼 `body` 로 읽는다.
  **순서: 배포 화면 v0.39 이상 확인 → 서버 장 구조.** v0.38 은 장이 실린 응답을 실패로 보여 주고,
  `partial` 의 `body` (성공한 장만) 를 완성본처럼 보일 수 있다.

### 3-2. 자료 없음

```json
{"status": "insufficient_material", "style": "spoken", "title": "", "chapters": [],
 "to_confirm": [], "body": "", "sources": [], "run": {"session_ids": ["…"], "chapters_requested": 0}}
```

지금과 같다 — 200 · 빈 본문. 조회 장애 (422 · 503) 와 섞지 않는다.

### 3-3. 일부 장 실패

```json
{"status": "partial", "style": "spoken", "title": "꽃집 앞에서 보낸 봄",
 "chapters": [
   {"no": 1, "title": "딸의 입학", "status": "ready", "paragraphs": ["…"]},
   {"no": 2, "title": "", "status": "failed", "reason": "generation_timeout", "paragraphs": []}
 ],
 "to_confirm": [], "body": "…1장 문장만…", "sources": ["…1장 문장만…"],
 "run": {"session_ids": ["…"], "chapters_requested": 2}}
```

- `partial` 은 **전체 완료가 아니다.** 화면은 「일부 장을 만들지 못했어요」로 따로 보여야 한다 (승우 님 MEM-FE-03).
- 지금 코드에는 `partial` 이 없다 — 모델 출력이 하나라도 어긋나면 전체 502 다.

### 3-4. 오류 — `{detail, code}` (더함)

| HTTP | `detail` | `code` |
|---|---|---|
| 400 | 선택 확인 | `bad_selection` · 문체는 `unsupported_style` |
| 404 | 회차 · 엽서 없음 | `not_found` |
| 422 | 자료 못 읽음 | `source_unavailable` |
| 502 | 만드는 중 문제 | `invalid_model_output` |
| 503 | 지금 만들 수 없음 | `not_final` — `needs_confirmation` · `needs_context` 를 화면이 나누지 않아 하나로 |
| 504 | 시간 안에 못 받음 | `generation_timeout` |

- 화면은 `code` 를 HTTP 숫자보다 먼저 보고, 없거나 모르는 값이면 숫자로 고른다 — 예전 서버 · 화면과 맞는다.
- `detail` 문장은 바꾸지 않았다. 시험 `tests/test_memoir.py` 에서 갈래마다 `code` 를 본다.
- **같은 선택으로 두 번 요청하면:** 엽서의 `busy` 같은 막음이 없다. 둘 다 모델을 부르고 둘 다 결과를 받는다.
  저장하지 않으므로 데이터는 섞이지 않고 비용만 두 번이다. 화면이 만드는 동안 버튼을 잠그므로 새 `code` 는 두지 않는다.

## 4. 미결 — 누가 정하나

| 항목 | 지금 | 담당 · 결정 |
|---|---|---|
| 자서전 선택 범위 | 3~5개 · 엽서 필수 | 태헌 — 「전체 선택 후 제외」가 승인된 최신 결정인지 근거 원문 |
| 출처 없는 연결 문장 | 금지 (줄마다 출처) | 대원 · 다애 — 새 사실이 없는 전환 문장에 `turns: []` 를 허용할지 |
| `partial` 을 보여 줄지 | 없음 (전체 502) | 태헌 — 승우 님이 A (완성본으로 열지 않음 · 기본) · B (만든 장만 「일부」 로) 두 안을 만들어 둠 |
| 장 수 · 장 나누기 | 없음 | 대원 — 한 회차 = 한 장으로 고정하지 않는다 (지시서) |
| 다섯 역할의 절 구성 · 단계별 출력 | 없음 | 대원 P1 |
| 실행 시간 · 재시도 · 요청 방식 | 단일 호출 · 기다리는 요청 | 대원 실제 시간 → 충 |
| 저장 | 저장 안 함 | 태헌 — 새 저장은 별도 결정 |
| 계정 안 화자 구분 | 없음 | 충 + 대원 → 태헌 |
