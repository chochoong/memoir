# 배포 — 고정 주소와 HTTPS

이 문서가 끝나면 이렇게 된다.

```
어르신 휴대폰
   │  https://naemalssami.com          ← 바뀌지 않는 주소 · 자물쇠 표시
   ▼
Cloudflare 엣지                           ← TLS 를 여기서 끝낸다 (인증서 자동)
   │  터널 (이 PC 가 밖으로 맺은 연결)
   ▼
cloudflared  (이 PC)
   │  http://127.0.0.1:8010              ← 이 컴퓨터 안에서만 오가는 평문
   ▼
uvicorn → FastAPI → Postgres
```

**공유기 포트를 열지 않는다.** 터널은 이 PC 가 Cloudflare 쪽으로 **나가서** 맺는
연결이라, 바깥에서 들어오는 구멍을 만들 필요가 없다. 인증서 발급·갱신도 없다.

## 왜 지금 이것부터인가

⑤ 로그인을 붙이려면 **바뀌지 않는 주소가 먼저** 있어야 한다. 구글 로그인은
로그인 버튼이 뜨는 주소(승인된 JavaScript 출처)를 미리 등록하게 하고, 그 주소가
바뀌면 로그인이 깨진다. 임시 터널 주소(`trycloudflare.com`)는 재시작마다 바뀌므로
등록할 수가 없다. 어르신께 보내는 인터뷰 링크도 `PUBLIC_ORIGIN` 위에 만들어져서,
주소가 바뀌면 이미 보낸 링크가 죽는다. 쿠키의 `Secure` 도 https 가 있어야 의미가 생긴다.

## 비용

| | |
|---|---|
도메인 | `.com` 연 2만원 안팎. Cloudflare Registrar 는 원가로 판다 |
Cloudflare 터널 · TLS · DNS | 무료 |
전기 · 인터넷 | 이 PC 를 켜 두는 값 |

`.kr` 은 Cloudflare 가 팔지 않는다. 가비아 등에서 사고 네임서버만 Cloudflare 로
바꾸면 된다 (2단계에 절차가 있다).

---

## 1단계 — 도메인

Cloudflare 계정을 만들고 **Domain Registration → Register Domain** 에서 바로 산다.
여기서 사면 네임서버가 자동으로 붙어 2단계를 건너뛴다.

이름은 어르신이 **불러 주기 쉬운 것**으로 고른다. 가족이 전화로 알려 드리는 일이
생긴다 — 철자를 설명해야 하는 이름은 그때 문제가 된다.

## 2단계 — 다른 곳에서 샀다면

Cloudflare **Add a site** → 도메인 입력 → Free 요금제 → 안내에 나온 네임서버 두
개를 원래 등록기관(가비아 등) 관리 화면에서 바꾼다. 반영에 보통 몇 분, 길면 하루
걸린다. Cloudflare 대시보드에 **Active** 로 바뀌면 끝이다.

## 3단계 — 터널 만들기

```powershell
winget install --id Cloudflare.cloudflared

cloudflared tunnel login          # 브라우저가 열린다 — 도메인을 고른다
cloudflared tunnel create memoa   # 터널 ID 와 자격 파일(.json)이 나온다
cloudflared tunnel list           # ID 를 확인한다

# 이 이름으로 오는 요청을 이 터널로 보낸다 (DNS 레코드가 자동으로 생긴다)
cloudflared tunnel route dns memoa naemalssami.com
```

설정 파일을 `%USERPROFILE%\.cloudflared\config.yml` 에 만든다. 본은
`deploy/cloudflared.example.yml` 에 있다 — 터널 ID·자격 파일 경로·호스트 이름
세 곳을 채운다.

먼저 손으로 띄워 확인한다. 창 두 개가 필요하다.

```powershell
# 창 1
.\run.ps1
# 창 2
cloudflared tunnel run memoa
```

휴대폰에서 `https://naemalssami.com/api/health` 를 연다.

## 4단계 — .env 의 배포값

```ini
PUBLIC_ORIGIN=https://naemalssami.com
TRUST_PROXY=cf
```

**이 두 줄이 이번 작업의 핵심이다.**

`PUBLIC_ORIGIN` 은 주소를 적어 두는 칸이 아니라 **「공개 배포 중」이라는 스위치**다.
이 값이 있으면 서버가 스스로 셋을 바꾼다.

- 개발용 CORS 허용(`localhost:5173`)을 목록에서 뺀다
- `/docs` 와 `/openapi.json` 을 닫는다 (`DOCS=1` 로 되살릴 수 있다)
- 신원 쿠키에 `Secure` 를 붙인다

끄는 것을 잊게 두지 않으려고 스위치를 따로 만들지 않았다. **배포 주소를 적는
행위 자체가 개발용 편의를 닫는다.**

`TRUST_PROXY=cf` 는 생성 상한이 셀 주소를 정한다. 터널 뒤에서는 모든 요청의 소켓
주소가 `127.0.0.1` 이라, 이걸 켜지 않으면 **전 세계가 한 칸을 나눠 쓴다** — 10분에
10회면 어르신 열한 분째부터 막힌다. `cf` 는 Cloudflare 엣지가 **덮어써 주는**
`CF-Connecting-IP` 를 읽는다.

> `X-Forwarded-For` 를 쓰지 않는 이유가 있다. 그 헤더는 클라이언트가 이미 넣어
> 보낸 값 **뒤에 덧붙는다.** 맨 앞을 읽으면 공격자가 쓴 글씨를 읽는 것이고, 그러면
> 요청마다 다른 값을 넣는 것만으로 상한이 사라진다. 일반 역프록시 뒤라면
> `TRUST_PROXY=xff` 를 쓴다 — 맨 **뒤** 값을 읽는다.

나머지는 그대로 둔다. `ALLOWED_ORIGINS` 는 **비워 둔다** — 화면을 이 서버가 직접
내므로 같은 출처이고, CORS 가 아예 필요 없다.

## 5단계 — 화면을 서버에 넣기

화면은 HTML 프론트(`origin/html-prototype` 의 `prototype/index.html` · 파일 하나)다 (4-C1).
그대로 넣으면 `X-User-Id` 를 보내는 dev 모드라 401 이 난다. **두 값만 바꿔** `web\index.html` 로 넣는다.

```
CONFIG.auth.mode            'dev'  → 'session'
CONFIG.auth.googleClientId  ''     → .env 의 GOOGLE_CLIENT_ID 와 같은 값 (비밀값 아님)
```

**`web\assets` 폴더는 비어 있어도 남겨 둔다.** `web\index.html` 이 있으면 서버가 `/assets` 를
붙이는데, 폴더가 없으면 기동이 실패한다. 이미 떠 있는 서버는 멀쩡해서 다음 재시작 때야 드러난다.

`web\` 는 git 에 들어가지 않는다. 화면이 새로 올라오면 이 일을 다시 한다.
서버를 다시 띄울 필요는 없다.

이러면 주소 하나로 화면과 API 가 같이 나온다. 같은 출처라 쿠키 문제도 없다.
어르신 링크 `/i#…` 도 같은 파일이 받는다.

## 6단계 — 재부팅에서 살아남기

둘 다 서비스로 올려야 한다. 하나만 올리면 재부팅 뒤에 조용히 죽어 있다.

**터널**

```powershell
cloudflared service install
```

설정 파일을 **SYSTEM 계정 자리에도** 둬야 한다. 손으로는 되는데 서비스로 바꾸면
안 되는 사고가 거의 다 여기서 난다.

```powershell
$sys = "C:\Windows\System32\config\systemprofile\.cloudflared"
New-Item -ItemType Directory -Force $sys
Copy-Item "$env:USERPROFILE\.cloudflared\*" $sys -Recurse -Force
Restart-Service cloudflared
```

**API**

```powershell
schtasks /Create /TN "memoir-api" /SC ONSTART /RU SYSTEM /RL HIGHEST `
  /TR "powershell -ExecutionPolicy Bypass -NoProfile -File C:\workspace\memoir\backend-agent\run.ps1"
```

**python 이 사용자 설치(`%LOCALAPPDATA%\Programs\Python`)면 SYSTEM 은 `python` 을 못 찾는다.**
SYSTEM 에는 그 사용자의 PATH 가 없다. 작업이 「실행됨」 으로 보이는데 서버는 없다.
`/TR` 에 run.ps1 을 바로 걸지 말고, PATH 에 python 폴더를 앞에 붙인 뒤 run.ps1 을
부르는 작은 기동 스크립트(예: `C:\ProgramData\memoa\start_api.cmd`)를 건다.
그 스크립트에서 출력을 파일로 돌려 두지 않으면 SYSTEM 으로 뜬 서버의 로그는 어디에도 안 보인다.

```bat
@echo off
set PATH=C:\Users\<사용자>\AppData\Local\Programs\Python\Python313;%PATH%
powershell -ExecutionPolicy Bypass -NoProfile -File C:\workspace\memoir\backend-agent\run.ps1 > C:\ProgramData\memoa\api.log 2>&1
```

**출력 돌리기는 cmd 에서 한다. PowerShell 의 `*>` 로 하지 않는다.** PowerShell 5.1 은 안에서
돌린 프로그램의 stderr 를 오류로 감싼다. run.ps1 이 `$ErrorActionPreference = "Stop"` 이라
uvicorn 이 stderr 에 쓰는 첫 줄(`INFO: Started server process`)에서 서버째 멈춘다.

Postgres(`postgresql-x64-16`)는 이미 자동 시작이다. API 가 DB 보다 먼저 떠도
「DB 없이 간다」로 뜨고 **기록이 메모리에만 남는다** — 부팅 직후 첫 회차가 그럴 수
있으니, 재부팅 뒤에는 7단계의 `health` 를 한 번 보고 `ok` 만이 아니라 로그의
`DB 연결 · 스키마 확인 완료` 를 확인한다.

## 7단계 — 확인

휴대폰(집 와이파이가 아닌 **LTE**)에서 연다. 와이파이로 보면 공유기 안에서 도는
것과 구별이 안 된다.

```
https://naemalssami.com/api/health
```

```json
{
  "ok": true,
  "public": "https://naemalssami.com",
  "proxy": "cf",
  "client_ip": "39.7.xx.xx",      ← 내 휴대폰 주소여야 한다
  "origins": [],                   ← 비어 있는 것이 정상이다
  "docs": false                    ← 닫혔다
}
```

**`client_ip` 가 `127.0.0.1` 로 보이면 4단계가 안 먹은 것이다.** 이 상태로 두면
상한이 모두를 한 칸에 몰아 넣는다. 화면은 멀쩡해서 티가 안 난다.

`/docs` 를 직접 열어 보는 것으로는 확인이 안 된다. 닫으면 그 경로가 **사라지고**,
사라진 경로는 SPA 캐치올이 받아 평소 화면을 200 으로 돌려준다. 스키마가 나가지는
않지만 눈으로는 열린 것과 구별이 안 되므로, 위 `health` 의 `docs` 를 본다.

서버 기동 로그 첫 줄에도 같은 내용이 남는다.

```
api  자세 — 공개주소=https://naemalssami.com · CORS허용=(없음·동일출처)
     · docs=닫힘 · 프록시=cf · 워커=1
```

## 왜 이 세 옵션인가 (run.ps1)

```
--host 127.0.0.1                          이 컴퓨터 안에서만 듣는다
--proxy-headers --forwarded-allow-ips …   터널이 알려 주는 https 를 믿는다
--workers 1                               회차가 프로세스 메모리에 있다
```

**`--host 0.0.0.0` 으로 열지 않는다.** 포트가 밖으로 나가면 터널을 거치지 않는
길이 생기고, 그 길로 온 요청에는 `CF-Connecting-IP` 가 없다. 인터넷에서 오는 길은
터널 하나뿐이어야 `TRUST_PROXY=cf` 의 전제가 선다.

**`--workers 1` 은 취향이 아니다.** 회차 레지스트리가 프로세스 메모리에 있어서,
둘로 띄우면 300ms 폴링이 다른 워커로 가 회차를 못 찾는다. 어르신 화면에서 회차가
무작위로 사라진다. 서버가 실수로 여러 벌 뜨면 기동 로그에 빨간 줄이 남는다.

## 지금 알고 있는 한계

| | |
|---|---|
**재시작하면 진행 중인 회차가 끊긴다** | 배포·재부팅은 어르신이 안 쓰실 시간에 한다. 상태를 밖으로 빼야 고쳐진다 |
**PC 가 꺼지면 서비스도 멈춘다** | 지금 단계에선 감수한다. 서버로 옮겨도 코드는 그대로다 |
**로그인 준비 전에는 아무도 못 들어온다** | 신원은 구글 로그인이 준 `msid` 쿠키 하나다 (어르신은 인터뷰 링크 — 3-C1). `X-User-Id` 헤더 · `uid` 쿠키는 더 읽지 않는다. `GOOGLE_CLIENT_ID` 가 비면 로그인이 503 이라 자녀 화면을 쓸 수 없다. 실제 구글 계정 시험은 아직이다 |
**시험 도구는 DB 로 로그인한다** | `tools/dev_login.py` 가 로그인 줄을 DB 에 직접 쓴다 (12시간). DB 에 쓸 수 있는 사람만 할 수 있고 화면 · 링크로는 닿지 않는다. 이 PC 가 아닌 DB 에는 `--allow-remote` 없이 쓰지 않는다 |
**업로드 상한** | 서버 20MB(`MAX_UPLOAD_MB`), Cloudflare 무료 플랜 100MB. 서버 쪽이 먼저 걸린다 |

## 되돌리기

`.env` 에서 `PUBLIC_ORIGIN` 과 `TRUST_PROXY` 두 줄을 지우고 서버를 다시 띄우면
개발 상태로 돌아온다 — CORS 가 다시 열리고 `/docs` 도 돌아온다. 터널은
`Stop-Service cloudflared` 로 멈춘다.
