# 6-C1 — 기록 목록 정렬 현황 · 초안 (P6-SV-01)

작성 최충 · 받는 사람 김대원 (DW-12) · 강승우 (FE-11) · 안다애 (P6-QA-02) · 확인 태헌

**현행과 태헌 님 결정 (10-26) 을 적었다. 연대기 정렬은 아직 없다** — 사건 시점을 저장하는 칸이 없다.

## 1. 세 가지 「때」를 섞지 않는다

| 이름 | 뜻 | 지금 어디에 |
|---|---|---|
| 작성 시각 | 회차를 연 때 | `session.created_at` (UTC, 화면이 한국 시각으로 표시). 엽서를 다시 구워도 안 바뀐다 |
| 사건 시점 | 어르신이 말한 경험의 때 | **없다** (§2) |
| 서술 순서 | 자서전에서 놓는 차례 | 자서전 응답 안에만 · 저장 안 함 (7-C1) |

## 2. 지금 목록 · 지금 있는 시점 자료

`GET /api/sessions?limit=&has_postcard=`

| 항목 | 지금 |
|---|---|
| 정렬 | 작성 시각 최신순 하나 (`ORDER BY created_at DESC`) |
| 범위 | 로그인한 계정의 회차만 · `has_postcard=1` 이면 엽서 있는 회차만 |
| 크기 | `limit` 1~100 (기본 20). **다음 쪽 · 더 보기가 없다** — 100개 넘는 기록은 목록으로 끝까지 볼 수 없다 |
| 칸 | `session_id · title · has_postcard · postcard_title · created_at` 외 (`엽서목록제목_C1_R1.md` C1) |
| 단위 | 회차 하나 = 한 줄 |

사건 시점처럼 보이지만 **쓰면 안 되는 것**:

| 자료 | 무엇인가 | 왜 안 되나 |
|---|---|---|
| 인터뷰 판단의 `information_status.when` | `missing` / 확인됨 — 「때를 물어봤나」 표시 | 연도 값이 아니다 |
| `confirmed_facts` | 「16년 7월에 말랑이를 만났다」 같은 자유 문장 | 구조가 없다 — 여기서 연도를 뽑는 것이 대원 님 추출 몫이다 |
| `photo.exif_taken_at` | 사진을 찍거나 스캔한 때 | 기억의 연도가 아니다 (`photo.py` 머리) · 지시서도 사진으로 연도를 계산하지 말라고 한다 |
| `created_at` | 작성 시각 | 사건 시점이 아니다 |

## 3. 시점 — 확정 (태헌 10-26)

**지금 DB 칸이 아니다.** 아래는 시점 추출 (대원 님) 이 낼 값과 서버가 정렬에 쓸 규칙이다.
원문 표현은 그대로 두고, 정렬용 값은 정렬에만 쓴다.

### 3-1. 사건 하나의 시점 — 넷을 섞지 않는다

| 구분 (안: `kind`) | 언제 | 정렬 | 표시 |
|---|---|---|---|
| 직접 `direct` | 어르신이 연도를 말함 — 「1997년」 · 「1997년쯤」 · 「1980년대」 | 그 연도. **기간은 시작점** (1980년대 → 1980) | 원문 그대로 — 「1980년대」 를 「1980년」 으로 바꾸지 않는다 |
| 추정 `estimated` | 출생연도 + 나이 · 시점이 확정된 다른 사건으로 계산함 | 계산한 연도 (**만 나이**) | 「1975년경(추정)」 |
| 상대 `relative` | 「결혼 뒤」 처럼 기준 사건이 있고 **그 사건의 시점이 확인됨** | 기준 사건 **바로 뒤** (서버 안 — §3-3). 새 연도를 만들지 않는다 | 원문 그대로 — 「결혼 뒤」 |
| 시기 미상 `unknown` | 근거 없음 · 기준 사건의 시점도 모름 | 맨 아래 ② 구역 | 「때 모름」 |

- 직접 말한 연도가 계산값보다 먼저다 (「1974년」 이라고 하셨으면 1974).
- 만 나이로 계산한다. 세는나이 때문에 ±1 년 날 수 있지만 「추정」 으로 표시하므로 범위로 바꾸지 않는다.
- 근거가 모자라면 (「어릴 때」 · 「한참 뒤」) 연도를 만들지 않는다. 사진 속 모습 · 역사 상식으로 추정하지 않는다.

### 3-2. 출생연도 근거

| 근거 (안: `basis`) | 무엇 | 쓰는 법 |
|---|---|---|
| `said` | 어르신이 인터뷰에서 말한 것 | 인생 사실로 쓸 수 있다 |
| `profile` | 자녀가 화자를 등록할 때 적은 `elder.born_year` (003 에 이미 있는 칸) | **추정 계산에만.** 「어르신이 1955년생이라고 말했다」 처럼 쓰지 않는다 |

- 예: `born_year=1955` (`profile`) + 「스무 살쯤」 → 1975년경(추정).
- 발언과 등록정보가 다르면 **하나를 고르지 않고 충돌**로 둔다. 서버 안: 충돌인 사건은 계산값을 만들지 않고
  시기 미상 구역에 두되 상태는 `conflict` 로 따로 남긴다 — 풀리면 다시 계산한다 (태헌 님 확인 전 서버 안).

### 3-3. 회차 하나의 대표 시점

| 상태 | 뜻 | 정렬 |
|---|---|---|
| 정해짐 | 그 회차의 **중심 사건**의 시점. 배경으로 잠깐 말한 옛일로 회차를 옮기지 않는다. 가장 이른 것 · 처음 말한 것을 기계적으로 쓰지 않는다 | 그 시점 |
| 대표 시점 미정 | 시점 있는 사건은 여럿인데 중심을 못 고름 | 맨 아래 ① 구역 |
| 시기 미상 | 회차 사건에 배치할 근거가 없음 | 맨 아래 ② 구역 |

**① 대표 시점 미정과 ② 시기 미상은 다른 값이다.** 합치지 않는다. 화면은 ① → ② 순으로 따로 둔다.

서버 안 (흔들리지 않게):
- 상대 시점 사건은 기준 사건 바로 뒤에 붙인다. 같은 기준 뒤가 여럿이면 작성 시각 → `session_id` 순.
- 같은 시점끼리는 작성 시각 → `session_id`.

## 4. 결정 (태헌 10-26)

| 항목 | 결정 |
|---|---|
| 기본 방향 | 연대기순: 오래된 사건 → 최근 · 작성순: 최근 작성 → 오래된 작성. 둘은 다른 값이다 |
| 기간 | 시작점에 놓고 원문 그대로 보인다 |
| 시점 모름 | 근거가 있으면 추정 (표시), 없으면 맨 아래 「시기 미상」. 상대 표현은 보존 |
| 대표 시점 | 중심 사건. 못 고르면 「대표 시점 미정」 — 시기 미상과 다른 구역 |
| 출생연도 | `elder.born_year` 를 추정 근거로 쓸 수 있다. 발언과 구분 · 충돌은 충돌로 |
| 정렬하는 곳 | 서버 (화면은 받은 쪽만 본다 — 승우 님 동의) |
| 더 보기 · 다음 쪽 | 정렬 작업 때 커서와 함께. 그 전에는 화면 limit 100 |
| 정정 · 제외 뒤 시점 | 최신 유효 원문에서 다시 뽑는다 |
