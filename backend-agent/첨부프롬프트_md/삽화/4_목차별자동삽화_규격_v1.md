# 목차별 자동 삽화 — 입력 · 출력 규격 v1 (로컬 실험)

`app/session/memoir_illust_book.py` · `tools/memoir_illust_book.py` 가 받는 것과 내는 것이다. 서비스에 붙인 것이 아니다 —
서비스 쪽(DB · API · UI)에서 무엇을 넘기고 무엇을 받으면 되는지 적어 둔다. 2026-11-15.

> 쓰는 법 · 모의 실행 · 알려진 제한의 요약은 [docs/삽화_자동삽입_안내.md](../../docs/삽화_자동삽입_안내.md) 에 있다.
> 아래 절들은 날짜순 기록이다 — 「아직 실제 모델로 …」 같은 문장은 그 절을 쓴 때의 상태다.
> 공유본의 예시는 합성이다. 실제 원문으로 한 실험의 기록(응답 · 그림 · 원문)은 저장소에 없다.

## 동작

자서전 본문이 다 만들어진 뒤, **목차 항목마다** 본다.

- 그 항목 본문에 사진이 한 장이라도 있으면 → 삽화를 넣지 않는다. (장면이 좋은지는 따지지 않는다)
- 사진이 없는 것이 확인되면 → 그 항목을 대표하는 삽화 한 장을 만들어 그 본문에 넣는다.
- 사진이 있는지 모르면 → 만들지 않고 「자료 부족」 으로 남긴다.
- 사람이 장면을 고르거나 항목마다 승인하지 않는다. 책 전체에서 몇 장까지라는 한도가 없다.
- 이미 삽화가 든 항목은 다시 만들지 않는다.

## 입력 (illust-input-v1 + 사진 자리)

```jsonc
{
  "schema_version": "illust-input-v1",
  "memoir": {
    "memoir_id": "…", "title": "…",
    "chapters": [{                       // 하나가 목차 항목 하나다. 본문 안의 제목 · 문단을 따로 항목으로 치지 않는다
      "no": 1,                           // 책에서의 차례
      "chapter_key": "c01",              // 있으면 그대로 쓴다. 없으면 번호로만 가리킨다 (지어 붙이지 않는다)
      "title": "사과 궤짝",
      "paragraphs": [{"sentences": [{"text": "…", "turns": [1]}]}],
      "source_turns": [1],               // (선택) 문장마다 출처가 없을 때 항목 단위 출처
      "photos": [{"photo_id": "…", "after_paragraph": 0}],   // ★ 이 항목 본문에 놓인 사진. [] 는 「없다」 는 확인, 칸이 없으면 「모른다」
      "illustrations": []                // (선택) 이미 넣은 삽화 — 있으면 이 항목은 건너뛴다
    }]
  },
  "source": {"utterances": [{"turn": 1, "session_id": "…", "asked": "…", "elder": "…"}],
             "turn_map": [{"global_turn": 1, "session_id": "…", "turn": 1}]},
  "photos": [{"photo_id": "…", "session_id": "…", "turns": [], "clues": null,
              "chapter_keys": ["c01"], "chapter_nos": [1]}],    // ★ (선택) 항목에 놓인 사진을 여기서 가리켜도 된다
  "photo_placement": {"complete": true}  // ★ (선택) 「항목에 놓인 사진은 이 입력에 빠짐없이 적혀 있다」 — 그러면 가리킨 사진이 없는 항목은 「없음」 이다
}
```

★ 표시가 지금 서비스 자료에 없는 것이다. 사진이 어느 목차 항목에 놓이는지는 지금 DB 에 없다(`photo.session_id` 뿐이다).
같은 회차에 사진이 있다는 것만으로는 그 항목에 사진이 있다고 보지 않는다.

| 사진 상태 | 조건 | 처리 |
|---|---|---|
| `has_photo` | `chapters[].photos` 에 사진이 있다 · 또는 `photos[]` 의 사진이 `chapter_keys` · `chapter_nos` 로 이 항목을 가리킨다 | 삽화 없음 · 사진 유지 |
| `no_photo_confirmed` | `chapters[].photos` 가 `[]` · 또는 `photo_placement.complete` 가 true 인데 가리키는 사진이 없다 | 삽화 한 장 |
| `unknown` | 그 밖 | 만들지 않음 · 자료 부족 · 책은 complete 가 아니다 |

## 출력

`book_illustrated.json` (illust-book-v1) — 원고는 건드리지 않는다. 따로 만든 결과다.

```jsonc
{
  "schema_version": "illust-book-v1", "mock": false, "automatic": true, "input_ref": "…",
  "chapters": [{"no": 1, "chapter_key": "c01", "title": "…", "blocks": [
      {"type": "paragraph", "index": 0, "text": "…"},
      {"type": "photo", "photo_id": "…", "after_paragraph": 0},
      {"type": "illustration", "image": "items/c01/image/image.jpg", "after_paragraph": 0, "basis": "turns",
       "mode": "SCENE", "scene_title": "…", "ai_generated": true, "automatic": true, "mock": false}]}],
  "summary": {"status": "complete | incomplete", "incomplete_reasons": ["…"],
              "counts": {"toc_items": 10, "has_photo": 4, "no_photo_confirmed": 6, "photo_unknown": 0, "targets": 6,
                         "selected": 6, "images": 6, "inserted": 6, "failed": 0, "held": 0, "pending": 0}}
}
```

`items.json` — 목차별 처리 결과표. 항목마다:

| 칸 | 뜻 |
|---|---|
| `ident` · `no` · `title` | 기존 목차 식별자(없으면 번호)와 제목 |
| `photo_state` · `photo_basis` · `photos` | 사진 상태와 그렇게 본 까닭, 놓인 사진 수 |
| `target` · `target_reason` | 삽화 대상인가, 왜 |
| `status` | `kept_photo` · `inserted` · `failed` · `held` · `photo_unknown` · `already_illustrated` · `pending` |
| `mode` · `selection_source` · `scene_title` · `evidence` | 고른 그림(SCENE · SYMBOLIC)과 원문 근거(턴 · 인용). `derived_symbolic` 은 사람을 뺀 그림이다 |
| `auto_checks` | 자동 검사의 결과 — `automatic: true` · `human_confirmed: false` · 사람마다 관계 검사와 `human: not_reviewed` |
| `image_status` · `image_path` | `generated` · `mock_generated` · `failed` · `not_requested` |
| `insertion` | `after_paragraph` · `basis`(`turns` · `label_match` · `default_chapter_end`) · 까닭 |
| `failure` | 실패 · 보류의 까닭 |
| `automatic` · `user_selected` · `user_approved` | 늘 true · false · false — 자동 처리를 사람의 선택 · 승인으로 적지 않는다 |

`status` 가 `complete` 인 것은 대상 항목이 모두 삽입됐고 사진 상태를 모르는 항목이 없을 때뿐이다.

## 자동 검사 (사람 확인을 대신하는 것이 아니다)

- 사람을 그리는 장면은 사람마다 관계 칸과 근거 인용이 있고, 인용이 원문에 있고, 중심 행동에 이어져야 한다. 「○○랑 둘이」 꼴로 원문에
  나오는데 빠진 사람이 있으면 안 된다. 전언 · 정정 · 부정 · 불확실 표지가 풀리지 않은 채 남아 있으면 안 된다.
- 통과하지 못하면 사람과 행동을 빼고 그 후보의 사물 · 풍경만으로 그린다. 그것도 안 되면 그 항목은 실패다 — 지어내서 채우지 않는다.
- 민감한 말씀(죽음 · 사고 · 질병 · 전쟁 · 폭력의 낱말)이 든 항목은 보류다 — 그리지 않는다.
- 코드가 보는 것은 글자 일치와 표지 낱말까지다. 그 사람이 정말 그 행동을 했는지는 보지 못한다.

## 다시 돌리기

같은 결과 폴더로 다시 돌리면: 장면을 다시 묻지 않고, 그림을 다시 만들지 않고, 삽화가 두 번 들어가지 않는다.
그림은 있는데 넣기에 실패한 항목은 저장된 그림으로 넣기만 다시 한다. 실패 · 보류로 끝난 항목은 스스로 다시 시도하지 않는다.
본문이 바뀌어 그 문단을 찾지 못하면 다른 문단에 넣지 않고 항목의 끝에 둔다.

## 2026-11-15 보완 — 다시 돌리기 · 모드 · 기존 사진

**사진 칸에 더 받는 것** (`chapters[].photos[]` 와 `photos[]` 둘 다)

| 칸 | 뜻 |
|---|---|
| `path` | 사진 파일 경로 — 입력 파일이 있는 폴더를 기준으로 읽는다. 미리보기에 사진이 보인다. 읽지 못하면 오류로 남고 책은 complete 가 아니다 |
| `url` | 사진 주소 — 가 보지는 않는다(`url_not_checked`). 미리보기는 그 주소로 보인다 |
| `after_paragraph` | 그 문단(0부터) 뒤에 둔다. 없으면 항목 머리. **음수 · 범위 밖 · 수가 아니면 사진을 빼지 않고 항목 끝으로 옮기고** `position_basis: default_end_invalid_position` 과 까닭을 적는다 |

**결과에 더 나오는 것**

- 항목 `status` 에 `needs_reprocess` — 앞선 선정 결과와 그림이 기대던 것이 달라졌다. 그 그림을 넣지 않는다. `stale.reasons` 에 까닭:
  `book_changed` · `source_changed`(그 장면이 인용한 턴의 원문 · 회차 · 원래 턴 번호) · `memoir_paragraph_changed`(그 장면의 본문 문단) ·
  `memoir_chapter_changed` · `select_prompt_changed` · `style_changed` · `image_settings_changed` · `no_basis`.
  문단이 자리만 옮긴 것, 그 장면과 상관없는 곳이 바뀐 것은 까닭이 아니다. 스스로 다시 만들지 않는다 — `--reprocess-stale` 로 그 항목만 다시 처리하고 앞선 파일은 `items/_stale/` 에 남는다.
- 항목 `basis` — 그 결과가 기대던 것(책 · 턴의 원문 해시와 출처 · 문단 해시 · 지시문 · 양식 · 그림 설정).
- 사진 블록 `position_basis` · `position_note` · `error`, 항목 `photo_files[].file`(`readable` · `unreadable` · `url_not_checked` · `no_file_info`).
- `summary.counts` 에 `needs_reprocess` · `photos_in` · `photos_out` · `photos_relocated` · `photo_errors`.
  `photos_in != photos_out` 이거나 읽지 못한 사진이 있으면 complete 가 아니다.

**모의 실행과 실제 실행** — 결과 폴더는 한 가지 모드로만 쓴다. 다른 모드로 다시 쓰려 하면 부르기 전에 멈춘다.
그림마다 기록(`run.json`)의 모드 · 지시문 해시 · 파일 해시를 다시 보고, 맞지 않으면 그 항목은 실패다(다시 부르지 않는다).

## 실제 자료에서 어디까지 이어지는가 (2026-11-15 조사 · 운영 DB 에 붙지 않았다)

| 자료 | 지금 있는 것 | 목차 ↔ 사진 |
|---|---|---|
| 실험 원고 `eval/exp/…/book1` (52편) | 글로 된 이야기 59편 · 수필별 이야기 번호 · 문장별 출처(v3) | **이을 수 없다.** 인터뷰 회차도 사진 자료도 없는 자료다. 52개 항목 모두 `unknown` 그대로다 |
| 서비스 — 문체 자서전(소설체 · 수필체 · 문학체) | 장 하나 = 회차 하나(`run.session_ids` 차례) · `photo.session_id` · 회차의 `photo_id` · 엽서의 `photo_id` | 장 ↔ 회차 ↔ 그 회차의 사진까지는 **자료로 이어진다.** 그러나 그 사진이 책의 그 장 본문에 **놓이는지는 어디에도 없다** — 지금 자서전 화면은 장에 사진을 그리지 않는다 |
| 서비스 — 파이프라인 자서전(v7) | 문장마다 전역 턴 · `turn_map`(턴 → 회차) | 장이 여러 회차를 섞는다. 턴 → 회차 → 사진은 따라갈 수 있으나 어느 장에 놓을지는 정해져 있지 않다 |

그래서 서비스가 넘겨야 하는 최소 입력은:

1. 목차 항목마다 **그 항목 본문에 놓는 사진의 목록** (`chapters[].photos` — 없으면 빈 목록 `[]`).
   「회차에 올린 사진은 그 회차의 장에 놓는다」 를 제품 규칙으로 정하면 서비스가 `photo.session_id` 로 이 목록을 채울 수 있다 — 그 결정은 이 실험 밖이다.
2. 사진마다 파일을 읽을 길 (`path` 또는 `url`) 과, 놓을 자리가 정해져 있으면 `after_paragraph`.
3. 책 식별자 `memoir_id`, 항목 식별자(지금 응답에는 `no` 뿐이다), 자서전을 만들 때의 `utterances` · `turn_map`.

같은 회차에 사진이 있다는 것만으로는 이 실험이 `has_photo` 로 치지 않는다 — 위 1번처럼 서비스가 「놓았다」 고 적어 줘야 한다.

**(이 절을 쓴 2026-11-15 당시) 장면 선정 지시문 v4 와 이 자동 흐름은 아직 실제 모델로 검증하지 않았다.** 지금까지의 결과는 모두 손으로 쓴 모의 후보와 시험용 그림이다.

## 2026-11-16 보완 — 목차의 중심 내용을 담는 그림 고르기

실제 원문 한 항목(비공개)으로 한 실제 시험(2026-11-15)에서, 중심 사물을 이야기하는 항목에 그 사물 없이 배경 풍경만 그린 그림이 들어갔다. 고친 것:

- 장면 선정 지시문을 v5(`1_장면선정_v5_목차중심.md`)로 바꿨다. 응답에 `focus`(summary · core · background)가 더해진다.
  코드는 focus 의 인용을 원문과 대조해(부정된 것 · 원문에 없는 것은 받지 않는다) 참고로만 쓴다.
- 선택은 「처음 통과한 후보」 가 아니라 **후보 전체 비교**다. 모델 후보와 사람을 뺀 그림을 모두 검사하고, 통과한 것 가운데
  이 항목의 중심 요소를 가장 많이 담은 것을 고른다. 중심 요소 = 제목의 말 · 모델 focus(대조됨) · 본문에 나온 사물 · 행동 · 인물,
  그리고 제목이나 모델 focus 가 말한 장소(풍경이 중심인 항목). 본문에 나왔을 뿐인 장소는 배경이다.
- 형식 검사를 통과해도 **배경만 남은 후보는 고르지 않는다.** 그것밖에 없으면 그 항목은 `failed: no_representative_candidate` 다.
- 사람의 관계 근거는 그 사람을 가리키는 말과 그 행동의 말을 함께 담아야 한다(`person_relation_evidence_thin`).
- 그림 지시문에 「중심 소재」(화면 중심 · 크게)와 보조 배경을 적고, 다른 사물을 주요 소재로 넣지 말라고 적는다.
  사람을 그리지 않는 그림에서는 나이(○ 살)를 뺀다. 원문 사실(`composition.facts`)과 구도 선택(`composition.choices`)을 따로 남긴다.
- 결과의 선정 기록에 `focus` · `comparison`(후보마다 통과 여부 · 담은 중심 요소 · 선택/탈락 이유) · `choice_reason` 이 더해진다.

**(이 절을 쓴 때) v5 지시문과 새 선택 로직은 아직 실제 모델로 돌려 보지 않았다.**

## 2026-11-16 보완 2 — 모델의 focus 는 제안이다

v5 실제 시험(실제 원문 한 항목 · 비공개)에서 모델이 배경 장소를 `focus.core` 에 적자, 인용이 맞는다는 이유로 그것이 중심 요소가 됐다.
중심 사물을 담은 후보가 없었다면 배경 풍경이 대표 그림으로 골라졌을 것이다. 고친 것:

- 인용 일치(그 요소가 원문에 있다)와 중심 판정(그 요소가 이 항목의 중심이다)을 나눴다. 중심 · 배경은 **목차 자체의 근거**로 정한다.
- 모델의 `focus` 는 제안으로 남는다 — 요소마다 `model_proposed`(core · background) 와 `model_agrees` 로 기록하고, 혼자서는 등급을 바꾸지 않는다.
- 사물 · 행동 · 인물: 제목의 말이거나 본문에 나오면 중심.
- 장소(풍경이 주제): ① 제목의 말이거나 본문 문장의 절반 이상(두 문장 이상)에 나오고 ② 신호 {제목 · 본문 비율 · 모델 focus.core} 가 둘 이상이며
  ③ 더 강한 사물 · 행동 · 인물 중심이 없을 때만 중심이다(제목에 없는 장소면, 제목에 든 사물 · 행동 · 인물이 없고 본문 비율이 더 높아야 한다).
  ③의 비교에는 모델 focus 에 적힌(인용이 맞는) 사물 · 행동 · 인물도 넣는다 — 모델이 그것을 배경이라 적었어도. 화자(나)는 넣지 않는다.
- 요소마다 `why`(맞은 신호) · `rule`(판정 문장) · `body_share` 를, 결과에 `rivals`(비교한 사물 · 행동 · 인물)를 남긴다.

**이 판정도 낱말과 문장 비율로 본다.** 모델이 중심 사물을 후보와 focus 어디에도 적지 않고 제목도 그것을 말하지 않으면, 코드는 그 사물이 있다는 것을 모른다.

## 2026-11-16 보완 3 — 원문에 있다 ≠ 중심이다 (목차 유형별 검증)

합성 자료(eval/illust_types_C.json · 목차 11개)와 손으로 쓴 모의 후보 26개 사례로 검증했다. 기대값은 코드를 돌리기 전에 적었다.
변경 전에는 26개 가운데 9개만 기대와 맞았다 — 본문에 한 번 나온 사다리 · 달력 · 라디오 · 찻잔만 그린 후보, 이사 이야기에서
찻잔을 건넨 주인 할머니 장면이 대표로 뽑혔고, 두 문장짜리 「보리밭」 은 탈락했다. 변경 후 23개가 맞는다(나머지 3개는 아래 한계).

- **두 판단을 따로 적는다.** 요소마다 `source_check`(인용이 맞는가 · 본문에 나오는가 · 제목의 말인가)와 `centrality`(중심인가 · 근거 · 규칙),
  후보마다 `source_check`(형식 · 원문 대조 통과)와 `represents`(중심을 담는가). 형식 검사에서 막힌 후보도 「인용이 맞는 요소로 그렸다면
  중심을 담았는가」 를 적는다(`represent.evaluated_on: quoted_elements`).
- **사물 · 행동 · 인물의 중심(core)** = 목차 자체의 근거: ① 제목의 말이고 본문에도 나온다 ② 본문 문장의 절반 이상에 나온다
  ③ 두 문장 이상 · 본문 문장의 3분의 1 이상에 되풀이된다. 그런 요소가 이 항목에 하나도 없을 때만 「본문에 나오고 모델 focus.core 에 있다」 가 중심 근거가 된다.
  「이 항목에 알려진 요소」 는 후보 요소와 인용이 맞는 모델 focus 요소(어느 칸이든)다.
- **중심이 아닌 것**: `linked`(중심 요소와 같은 본문 문장에 나온다 — 딸린 것) · `supporting`(본문에 지나가는 말 · 주변 인물 · 주변 사물) ·
  `narrator`(화자 — 중심 판정 · 견줄 대상에 넣지 않는다). 대표가 되려면 중심(core)을 하나 이상 담아야 한다.
- **장소**: 「본문 비율」 신호(본문 문장의 절반 이상)에서 「두 문장 이상」 조건을 뺐다 — 짧은 글에서 한 번만 나왔다는 이유로 떨어지지 않게.
  대신 제목에 든 장소도 본문 비율이 더 높은 사물 · 행동 · 인물과 견준다. 신호 둘 이상 규칙은 그대로다.
- **비교 점수**: 제목의 말인 중심 수 · 중심 수 · 딸린 것 수 · 사람이 든 장면 · 본문 횟수 · 모델 후보 · 모델의 차례.
  제목 점수는 장소에는 본문도 그 장소를 다룰 때(절반 이상)만 준다 — 「서울로 이사하던 날」 의 서울처럼 제목의 장소가 가는 곳일 수 있다.
- **참여자 누락 꼴**: 「아버지랑 저랑 둘이서」 처럼 가운데 사람이 한 명 더 낀 꼴도 찾는다(가운데 사람도 따로 찾을 수 있게 지우지 않는다).

기준 변경의 영향 (변경 전 → 후):

| 경우 | 변경 전 | 변경 후 |
|---|---|---|
| 본문에 한 번 나온 사물 · 사람만 담은 후보 (사다리 · 달력 · 라디오 · 찻잔 · 구경한 할머니) | 대표로 선택 | 실패 — 빈칸 |
| 두 문장짜리 글의 제목 풍경 (보리밭 · 텃밭) | 모델 focus 가 없으면 배경 | 중심 |
| 두 문장짜리 8번 항목, 제목 「안방」 + 모델 focus · 라디오가 두 문장 모두에 나옴 | 안방 선택 | 실패 — 라디오가 더 강하다 (시험을 그렇게 고쳤다) |
| 세 문장 가운데 한 번 나온 사물(시험 자료의 졸업장 · 족두리) | 중심 | 모델 focus 가 더해져야 중심 (시험 자료에 focus 를 넣었다) |
| 「어머니와 김장하던 날」 의 김장독 (본문 한 번) | 선택 | 실패 — 한계로 남긴다 |
| 실제 원문 한 항목의 v4 · v5 응답 (비공개 — 공유본에는 이 시험이 없다) | 중심 사물 · 배경 장소 상징 그림 | 같음 |

**한계 (자동 판정이 따라가지 못하는 것 — 빈칸으로 남는 쪽이다)**
- 제목이 비유이고 모델 focus 가 없으면, 본문 전체가 풍경이어도 신호가 하나뿐이다.
- 같은 풍경을 문장마다 다른 말(바다 · 물결 · 수평선)로 부르면 장소마다 한 번씩이라 목차 근거가 모자란다.
- 제목의 말이 요소 이름의 일부로만 겹치면(김장 · 김장독) 잇지 못한다.
- 함께 한 사람이 본문에 한 번만 나오면 중심으로 보지 않는다(실제 원문 시험에서 함께 일한 가족 한 사람 — 관계 근거 인용도 얇았다).
- 짧은 글에서는 한 번 나온 것도 본문 절반이라 중심이 된다 — 두 문장짜리 글에는 「지나가는 말」 을 가릴 근거가 없다.
- 모델이 중심 사물을 후보와 focus 어디에도 적지 않으면, 코드는 그것이 있다는 것을 모른다(8번 항목에서 라디오를 아무도 적지 않으면 안방을 고른다).

## 2026-11-18 보완 5 — 기본 방식을 목차 주제 삽화(chapter_theme_v1)로

장면 방식은 한 장면의 인물 · 행동 · 인용을 원문과 정밀하게 맞추는 데 치우쳐, 그림을 만들 수 있는 장도 실패했다(사람 장면이 막히면
대신할 그림이 없음 · 짧은 인용 · 부정 표지 등). 제품 목적은 「장의 주제를 나타내는 따뜻한 회상 수채화 한 장」 이라 기본 방식을 바꿨다.

| | 장면 방식 `scene_v5` | 목차 주제 방식 `chapter_theme_v1` (기본) |
|---|---|---|
| 모델에 주는 것 | 장 목록 · 문장 · 원문 (v5) | 그 장의 본문 전체(문단 번호) · 그 장의 원문 말씀 ([v6](1_목차주제_v6.md)) |
| 모델이 내는 것 | 장면 후보 · 요소 · 인용 · 관계 | 주제 · 분위기 · 뒷받침 내용(문단) · 소재(+ 본문 낱말 anchor) · 구도 · 본문에 없는 것 |
| 코드 검사 | 인용 원문 대조 · 관계 · 함께 한 사람 누락 · 부정 · 전언 · 나이 표지 · 중심 요소 | 중심 소재가 본문(또는 제목)에 있고 제목 · 주제 · 뒷받침과 이어지는가(반복 횟수는 참고) · 그 낱말에 걸린 부정 문형으로만 나오는가 · 본문에 없는 관계 · 숫자 · 중심 소재가 남는가 |
| 그림 양식 | [v1](2_그림양식_v1.md) (옛 생활 모습 · 인물 칸 밖 금지) | [v2](2_그림양식_v2.md) (그 장의 때 · 일반화된 인물 허용) |
| 넣는 자리 | 그 장면의 문단 뒤 | 장의 첫머리 (30자 이상인 첫 문단 뒤) |

선정 결과(`selection`)는 두 방식이 같은 모양이다(`status` · `mode` · `scene` · `prompt` · `placement` · `auto_checks`). 주제 방식은
`policy: chapter_theme_v1` · `mode: THEME` · `theme`(계획과 검사 결과) · `verdict`(한 검사 · 하지 못한 검사)를 더 싣는다.
재사용 판단(`reuse_check`)은 지금 돌리는 방식의 지시문 해시와 견준다 — 다른 방식의 앞선 결과는 `select_prompt_changed` 로 「다시 처리 필요」 가 된다.

서비스(`memoir_illust_service`)는 장마다 처리한 방식을 기록하고, 앞선 방식으로 실패한 장만 운영자 도구(`tools/memoir_illust_reprocess.py`)로
다시 처리하도록 표시한다(앞선 기록은 `history` 에 남는다). 주제 방식은 아직 실제 모델로 부르지 않았다 — 모의 계획(AI 작성)으로만 확인했다.
