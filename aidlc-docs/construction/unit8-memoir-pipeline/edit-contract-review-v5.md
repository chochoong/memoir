### 1-1. 사실 원장의 메모가 사실상 문장 틀로 쓰입니다 (측정으로 확인)
- 편집 단계는 사실 원장 전체 66개를 `text`까지 받습니다(`edit_message` → `payload["facts"]`).
- 그런데 이 `text`는 화자의 말투를 거의 그대로 줄인 문장입니다.

  - 예: f3 "무릎이 아파서 더는 못 앉아 있겠어서 그만둠"
- 각 문장과 그 문장이 인용한 사실 메모의 글자 유사도(difflib)를 쟀습니다.

| | 근거 있는 문장 | 메모와 평균 유사도 | 0.7 이상 | 사실 하나만 단 문장 |
|---|---|---|---|---|
| Pro 초안 | 24 | 0.74 | 14 | 18 |
| Pro 편집 | 26 | **0.82** | **20** | **20** |

- 편집을 거치자 문장이 사실 메모 쪽으로 더 가까워졌습니다. 새로 생긴 구어체 세 곳도 모두 메모에 그대로 있던 말입니다.

## 2. 최소 구조 변경안 — 다섯 단계 역할은 그대로 둡니다

### 2-1. 출력 계약: 문단은 산문으로 쓰고, 근거는 따로 답니다
- 집필과 편집의 문단을 다음 모양으로 바꿉니다.

```json
{"text": "문단 전체 산문",
 "claims": [{"span": "본문 일부를 글자 그대로", "facts": ["f16"]},
            {"span": "...", "facts": ["f17", "f20"]}],
 "links":  [{"span": "새 사실이 없는 잇는 말", "kind": "editorial"}]}
```

- 모델은 문단을 한 덩어리 산문으로 씁니다. 문장 객체 단위로 복사하던 길이 사라집니다.
- 코드는 다음을 확인합니다.
  - 모든 `span`이 그 문단 `text`에 글자 그대로 들어 있는가
  - span끼리 겹치지 않는가
  - 코드가 나눈 문장마다 적어도 한 span(claims 또는 links)에 덮이는가
  - 덮이지 않은 서술이 있으면 `uncovered_text`(fix). 근거 없는 글이 문단 근거에 묻혀 지나가지 않게 합니다.
- 기존 검사는 근거 단위만 문장에서 span으로 바꿔 그대로 돌립니다.
  - fact_token · hearsay_lost · certainty_lost · opinion_as_fact
  - 아래 새 검사도 같은 방식으로 돌립니다.
- 문단 수준 근거로 묻히지 않게 하는 핵심: 검사 단위가 문단이 아니라 span입니다. span은 보통 한 문장 이하입니다.
- `locations`는 `ch-1/pN/sM`(코드가 나눈 문장)를 유지합니다. 검증 역할의 위치 계약은 바뀌지 않습니다.
- `edit_trace`는 문장을 코드가 나눈 뒤 지금처럼 비교하고, span의 facts를 근거로 씁니다.

### 2-2. 편집 입력: 초안을 문장 객체로 주지 않습니다
- 이유: 1-1과 1-3의 원인을 끊기 위해서입니다.
- 초안은 문단별 산문 + 문단별 사실 id 목록으로만 줍니다. 문장별 facts는 코드가 보관합니다.
- 사실 원장은 그대로 줍니다(사실 근거로 필요). 다만 다음 원칙을 계약 설명에 적습니다.
  - 원장 `text`는 사실 메모이지 문장이 아닙니다.
  - 서술에서는 원문 말투를 쓰지 않습니다. 원문 말투는 따옴표 인용으로만 씁니다.
  - 이 원칙은 아래 2-4의 `spoken_carryover` 검사로 확인합니다.
- `book_plan`은 문단별 facts 배열을 빼고 장의 center · experience · core만 줍니다. 핵심 사실 목록은 `plan_core`가 그대로 지킵니다.

### 2-3. 편집 출력에 구성 설계 칸을 두고, 진단과 결과를 묶습니다
- 원고 앞에 다음 칸을 둡니다(기존 diagnosis를 바꾸는 것이지 새 AI 역할이 아닙니다).

```json
"composition": [{"paragraph": 0, "role": "", "from": ["ch-1/p0", "ch-1/p6"],
                 "after_previous": "앞 문단과 무엇으로 이어지는가 (사실 id 또는 시간)",
                 "reorder": {"facts": ["f42"], "reason": ""} }]
```

- diagnosis 항목에는 `change`와 `result`를 붙입니다.
  - `change`: move · merge · split · rewrite · cut · link · fact_fix
  - `result`: 편집본 위치
- 코드는 claim마다 edit_trace와 대조합니다(`edit_claim_mismatch`, fix, kept 불가).
  - move: 옮김 표시
  - merge: 초안 문단 둘 이상에서 옴
  - rewrite: kept가 아님
  - cut: 해당 초안 문장이 빠짐
- 사람 검토 지적은 "diagnosis에 반영"이 아니라 `fact_fix` 항목으로만 받습니다. 구성 진단을 지적 목록이 대신하지 않게 하려는 것입니다.

### 2-4. 사실 보존 계약
- 핵심 사실 18개는 지금처럼 `core_findings`로 봅니다. 빠뜨리면 core_missing, 이유와 함께 빼면 core_omitted(info)입니다.
- 보조 사실은 이유 없이 빼도 됩니다. trace에 `dropped_support`(info)로만 남깁니다.
  - 편집 규칙 5의 "목차가 뺀 것도 다시 적습니다"를 없앱니다.
  - omitted 이유는 core · must_keep 사실에만 필수입니다.
- 인용한 ID와 실제 표현이 맞는지는 두 가지로 확인합니다.
  - (a) span의 글자 조각이 인용한 사실의 근거 턴 화자 발언과 겹치는 비율이 너무 낮으면 `claim_weak`(fix)입니다. `FACT_SOURCE_MIN_OVERLAP` 방식을 다시 씁니다.
  - (b) 사실 원장의 표지가 span에 남았는지 봅니다. 기존 heard · approx · view 검사에 다음을 더합니다.
    - **negation**: 근거 턴 화자 발언에 부정이 있고(`turn_marks.negation`), 그 부정이 사실 메모에 있는데(`_NEG_FACT`), span에 부정 표지가 없으면 `negation_lost`(fix, kept 불가)
    - doubt: 같은 방식
    - emotion: 같은 방식
- 한 사실에 두 주장이 든 경우(f16)는 분석 계약에서 "사실 하나 = 주장 하나"로 나누는 것이 맞습니다. 다만 시험용 분석 스냅샷은 보존해야 하므로, 이번에는 negation 검사로 막습니다.

### 2-6. 바꾸지 않는 것
- 다섯 단계 역할, 분석 · 목차 스냅샷, 핵심 사실 계약, 검증 역할의 위치 형식

## 3. 사실성 회귀 시험 (구현할 때 기준선으로 쓸 사례)
- 모두 기준선 파일의 실제 문장으로 만듭니다.
- 외부 호출은 하지 않고, conftest의 차단을 그대로 둡니다.

1. 턴 10 부정 표현
   - "엄마가 밭일 나가면 큰언니가 나를 업어 키웠다고 들었다." [f16] → `negation_lost`
   - "…업어 키웠다고 들었지만 나는 기억이 나지 않는다." → 통과
2. 구어체
   - 서술 속 "'기름 자주 쳐라' 그거 하나 적혀 있었다", "못 앉아 있겠어서", "싫었는데 말이다" → `spoken_carryover`
   - 따옴표 안 '기름 자주 쳐라'만 있는 문장 → 통과
3. 1977년으로 되돌아감
   - 1985~2010년 문단 뒤의 "1977년쯤 … 바다를 처음 보았다"가 reorder에 없음 → `time_reversal`(표지가 있어도)
   - reorder `{facts:[f42,f43], reason:…}`가 있음 → 통과
4. 안내문
   - "이 재봉틀에 얽힌 기억을 따라가다 보면 어린 시절로 거슬러 올라가게 된다." → `meta_text`
5. 중복
   - 이웃 두 문장의 "2010년에 … 그만두었다. 2010년에 가게 문을 닫으면서" → `repeat_phrase`
6. 근거 없는 인과
   - "말이 별로 없었던 큰언니는 손이 빨라서 동네 사람들의 옷을 다 고쳐 주곤 했다." [f18, f19, 턴 12] → `causal_unsupported`
   - "무릎이 아파서 … 2010년에 수선집을 그만두었다." [f2, f3, 턴 2 "아파서"] → 통과
7. 편집 설명과 실제 변경
   - 이번 편집의 진단 1("문단을 다시 구성") → change merge, result는 편집 위치
   - trace에 문단 합침이 하나뿐이면 걸리는 경우와 걸리지 않는 경우를 함께 시험
   - 결과 위치가 kept뿐인 rewrite 주장 → `edit_claim_mismatch`
8. 산문 + 근거 계약 자체
   - span이 본문에 없음 → 거부
   - span끼리 겹침 → 거부
   - 근거 없는 서술 문장 → `uncovered_text`
   - span이 뜻이 다른 사실을 인용함(근거 턴 겹침이 낮음) → `claim_weak`
   - 핵심 사실 18개 보존과 보조 사실 생략(info만)
9. 기준선 회귀
   - 기준선 Pro 편집 결과를 새 검사에 넣으면 위 1·2·4·6이 실제로 걸리는지 확인합니다. 지금 pass였던 것이 attention이 되어야 합니다.

## 4. 품질 평가 방법
- 숫자(문장 수 · 순서 유지 비율 · 사실/문장 · 메모 유사도)는 진단 신호로만 남기고, 성공 판정에 쓰지 않습니다.
- 판정은 사람이 원고만 읽고 합니다. 원문, 사실 원장, edit_trace는 보지 않습니다.
- 질문 다섯 가지:
  1. 한 이야기로 읽히는가? 다 읽은 뒤 한 문장으로 줄여 말할 수 있는가?
  2. 첫 문단(지금의 재봉틀 소리)과 끝 문단이 서로 받는가?
  3. 문단마다 맡은 일이 있고, 다음 문단으로 넘어가는 까닭이 글 안에 있는가?
  4. 인터뷰 요약처럼 읽히는 곳(한 문장에 한 사실, 원문 순서, 구어)이 어디인가?
  5. 그대로 책에 실을 수 있는가? 고쳐야 할 문장 수는 몇인가?
- 비교 방식: 기준선 Pro 편집본과 새 계약의 결과를 A/B로 이름을 가리고 읽습니다.
- 사실 충실도는 사람 판정과 따로 봅니다. 코드 판정, 검증 역할, 문장별 원문 대조를 거쳐 판정합니다. 문학적 완성도가 높아져도 사실 판정이 떨어지면 실패입니다.
