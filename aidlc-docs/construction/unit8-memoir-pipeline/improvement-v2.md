## 1. 원인 분석
| 증상 | 원인 (지시문 · 계약 · 코드) |
|---|---|
| 사건 1개 = 장 1개 | 목차 v1 이 "1~5장, 자료가 적으면 적게"만 말하고 한 장 회상록 · 묶음 기준이 없다. 예시가 사건 하나 = 장 하나 모양. 묶은 이유를 요구하지 않아 기계적 분할이 가장 쉬운 답이 된다 |
| 원문 다시 적기 | 장 집필 v1 이 "원문에 있는 세부만", "supported 는 그 문장의 모든 주장을 뒷받침하는 턴" 을 강조하고 재구성 지시는 없다. 가장 안전한 답이 원문 문장을 그대로 옮기는 것. 장마다 받은 원문이 2턴뿐 |
| 장 사이 연결 부족 | 장 집필은 장 하나만 보고 "다른 장 내용을 쓰지 말라" 는 말만 받는다. 목차의 transition 을 쓰라는 지시가 없다. 편집 v1 은 전환을 "쓸 수 있다" 로만 말한다 |
| 편집이 교정에 머묾 | 편집 v1 이 **"장을 더하거나 빼거나 합치지 마세요"** 라고 했고, 코드(E-1)도 장 키가 목차와 같아야 통과시켰다 — 과도한 분할을 고칠 수단 자체가 없었다. 구성을 봤다는 기록도 요구하지 않았다 |
| 약하거나 모순된 주제 | 분석 v1 에 주제의 강도 기준이 없고, neutral 과 theme 의 관계가 정해져 있지 않아 "중립인데 주제는 가족" 이 나왔다. "가족" 처럼 넓은 말을 근거 있는 주제로 받았다 |
| 검증이 구성 문제를 못 잡음 | 검증 v1 의 code 가 모두 사실 오류다. 나열 · 분할 · 전환을 적을 분류가 없고, 목차 계획도 받지 않아 장 역할 중복을 판단할 수 없었다 |
| (발견) 제외 위험 | 장 입력의 "같은 회차 앞뒤 1턴" 규칙이 seed B 의 꽃집 장에 **빼 달라고 한 턴(4)과 그 요청(5)을 끌어온다.** 제외는 모델이 원문 글을 읽고 지키는 것뿐이었다 |
| (발견) 사건 누락 | 분석이 발언을 사건에서 빠뜨려도, 목차가 사건을 버려도(v1 은 경고뿐) 그대로 진행됐다 |

## 2. 변경 (지시문 v2 · 계약 · 코드)
### 지시문 (`첨부프롬프트_md/파이프라인/*_v2.md`)
- **분석**: 주제 `strength`(clear · partial · weak), 넓은 말은 weak, clear 가 없으면 `neutral=true` · `theme=""`. 모든 발언 턴을 사건 · `not_in_events` · `exclusions` 중 한 곳에. 제외 요청은 `exclusions{turns, requested_in, scope}`
- **목차**: 사건 = 장 금지, 10턴 안팎이면 한 장 회상록이 기본, 장마다 `grouping_reason`(원문에서 확인되는 공통점 · 편집 목적, 없으면 중립 묶음이라고 밝힘), `book.structure_reason`, 모든 사건은 장이나 `left_out` 에. 제외 턴 사용 금지. 원문에 없는 장면을 purpose 에 쓰지 않음
- **장 집필**: 원문 순서대로 옮기기 금지, 문장 · 문단 재구성, 여는 · 잇는 · 닫는 editorial 문장, 핵심 어휘 · 직접 감정 표현 유지, 새 사실 금지는 그대로
- **편집**: 먼저 구성(분할 · 도입/마무리 · 연결 · 중복 · 나열)을 보고 `structure_notes` 에 적는다. **장을 합칠 수 있다**(`from_chapters`). 나누기 · 순서 바꾸기 · 새 장은 금지. 자료가 적으면 짧게
- **검증**: issue 마다 `category` — fact(기존 7) / composition(summary_listing · over_split · role_overlap · weak_transition · theme_contradiction · style_mismatch). 자료 한계에는 `accept_limit` 로 창작 요구 금지. 목차 계획(`plan`)을 받는다

### 계약 · 코드 (`app/session/memoir_pipeline.py`)
| 무엇 | 검사 |
|---|---|

| 목차 `book.structure_reason` · `grouping_reason` · `left_out` | 모양 · **모든 사건이 장 또는 left_out 에**(아니면 reference) · 제외 턴 사용 reference · 사건마다 장 하나면 경고 |

## 3. 평가 기준 (기준선과 비교)
지표는 판정이 아니라 비교 기준이다. 품질 승인은 사람 검수(`human_review`)로만 한다.
**지표를 맞추려고 바꾸지 않는다** (사용자 지시 2026-10-26): 원문 그대로 비율 · 편집 변경 수 · 연결 문장 수는 기록만 한다. 원문이 이미 자연스러우면 그대로 둬도 되고, 근거 없는 연결 문장을 개수 때문에 넣지 않는다. 지시문 v2 도 "필요할 때만" 으로 고쳤다.

### 품질 평가 — 사람이 이 순서로 본다 (R1 요약의 사람 검수 칸)
1. 중심 주제가 실제 발언으로 뒷받침되는가 (뒷받침이 약하면 중립으로 둔 것이 맞다)
2. 장 구성이 필요한 만큼만 나뉘었는가
3. 회차 요약을 단순 나열하지 않았는가
4. 전체 흐름이 자연스러운가
5. 원문 사실과 직접 표현된 감정이 보존됐는가
6. 제외된 정보가 재등장하지 않는가

### 공통 — 반드시 (하나라도 어기면 그 판은 실패)
- F1 사실: 사람 대조로 unsupported · 시점 · 인물 오류 0, 직접 말한 감정 유지
- F2 근거: 코드 검사 통과(전역 턴 · 범위 · 제외 턴 미사용)
- F3 빠짐: 분석이 모든 턴을 덮고, 목차가 모든 사건을 배치하거나 이유를 남김
- F4 상태: `human_review=not_run`, 실패 시 partial/failed 로 멈춤

### 자료별 기대
| 자료 | 묻는 것 | 기대 (기준선 대비) |
|---|---|---|

### 제외 처리 — 보장하는 것과 못 하는 것 (2026-10-26 보완)
seed B 턴 4 는 한 문장에 **꽃집 준비(남길 수 있음)** 와 **누나에게 빌린 돈 · 금액(뺄 것)** 이 함께 있다. 턴 5 는 요청 자체다. merge 출력의 메모(`facts_found` 턴 4, `confirmed_facts`)에도 "누나에게 삼백만 원 빌림" 이 그대로 있다.

| 구분 | 코드가 보장 (시험으로 고정) | 모델 · 사람에게 남는 것 |
|---|---|---|
| 턴째 제외 (`mode=whole`) | 그 턴과 요청 턴이 목차 · 장 · 편집 입력에 없음 · 사건 근거 · 목차 focus/context · 편집본 근거에 쓰이면 실패 | 분석이 그 요청을 찾아내는 것 |
| 부분 제외 (`mode=partial`) | 턴은 남고 번호 · 출처 대응 그대로 · 요청 턴은 막음 · 그 턴의 메모(`facts_found`)와 `confirmed_facts` 는 목차 · 장 · 편집에 안 감 · 각 단계에 scope 알림(구체 값 없이) | **그 턴 원문 안의 뺄 부분을 실제로 빼는 것** · 다시 나왔는지 찾는 것(검증 `exclusion_violation`, 사람 검수 6번) |
| 분석 · 검증 | 원자료 전부를 받는다 (찾고 대조해야 하므로) | — |
| 남은 한계 | 원문을 고치거나 지우지 않는다 · DB 에 반영하지 않는다 · 서비스의 수정 · 제외 기능(단위 8d)이 아니다 · 분석이 요청을 못 찾으면 아무것도 막지 못한다 · partial 의 문장 안 생략을 코드로 확인할 수 없다 | |

**B 에 대한 한계 — 주장하지 않을 것**: seed B 의 제외 요청은 말씀 속 글(턴 5)일 뿐 입력에서 실제로 빠지지 않는다. v2 는 모델이 그 글을 읽고 `exclusions` 로 짚은 뒤에야 코드가 막는다. 따라서 B 결과가 좋아도 **"제외 기능이 검증됐다"고 하지 않는다** — 서비스의 제외 기능(단위 8d)이 입력에서 빼는 것과는 다른 시험이다.

## 5. 더 풍부한 합성 자료 — 제안 (만들지 않음)
A · B 는 회차마다 1~3턴이라 주제 · 묶음 · 반대 근거를 시험하기 어렵다. 제안하는 seed C(가칭):
- 한 화자 5회차 · 회차마다 4~6턴 (전체 25턴 안팎)
- 같은 사건을 두 회차에 나눠 보충 (MEM-T01), 장소 · 연도만 같은 별개 사건 하나
- 시기 불명 · "그때" 같은 모호한 시점 (MEM-T02)
- 주제를 지지하는 경험 셋과 반대 · 복합 감정 하나 (MEM-T03), 자녀의 희망을 말한 발언 하나
- 정정 하나 · 중요한 마지막 발언 하나 (MEM-T04)

걸림돌: `tools/seed_sessions.py` 의 `check_seed` 가 set_id 를 A · B 로만 받는다(`SET_IDS`, 제목 접두어). C 를 쓰려면 그 팀 도구의 `SET_IDS` 를 넓히거나 파이프라인 전용 검사를 따로 둬야 한다 — 팀(seed 담당)과 정할 일이라 이번에 바꾸지 않았다.
