## 1. 분석 · 목차 — 원인

### 1-1. 1977 · 2003 부산 방문이 사건 하나(e9)로 합쳐진 이유
| 원인 | 근거 | 종류 |
|---|---|---|
| **"사건" 의 단위가 정의되지 않았다** | 분석 v3 규칙 4 "원문에서 **실제로 이어지는 문맥**이 있을 때만 하나로 묶으세요" — 28(c4) "두 번 갔어요. 처음은 …" 과 29 "두 번째는요?" → "2003년이요" 는 **대화가 이어진 것**이지 사건이 이어진 것이 아니다. 지시문이 "이어진 대화" 와 "같은 사건" 을 가르지 않는다 | 지시문 |
| **사건 계약이 여러 시점을 받아 준다** | `time` 이 문자열 하나라 e9 는 `"77년쯤, 2003년"`, e12 는 `"2004년 봄, 2015년"`, e7 은 `"83년쯤, 86년, 1985년 봄"` 을 담았다. 코드 검사(`check_analysis`)는 time 모양만 본다 | 계약 · 코드 |
| **화자의 말이 "부산 방문" 을 한 주제로 묶어 꺼냈다** | 28 이 "두 번 갔어요" 로 시작 — 주제(부산)와 사건(방문 하나하나)을 모델이 같은 층으로 받았다. 이어 주는 끈(부산 · 큰언니)을 담을 자리가 계약에 없어서 사건으로 합쳤다 | 계약 |

### 1-2. 큰언니(2004) · 남편(2015) 사망이 사건 하나(e12)로 묶인 이유
| 원인 | 근거 | 종류 |
|---|---|---|
| **전역 턴이 회차 경계를 넘어 붙어 있다** | 33(c4 끝, 남편) · 34(c5 처음, 큰언니)가 바로 이웃 번호다. 분석은 원문 전체를 turn 순서로 받으니 "죽음" 이라는 주제 · 번호 근접으로 묶었다 | 데이터 모양 |
| 같은 원인 1-1 (사건 단위 · 다중 시점 허용) | e12 time `"2004년 봄, 2015년"`, people 에 큰언니 · 남편 · 남동생이 함께 | 지시문 · 계약 |
| 34 원문 수정(주어 보강) 뒤에도 생김 | 34 는 이제 "큰언니요? 병원 다녀온 …" 이라 주어가 분명하다 — 주어 문제가 아니라 **사건을 주제 단위로 묶는 경향** 문제 | — |

> 사건 식별과 편집상 묶음은 다른 층이다. **분석은 일어난 일 하나 = 사건 하나**(한 시점 · 한 장소 · 한 행위자 묶음)로 쪼개고, 같은 사람 · 소재 · 장소로 이어지는 관계는 **별도의 끈(thread)** 으로 적어야 한다. 서로 다른 사건을 한 장에 두는 것은 목차의 일이다.

## 3. 검증 — 세 갈래로 나누고, 모델이 놓쳐도 자동 합격이 되지 않게

v3 검증은 코드가 이미 찾은 합니다체 5문장(plan.checks)을 받고도 지적 0건 · pass 를 냈다. 겹친 턴 · 인터뷰 흔적 · 나열도 적지 않았다. **문제는 모델 판정 하나가 최종 판정 자리에 앉아 있다는 것**이다.

| 갈래 | 무엇 | 누가 | 지금 | 바꿀 것 |
|---|---|---|---|---|
| **A. 코드로 판별** | 해요체가 아닌 문장 끝 · 인터뷰 답 조각 · 말을 멈춘 표현 · 두 장에 겹친 근거 턴 · 목차 메모 혼입 · 없는 턴 · 제외 턴 · 한 사건 여러 시점 · 장 수/사건 수 | 코드 (`code_findings`) | 일부는 실패, 일부는 경고만 하고 버림 | 단계마다 모아 **편집 입력으로 넘기고**, 편집 뒤에도 남으면 **code_gate=blocked** |
| **B. 의미 판단** | 원문에 없는 주장 · 정정 전 내용 · 들은 말을 기억으로 · 인물 혼동 · 제외 내용 재등장 · 중요 내용 누락 | 검증 모델 | 사실 · 구성 code 를 다 맡김 | 검증 모델은 **B 에 집중**. A 는 코드가 이미 판정하므로 모델이 놓쳐도 결과가 바뀌지 않는다 |
| **C. 사람의 판단** | 주제가 글에 살아 있는가 · 흐름 · 문학적 완성도 · 자서전으로 읽히는가 | 사람 (`human_review`, 평가 기준 9항목) | 같음 | 결과에 "사람 검수 전" 을 상태로 못 박는다 |

**합격 판정 구조 (계약 변경, 호출 수 그대로)**
```
code_gate        pass | blocked        (A — 코드, 편집 뒤 최종 본문 기준)
model_verdict    pass | revise | ask_user | null   (B — 검증 모델)
human_review     not_run | passed | failed          (C — 사람)
overall          blocked_by_code | model_flagged | awaiting_human | approved
```
- `approved` 는 **사람만** 만든다 (human_review=passed). 코드는 쓰지 않는다
- code_gate=blocked 이면 model_verdict 가 pass 여도 overall=blocked_by_code
- pipeline_complete 는 지금처럼 "다섯 단계가 돌았다" 는 실행 사실로만 남긴다
- 여섯 번째 호출 · 감독 에이전트 없음 — 코드 검사는 호출이 아니다

## 4. 프롬프트로 될 것 / 코드 · 전달 정보 · 계약을 바꿔야 할 것

| 문제 | 프롬프트만 | 코드 · 전달 · 계약 필요 | 이유 |
|---|---|---|---|
| 부산 두 방문 · 두 죽음 합침 | 일부 (사건 = 일어난 일 하나, "두 번 갔어요" 는 사건 둘) | **예** — 사건과 끈(thread)을 계약에서 분리, 한 사건에 서로 다른 연도가 둘 이상이면 코드 경고 | 지시문만으로는 v1~v3 내내 같은 경향이 남았다 |
| 주제를 목차가 안 씀 | 일부 (clear 면 주제로 처음 · 끝을 정한다, "시간 순서의 짧은 회상" 예시 제거) | **예** — 분석에 threads, 목차에 `book.opening_turns · closing_turns` · 장마다 `role` 한 문장 | 이어 줄 재료가 계약에 없으면 목차가 만들 수 없다 |
| 모음 장 | 일부 | 예 — 장의 사건 · 인물 · 시기 폭이 크고 공통 thread 가 없으면 경고 → 편집 입력 | |
| 두 장에 같은 내용 | 아니요 | **예 (코드만)** — 앞뒤 1턴을 붙일 때 다른 장의 focus · 사건 턴은 빼기, 편집본에서 같은 턴을 두 장이 근거로 쓰면 code_finding | 원인이 코드다 |
| 원문 나열 | 일부 (v2 완화 문구 정리, 재구성 지시) | **예** — 장 입력을 **사건 묶음(event packet)** 으로 재배열(턴 번호 · 글은 그대로), 연속된 한 턴 문장이 길게 이어지면 code_finding(참고) | 인터뷰 순서로 주면 인터뷰 순서로 쓴다 |
| 인터뷰 흔적 | 예 (답 조각은 질문과 이어 읽어 독립 문장으로, 말을 멈춘 표현은 본문에 넣지 않음) | 예 — 패턴 검출(`아니요,` · `가끔요.` · `그만할게요` …) → 편집 입력 · code_gate | 검출은 코드가 확실하다 |
| 합니다체 | 예 | 예 — 이미 검출함. **편집에 넘기고** 남으면 code_gate | 지금은 경고를 버린다 |
| 편집 무변경 | 일부 (완화 문구 정리) | **예** — 편집 입력에 `checks`(할 일 목록), 편집 출력에 항목별 처리(`resolved` · `kept` + 이유), 코드가 다시 검사 | 할 일을 안 주고 하라고 할 수 없다 |
| 검증 pass 남발 | 아니요 | **예** — code_gate 와 overall 분리(3절) | 모델 판정을 최종 판정에서 내린다 |

| 언니가 준 그 재봉틀은 아직 못 버렸어요. 돌리면 드르륵 소리가 나는데, 그 소리가 나면 언니 생각이 나요. 공장 다닐 때는 그 소리가 그렇게 싫었는데요. | 38 |
| 애들한테 줄지는 아직 모르겠어요. 걔들이 쓸 일이 있겠어요. | 39 |

- 세 회차(c1 · c4 · c5)의 9턴이 두 문단 하나의 흐름이 됐다. 문장마다 근거 턴이 있고, 여러 턴을 묶은 문장이 넷이다
- 새 사건 · 심리 · 인과 · 대사 · 감정 없음. "언니다웠어요" · "언니 생각이 나요" · "싫었는데" 는 화자의 말 그대로
- 주의 두 곳: "수선집을 하는 동안" 은 3 의 일상을 가게 기간으로 읽은 편집이다(3 은 가게 일과를 묻는 질문의 답). "그걸로 줄여요" 는 36 의 답을 질문("지금도 그 재봉틀을 쓰세요?")과 이어 읽은 것이다 — **답이 질문에 내용으로 답한 경우에만** 허용하고, "네" 만 한 경우는 사실로 쓰지 않는다(공통 지침 3). 이 경계를 지시문에 적어야 한다
- 이 예시는 장 하나 안에서도 가능하다 — 재봉틀 thread 를 목차가 한 장(또는 책의 끝)으로 모아 줄 때 나온다

## 6. 최소 변경안 (v4 — 승인 뒤 착수, 지금은 손대지 않음)

호출 수는 그대로(장 수 + 4). 여섯 번째 호출 · 감독 에이전트 없음. 서버 · DB 무수정.

| 순서 | 변경 | 대상 | 규모 |
|---|---|---|---|
| 1 | **장 입력의 앞뒤 1턴에서 다른 장의 focus · 사건 턴 빼기** | `chapter_source` | 작음 · 중복 원인 제거 |
| 2 | **장 입력을 사건 묶음으로** — `source.utterances` 는 그대로 두고 `event_packets: [{event_key, turns}]` 를 사건 순서로 추가(턴 번호 · 글 무변경) | `chapter_message` | 작음 |
| 3 | **code_findings 를 모아 편집에 넘기기** — 해요체 아님 · 답 조각 · 말 멈춤 표현 · 두 장에 겹친 턴 · 메모 혼입 · 한 턴 문장 연속(참고) | 새 함수 + `edit_message` | 중간 |
| 4 | **결과 계약에 code_gate · overall** — 편집본 최종 검사에서 blocking finding 이 남으면 blocked, approved 는 사람만 | `_result` · R1 요약 | 중간 |
| 5 | **분석 계약: 사건 = 일어난 일 하나 · threads 분리** — `threads: [{name, kind: person/object/place, events, turns}]`. 한 사건 time 에 서로 다른 연도 둘 이상이면 경고 | 분석 지시문 · `check_analysis` | 중간 |
| 6 | **목차 계약: 장 role 한 문장 · book.opening/closing turns · thread 사용** — "시간 순서의 짧은 회상" 예시 제거, clear 주제면 처음 · 끝에 쓰기, 모음 장 경고 | 목차 지시문 · `check_outline` | 중간 |
| 7 | **편집 계약: checks 처리 결과** — `checks_resolution: [{finding, action: resolved/kept, reason}]`, 코드가 편집본을 다시 검사해 대조 | 편집 지시문 · `check_final` | 중간 |
| 8 | 지시문 정리 — v2 의 "자연스러우면 그대로" · "바꾼 곳 개수 목표 아님" 을 "code_findings 와 나열은 고친다, 나머지는 필요할 때만" 으로. 답 조각 · 말 멈춤 표현 규칙. 검증은 의미(B)에 집중 | 지시문 5개 | 중간 |

권장 착수 범위: **1 · 2 · 3 · 4 를 먼저**(코드 · 전달 · 계약, 모델 지시와 무관하게 확실히 효과가 있는 것), 그다음 5 · 6 · 7 · 8 을 v4 지시문과 함께. 1~4 만으로도 "중복 · 합니다체 · 인터뷰 흔적을 남긴 채 pass" 는 구조적으로 막힌다.
