# 남은 결정 사항

이 자료가 대신 정하지 않은 것들이다. 담당자별로 나눴다.

## 2판에서 풀린 것

| | 결과 |
|---|---|
| 소설체 최소 수정 v1 의 승인 | **다애님 승인 완료 — 소설체 최소 수정 v1.** 사용자가 전달한 승인이다(승인 날짜와 증빙 파일은 확인되지 않아 적지 않았다) |
| 분석 지시문 | 예시의 인물 이름 하나를 가상 식별자로 바꾼 **안전 사본**을 넣었다. 원본은 올리지 않는다 → `analysis_prompt_safety.md` |

올리기 전에 사람이 확인해야 하는 것은 남아 있지 않다. 아래는 모두 **올린 뒤 연동을 시작할 때** 정할 것들이다.

## 충님(백엔드) — 연동을 시작하기 전에

| # | 결정할 것 | 지금 상태 | 참고 |
|---|---|---|---|
| 1 | **문체 값의 정합** — 새 값 `essay` · `literary` · `novel` 을 `style.py` 에 어떻게 넣을 것인가. 기본값 `spoken`(구어체)을 남길 것인가. `style.py` 는 엽서와 같이 쓰는데 자서전에만 열 것인가 | `SUPPORTED = ("spoken",)`. `novel` 은 머리말에 예약된 이름과 같다 | `compatibility_report.md` §4 |
| 2 | **문체별 모델** — 서비스의 기본 모델은 Gemini 3.5 Flash Lite이고, 세 문체는 그 모델로 돌려 본 적이 없다. 문학체와 소설체는 Claude Sonnet 5.5에서만 검증됐다. Anthropic · OpenAI 호출 경로를 새로 둘 것인가 | 검증된 조합은 `style_manifest.json` | `backend_handoff.md` §7 |
| 3 | **수필체 · 문학체의 분석 단계** — ① 안전 사본의 분석 지시문으로 분석 호출을 새로 둔다 ② 서비스의 v7 분석을 넓혀 같은 스키마를 채운다. 어느 쪽이든 분석 호출과 묶음 조립을 서비스 코드로 구현해야 한다. 분석의 모델과 상한도 정해야 한다(실험은 Fable 5.1 · 출력 상한 32,000) | 지시문 · 스키마 · 묶음 조립 참조 구현이 모두 들어 있다. ①은 안전 사본으로 돌려 본 적이 없고, ②는 검증된 적이 없다 | `backend_handoff.md` §3 |
| 4 | **응답 규격** — 문장 · 턴 단위 응답을 문단 단위로 넓힐 것인가, 문체 출력을 문장 단위로 바꿔 넣을 것인가. `body` 를 어떻게 만들 것인가 | 지금 `body` 는 문장마다 줄을 바꿔 합친다 — 문학체 · 소설체의 형식이 깨진다 | `backend_handoff.md` §5 |
| 5 | **상한** — 장 집필 6,000 토큰 · 90초, 전체 600초로는 돌지 않는다 | 실험값: 한 장 71~329초 · 출력 8천~4만 8천 토큰(추론 포함) | `compatibility_report.md` §5 |
| 6 | **재시도 · 실패 처리** — 잘림 · 파싱 실패 · 검증 실패 때 무엇을 다시 부를 것인가 | 실험은 재시도 0 · 대체 모델 없음 | `backend_handoff.md` §8 |
| 7 | **`essay_id` 가 예시값으로 올 때** — 형식 오류로 실패시킬 것인가, 요청한 장 id 로 덮고 기록할 것인가 | 프롬프트는 고치지 않는다 | `backend_handoff.md` §8 |
| 8 | **확정 제목의 공급** — 수필체는 확정 제목이 입력에 있어야 한다. 분석은 후보 6개만 낸다. 제목을 어디서 정하고, 정해지지 않았을 때 어떻게 할 것인가 | 실험의 제목 선정 로직은 이번 자료에 없다 | `backend_handoff.md` §6 |
| 9 | **소설체의 사실 확인** — 출력에 사실 표시 · 각색 기록이 없다. 창작된 대사를 사용자에게 어떻게 알릴 것인가, 원문과의 사후 대조를 둘 것인가 | 기계 검증 수단이 없다 | `backend_handoff.md` §6 |
| 10 | **각색 기록을 어디에 둘 것인가** — 응답에 실을 것인가, 저장만 할 것인가 | 지금 응답에 자리가 없다 | `compatibility_report.md` §3 |
| 11 | **프롬프트를 둘 위치와 읽는 방식** — 제안 위치는 `backend-agent/첨부프롬프트_md/문체/`(분석 지시문은 그 아래 `analysis/`). 기존 로더를 쓰지 않는 읽기 경로 | 로더는 공통 지침을 붙이고 울타리 줄을 지운다 | `backend_handoff.md` §2 · `analysis_prompt_safety.md` §7 |
| 12 | **줄바꿈 변환 방지** — 문체 폴더의 `.gitattributes` 를 둘 것인가, 저장소 루트의 것에 합칠 것인가 | 폴더 안에 넣어 두었다. 없으면 Windows 에서 받을 때 해시가 달라진다(임시 저장소에서 확인) | `validation_report.md` §6 |
| 13 | **민감한 기억의 판정** — 묶음의 `sensitive` 를 무엇으로 정할 것인가 | 실험은 낱말 규칙과 사람이 고른 목록 | `input_output_contract.md` §2 |
| 14 | **기존 편집 · 검증 단계(4 · 5단계)를 문체 원고에 돌릴 것인가** | 돌려 본 적이 없다 | `compatibility_report.md` §6 |

## 태헌 · 팀(분석 지시문)

| # | 정할 것 | 지금 상태 |
|---|---|---|
| ㄱ | **안전 사본으로 실제 분석을 한 번 돌려 원본 때의 결과와 나란히 볼 것인가** | 구조와 입력 조립만 확인했다. 모델이 내는 분석의 동일성은 확인하지 않았다 — 실서비스 연동 후 검증 필요 |
| ㄴ | **예시의 사물 표현 셋**을 가상의 것으로 바꿀 것인가 | 실제 인터뷰에도 나오는 일상 사물의 명사구다. 사람을 가리키지 않아 바꾸지 않았다(`analysis_prompt_safety.md` §2) |
| ㄷ | **원본의 해시를 저장소 어디에도 적지 않는다**는 원칙을 지킬 것 | 원본과 사본이 짧은 이름 하나만 달라, 해시가 공개되면 이름을 맞춰 볼 수 있다 |

## 다애님(소설체) — 연동 때 확인하면 좋은 것

| # | 확인할 것 | 까닭 |
|---|---|---|
| A | **기준 모델** — 수정본은 Sonnet 5.5로만 돌렸다 | 원본은 GPT 와 Sonnet 을 모두 돌렸다 |
| B | **장 단위로 이어 쓸 때** `[이번 요청 메모]` · `[앞 장에서 이어받을 내용]` 을 어떻게 채우는가 | 채워서 돌린 기록이 없다 |
| C | 소설체의 **사실 확인을 어떻게 할 것인가** | 출력에 사실 표시 · 각색 기록이 없다 |
| D | 원본을 더 고칠 계획이 있는가 | 원본이 바뀌면 수정본을 다시 파생해야 한다(변경 규칙은 기록돼 있다) |
