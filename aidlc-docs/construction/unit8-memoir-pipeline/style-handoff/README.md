# 「내말싸미」 자서전 문체 3종 — 전달 자료(3판)

준비일 2026-11-11 · 상태 **전달 준비 완료(서비스 연동 전)**. 이 자료는 구현 · 배포가 아니라, 백엔드 담당자가 연동을 시작할 수 있도록 **기준 프롬프트와 규격을 고정해 넘기는 것**이다. 문체 프롬프트와 분석 지시문은 아직 어느 운영 코드에서도 읽지 않는다 — 올려도 서비스 동작은 바뀌지 않는다.

2판에서 달라진 것은 둘이다 — ① **분석 지시문을 안전 사본으로 넣었다**(실제 인터뷰의 인물 이름 하나를 가상 식별자로 바꾼 사본) ② **소설체 최소 수정 v1 에 대한 다애님 승인을 반영했다.** 문체 프롬프트 세 개 · 스키마 · 예시 · 참조 구현은 2판과 바이트까지 같다.

- 세 프롬프트는 **검증 원고를 만든 파일과 바이트까지 같은 사본**이다. 문장 · 줄바꿈 · 파일 이름을 바꾸지 않았다. 전체 해시와 출처는 `style_manifest.json`.
- 소설체는 다애님의 구운몽ST 원본에서 꿈 · 기시감 · 미래 예지 서술을 요구하는 구절만 뺀 판이다. 무엇을 뺐는지는 `novel_prompt_diff.md` 한 장에 있다. 승인은 사용자가 전달한 것이며, 승인 날짜와 증빙 파일은 확인되지 않아 적지 않았다.
- 구운몽ST 원본과 분석 지시문 원본은 이 자료에 없다.
- 내부 ID는 제안값이다. 팀 백엔드에는 이미 `backend-agent/app/session/style.py`(spoken · 예약된 novel · cyworld)가 있다 — 정합은 백엔드 담당자가 정한다.
- 모델은 백엔드 담당자가 정한다. 다만 **검증된 조합이 아니면 문체가 달라질 수 있다** — 검증된 모델과 설정은 `style_manifest.json` 의 `verified_runs`.

## 먼저 알아야 할 다섯 가지

1. **세 문체는 입력과 출력의 모양이 서로 다르다.** 수필체 · 문학체는 "분석 결과로 만든 장 자료 묶음 → JSON 원고"이고, 소설체는 "원문을 끼워 넣은 프롬프트 하나 → 본문 텍스트"다. 소설체에는 제목 · 사실 표시 · 각색 기록이 없다.
2. **수필체 · 문학체는 두 단계다.** 원문 → (분석 지시문) → 분석 결과 → (묶음 조립) → 장 자료 묶음 → (문체 프롬프트) → 원고. 분석 지시문 · 분석 출력 스키마 · 묶음 조립 참조 구현이 이 자료에 모두 들어 있다. 수필체는 여기에 **확정 제목**이 따로 있어야 한다. 소설체는 분석 없이 돈다.
3. **기존 파이프라인의 지시문 로더로 읽으면 안 된다.** 그 로더는 공통 지침을 앞에 붙이고 코드 울타리 줄을 지운다 — 검증한 프롬프트와 다른 글이 된다. 네 파일 모두 파일 그대로 읽는다(`backend_handoff.md` §2).
4. **Windows 에서 받으면 줄바꿈이 바뀔 수 있다.** 팀 저장소의 기본 설정(`core.autocrlf=true`)으로는 프롬프트가 CRLF 로 풀려 해시가 달라진다. 문체 폴더에 변환을 끄는 `.gitattributes` 를 함께 넣었다(임시 저장소에서 올리고 받아 확인 — `validation_report.md` §6).
5. **분석 지시문 안전 사본은 모델로 돌려 본 적이 없다.** 예시의 이름 하나만 다르지만, 원본 때와 같은 분석이 나오는지는 실서비스 연동 후 확인해야 한다(`analysis_prompt_safety.md` §5).

## 점검하는 법

```bash
cd backend-agent
python -m pytest tests/test_style_handoff.py -q
```

모델을 부르지 않는다. 이 테스트가 통과한다는 것은 **파일이 그대로이고 형식 계약이 맞다**는 뜻이지, 서비스에서 집필이 된다는 뜻이 아니다.

## 판정

**READY — GitHub 업로드용 묶음으로서.** 두 상태를 나눠 적는다.

- **GitHub 업로드 준비: 됨.** 올릴 파일 27개는 전부 신규이고, 검증을 통과했으며, 기존 파일과 다른 팀원의 변경을 건드리지 않는다. 실제 업로드는 별도 지시가 있을 때 한다.
- **실제 서비스 연결 준비: 안 됨.** 문체에 따른 분기 · 분석 호출 · 응답 규격 · 모델과 상한이 모두 백엔드 구현을 기다린다(`backend_handoff.md`). 안전 사본으로 받은 분석과 서비스 경로의 집필은 검증된 적이 없다.

근거는 `validation_report.md` 끝.
