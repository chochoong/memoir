# 입력 · 출력 규격

실험 실행기와 실제 호출 기록에서 **확인된 것만** 적었다. 확인하지 못한 것은 "미확인"으로 적었다. 없는 필드를 필수라고 적지 않았다. 아래의 상대 경로는 `backend-agent/첨부프롬프트_md/문체/` 기준이다.

## 1. 한눈에

| | 수필체 `essay` | 문학체 `literary` | 소설체 `novel` |
|---|---|---|---|
| 프롬프트의 역할 | 시스템 프롬프트 | 시스템 프롬프트 | **템플릿** — `{{SOURCE_TEXT}}` 에 원문을 넣은 글 전체가 입력 |
| 메시지 구성 | 시스템 = 프롬프트 · 사용자 = 장 자료 묶음 | 시스템 = 프롬프트 · 사용자 = 장 자료 묶음(틀이 다름) | **사용자 메시지 하나 · 시스템 없음**(검증 실행이 그랬다) |
| 집필 단위 | 장 하나(이야기 3~4개) | 장 하나(이야기 3개로 검증) | 장 하나(이야기 3개로 검증) |
| 인터뷰 원문 | 장의 이야기 전문 | 장의 이야기 전문 | 장의 원문 |
| 분석 결과 | **필요** | **필요** | 쓰지 않음 |
| 사실 원장 | **필요** | **필요** | 쓰지 않음 |
| 지킬 세부 · 감정 · 주의 | **필요** | **필요**(+ 회고 · 인물 · 때 · 곳 · 들은 이야기 · 직접 인용) | 쓰지 않음 |
| 집필 방향(분석의 제안) | **필요** | 주지 않음 | 쓰지 않음 |
| 제목 | **확정 제목이 입력에 있어야 한다** | 임시값 「제목 미확정」으로 돈다 | 없음 |
| 출력 | JSON | JSON(각색 기록 필드가 더 많음) | 본문 텍스트 |
| 사실 표시 · 각색 기록 | 있음 | 있음(은유는 싣지 않음) | **없음** |
| 문단 안 줄바꿈 | 관찰되지 않음 | **허용**(프롬프트가 명시 · 검증 원고에는 0) | 대사마다 줄바꿈 · 장면마다 빈 줄 |
| 따옴표 대사 | 원문의 직접 인용만 | 자유(쓰면 독립 문단 · 각색 기록) | 적극 사용 — 전부 창작일 수 있다 |

## 2. 수필체 · 문학체의 입력 — 장 자료 묶음

두 문체는 **같은 분석 결과**에서 만든 자료 묶음을 사용자 메시지로 받는다. 조립 규칙은 `reference/bundle_reference.py` 가 그대로 보여 준다 — `essay_user_message()` · `literary_user_message()`. 결과의 모양은 `examples/essay_user_message.sample.md` · `examples/literary_user_message.sample.md`(가상 자료로 참조 구현이 실제로 만든 글).

### 분석 결과 — `schemas/analysis_output.schema.json`

실험 실행기의 스키마를 그대로 꺼낸 것이다. 이 결과를 만드는 지시문은 `analysis/0_원문분석_목차통합_안전사본.md` 이고, 원문을 넣는 법은 `backend_handoff.md` §3 에 있다. 묶음이 쓰는 필드:

| 수준 | 필드 | 쓰이는 곳 |
|---|---|---|
| 이야기 | `turn`(이야기 번호) · 원문 전문(분석 결과가 아니라 따로 준다) | 두 문체 |
| 이야기 | `facts[]` — `id` · `text` · `source`(self/heard/view) · `certainty`(stated/approx/uncertain) | 두 문체 — 사실 원장 |
| 이야기 | `must_keep[]` | 두 문체 — 반드시 남길 세부 |
| 이야기 | `emotion_notes[]` — who · kind · target · intensity · when · explicit · evidence | 수필체(집필 방향 안) · 문학체(감정 기록) |
| 이야기 | `reflections_now[]` · `people[]` · `time[]` · `places[]` · `heard[]` · `quotes[]` · `title_hint` | 문학체 |
| 장 | `id` · `stories[]`(장에 든 이야기) | 두 문체 |
| 장 | `center_scene` · `emotion` · `direction` | **수필체만** — '이 편의 집필 방향' |
| 장 | `fiction_notes` · `avoid_overlap` | 두 문체 — 주의 |
| 장 | `title_basis.candidates[]` | 묶음에 쓰지 않는다 — 제목 **후보**일 뿐이다(§5) |

스키마에 있으나 묶음이 쓰지 않는 필드: `book_title` · `events` · `objects` · `emotions_then` · `fact_ids` · `title_basis`.

### 분석 결과 밖에서 와야 하는 것

| 값 | 누가 정하는가 | 실험에서는 |
|---|---|---|
| **확정 제목** `chapters[].title`(수필체) | 제목 확정 단계 또는 사람 | 후보를 따로 평가 · 선정했고, 적격 제목이 없으면 비우고 멈췄다. 분석 스키마에는 이 키가 없다 — 참조 구현은 없으면 오류를 낸다 |
| **민감 여부** `sensitive` | 호출하는 쪽 | 낱말 규칙과 사람이 고른 이야기 번호 목록으로 정했다(이 자료에 없음) |
| **참고 분량** `target_chars`(문학체) | 호출하는 쪽 | 원문 1,234자(공백 제외)에 4500~7000자 한 조합만 검증 |
| 추가 주의 `extra_cautions`(수필체) | 호출하는 쪽 · 선택 | 일부 이야기에 사람이 적은 주의 문구를 덧붙였다 |

### 두 문체의 틀 차이

같은 내용을 서로 다른 머리 문구로 싣는다. 문구가 문체에 영향을 주므로 섞어 쓰지 않는다.

| 자리 | 수필체 | 문학체 |
|---|---|---|
| 첫 줄 | `# c1 「확정 제목」` | `# c2 — 제2장(제목 미확정) · 이야기 41 · 42 · 43` |
| 분량 | "참고 목표 원문의 2~3배. 분량을 채우려 반복하거나 불필요한 장면을 만들지 않습니다." | "참고 분량 4500~7000자. 넓게 펼쳐 쓰는 장입니다." |
| 이야기 | 첫 이야기 번호 · 민감 여부 | "N개 이야기가 모두 충분한 문학적 무게를 가져야 합니다. 순서와 배치는 자유입니다." |
| 집필 방향 | 중심 장면 · 중심 감정 · 구성 방향 · 목차 · 감정 관계 | **없음**(문체 지침은 프롬프트뿐) |
| 감정 · 회고 · 인물 · 들은 이야기 · 직접 인용 | 집필 방향 안에 감정만 | 절마다 따로 |
| 일화 연결 | — | "원문에 없는 사건 · 원인 · 결과를 만들지 않습니다. 이미지 · 정서 · 상징으로 잇는 것은 자유입니다." |
| 마지막 줄 | "위 자료로 이 편을 집필해 JSON 하나만 출력하세요." | "위 자료로 이 장을 극서정 문학체로 집필해 JSON 하나만 출력하세요." |

문학체 실험에서 **일부러 뺀 문구**: "하한이 아닙니다" · "완성도가 분량보다 중요합니다" · "장면을 덮지 않음" · "독립된 채로 두어도 됩니다". 이 문구들이 들어가면 원고가 짧아졌다(앞선 문학체 실험에서 관찰). 문학체 자료에 다시 넣지 않는다.

### 참조 구현이 그대로 옮긴 사소한 것

- 수필체 자료의 둘째 줄은 이야기 번호를 **첫 번째 것만** 찍는다(`- 이야기: 41 · 민감: true`). 원문과 사실 원장에는 모든 이야기가 있다. 실행기의 표기일 뿐이지만 검증한 입력과 같게 두었다.
- 문학체 자료의 민감 문구는 "있음(사고 · 위험 — …)" 한 가지다. 검증한 장이 그런 장이었다. 다른 종류의 민감한 기억에 맞는 문구는 **검증된 것이 없다.**

## 3. 소설체의 입력 — 템플릿

- `novel/prompt_소설체_최소수정v1.md` 의 `{{SOURCE_TEXT}}`(한 군데)를 그 장의 원문으로 바꾼다 — `reference/bundle_reference.py` 의 `novel_user_message()`. 그 글 전체를 **사용자 메시지 하나**로 보낸다. 시스템 프롬프트 · 출력 형식 강제는 없다.
- 원문은 손대지 않고 넣었다(검증 실행의 원문은 줄바꿈이 CRLF 인 텍스트 파일의 해당 구간이었다 — 정규화하지 않았다).
- 템플릿 안의 두 절은 선택 입력이다. 검증 실행에서는 **안내 문구 그대로** 두었다.
  - `[이번 요청 메모 — 선택]` — 집필 범위 · 작품 내 위치.
  - `[앞 장에서 이어받을 내용 — 선택]` — 직전 장 끝부분 · 이어지는 시절과 장소 · 이미 세운 감각 단서. **채워서 돌린 기록은 없다.**
- 사실 원장 · 분석 결과 · 목차 · 제목은 받지 않는다.
- 가상 견본(도서관 · 우산)이 프롬프트에 들어 있다. 실제 인물과 무관하다.
- 원문에는 실제 인터뷰가 들어간다 — 요청 기록을 남길 때 주의.

## 4. 출력

### 수필체 — `schemas/essay_output.schema.json`

```
essay_id      문자열  자료의 장 식별자
title         문자열
paragraphs    문자열 배열  본문 문단
facts         [{id, where}]  사실 원장의 id 마다 한 번 · where 는 본문에 글자 그대로 있는 구절
quotes_kept   문자열 배열
fiction       [{text, type, basis, risk, human_check}]  type 은 자유 문자열(분위기 · 감각 · 행동 · 비유 · 감정 · 내면 · 연출 · 순서 · 장면 · 상징)
notes         문자열
```

### 문학체 — `schemas/literary_output.schema.json`

수필체와 최상위 키가 같다. 다른 것은 각색 기록뿐이다.

```
fiction       [{text, type, basis, risk, conflict, human_check, note}]
              type 은 8개 중 하나: 감각·분위기 창작 · 사소한 행동 창작 · 화자 내적 독백 · 가상 대화 ·
                                   다른 인물의 내면 추론 · 장면 순서 재배치 · 상징·비유 · 사실 기반 재구성
```

- 문학체의 `fiction` 은 **은유를 하나하나 싣지 않는다**(프롬프트의 설계). 중심 이미지, 실제 사건으로 오해될 수 있는 비유, 실제처럼 읽히는 창작만 싣는다.
- `paragraphs` 의 문자열 안에 줄바꿈(`\n`)이 올 수 있다. 한 문장으로 된 문단도 온다.

### 소설체 — 본문 텍스트

- JSON이 아니다. 제목 줄 · 머리말 · 작업 보고가 없다(프롬프트: "소설 본문만 출력한다").
- 장면은 빈 줄로, 대사는 줄바꿈으로 나뉜다. 검증 원고: 공백 제외 3,427자 · 빈 줄로 나뉜 덩어리 66 · 따옴표 발화 33.
- 검증 원고의 따옴표는 **곧은 모양(`"`)**이었다. 프롬프트의 견본은 굽은 따옴표(`“ ”`)다 — 대사를 따옴표로 찾는다면 두 모양을 모두 본다.
- 모양은 `examples/novel_output.sample.txt`(가상).

### 공통으로 저장해야 하는 실행 정보(실험 기록에 실제로 있던 것)

모델 · 설정(effort · 출력 상한) · 종료 사유(`stop_reason` 또는 `status`) · 입력/출력 토큰 · 비용 · 시간 · **프롬프트 해시** · 입력 해시 · 응답 id.

## 5. 제목

| | 동작 |
|---|---|
| 수필체 | 입력에 확정 제목이 있어야 한다. 그런데 지시문은 `"title": "편 제목(새로 짓습니다)"` 라고 적혀 있어, **모델이 다른 제목을 내는 일이 있다**(저장 결과 9개 중 4개). 실험에서는 책을 조립할 때 목차의 제목을 썼고, 모델이 낸 제목이 다르면 기록만 했다 |
| 문학체 | 자료가 준 값을 글자 그대로 낸다. 검증 실행에서는 임시값 「제목 미확정」을 그대로 냈다 |
| 소설체 | 제목을 내지 않는다 |

**어느 문체든 모델이 낸 `title` 을 확정 제목으로 쓰지 않는다.** 제목은 목차 쪽에서 오고, 검증된 것만 전달한다(`backend_handoff.md` §6).

## 6. 형식을 지켜야 하는 곳

1. **문단 경계를 합치지 않는다.** 문학체는 한 문장 문단과 문단 안 줄바꿈이 표현의 일부다. 소설체는 대사마다 줄이 바뀐다.
2. **공백을 한꺼번에 정규화하지 않는다.** 줄바꿈을 공백으로 바꾸면 소설체의 대사와 문학체의 행이 한 줄이 된다.
3. **문장 단위로 쪼개 한 줄씩 합치지 않는다.** 현재 서비스 응답의 `body` 는 문장마다 줄을 바꿔 합친 글이다 — 문단 경계가 사라진다(`compatibility_report.md` §3).
4. 사실의 자리(`facts.where`)와 각색 구절(`fiction.text`)은 **본문에 글자 그대로** 있어야 대조된다. 본문을 고치면 대조가 깨진다.
5. Markdown · PDF로 낼 때 문단 안 줄바꿈은 줄바꿈으로 남긴다(Markdown은 줄 끝 공백 둘 또는 `<br>`).
