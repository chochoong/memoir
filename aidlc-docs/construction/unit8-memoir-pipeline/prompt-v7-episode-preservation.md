## 지시문 변경 (v5 → v7)
- **분석**
  - 한 메모에 출처 · 불확실성 · 부정의 범위가 섞이면 나눕니다.
  - stated / approx / uncertain의 뜻은 그대로 두고, 흐림이 걸린 대상은 원문 표현대로 time · 메모에 남깁니다.
  - 직접 말한 감정 · 본 일은 self입니다. view는 평가 · 추측 · 판단에만 씁니다.
- **목차**
  - 문단은 "기억의 흐름"입니다. 긴 기억은 여러 문단에 걸칠 수 있습니다.
  - core에 필수 경위를 담습니다. 개수는 강제하지 않습니다.
  - 독립 일화는 주제 차이만으로 빼지 않습니다. 기억 단위 전체를 빼면 따로 기록합니다.
  - 상세 서술의 주된 구간은 한 곳입니다. 재언급은 role에 적습니다.
  - 제목이 가리키는 경험은 문단 계획에 있어야 합니다.
- **장 집필**
  - 메모 하나를 문장 하나로, 발언 하나를 문단 하나로 옮기지 않습니다.
  - 상황 · 행동 · 선택 · 결과로 경위를 씁니다. 분량은 필요한 만큼입니다.
  - 경위가 계획에서 빠졌으면 review_notes에 적습니다.
  - 흐림은 흐린 대상에만 둡니다. "생각한다 · 것 같다"는 필수 문형이 아닙니다.
  - 감정의 대상 · 세기 · 시점을 지키고, "그래서 그런지"처럼 유보한 인과는 유보한 채로 씁니다.
- **편집**
  - 사건을 합쳐 경위를 지우지 않습니다.
  - 삭제보다 통합을 먼저 검토하고, 짧은 연결은 남깁니다.
  - 표현만 줄인 것은 omitted에 적지 않습니다. 사실을 뺐으면 부수 사실이라도 이유를 적습니다.
  - "중복" 이유에는 남은 사실 id를 적되, id가 남은 것을 뜻이 남은 증거로 보지 않습니다.
  - 목차가 뺀 사실은 다시 적지 않습니다.
  - certainty_lost는 흐린 대상에만 고치고, 예시 문구를 일괄 덧붙이지 않습니다.
  - opinion_as_fact는 원장 분류가 틀려 보이면 kept + 이유로 남깁니다. 남은 문제로 집계됩니다.
  - 편집에서 새로 만든 장 사이 재언급은 fix로 남고, 검증 · 사람이 판단합니다.
- **검증**
  - 원문 → 원고로 누락 · 변형을, 원고 → 원문으로 더해진 사실을 봅니다.
  - 생각한다 · 것 같다의 개수만으로 오류를 확정하지 않습니다.
  - 흐림의 범위와 감정의 대상 · 시점을 봅니다.
  - plan.protected_omissions · plan.omission_review를 원문과 대조합니다.
  - Q4는 보존과 배치로 채점합니다.
  - 원문 순서나 문단 길이만으로 나열이라 판정하지 않습니다.
  - 제목은 원문에 없으면 사실 문제, 원문에는 있고 본문 근거가 부족하면 `composition / theme_contradiction / warning`(Q1 반영)입니다.

## 코드 변경 (`app/session/memoir_pipeline.py`)

| 대상 | 변경 |
|---|---|
| `keep_findings` | 목차 생략과 편집 생략을 나눠 받음. 목차가 뺀 must_keep → `must_keep_excluded`(review). 편집이 뺀 must_keep → `must_keep_omitted`(**fix** — 이유가 있어도 미해결) |
| `core_findings` | 편집이 이유와 함께 뺀 core → `core_omitted` **fix**(전에는 info). 이유 속 id로 낮추지 않음 |
| `all_findings` | omitted = 목차 생략, edit_omitted = 편집 생략. final이면 `episode_findings` 포함 |
| `episode_findings`(새) | 채택(facts + brief)한 기억 단위가 최종본에서 통째로 사라지면 `episode_missing`(이유 없음) · `episode_omitted`(이유 있음), 둘 다 fix. 목차가 단위 전체를 뺐으면 `episode_excluded` review. 본문에 남은 단위는 보지 않음. main / minor를 가리지 않음 |
| `omission_candidates`(새) | edit_trace를 다시 쓰며 반환 모양은 바꾸지 않음. `fact_dropped` · `fact_changed`(같은 id라도 덜어 낸 문장에 들었거나, 사실 범위의 수 · 부정 · 전언 · 흐림 표지가 사라짐) · `fact_new`. 후보마다 원문 근거 · 초안 표현 · 편집본 표현 · 생략 이유. 코드 오류는 내지 않음 |
| `protected_omissions`(새) | 보호 대상 판정(core · must_keep · episode)의 대상 사실 · 지적 · 원문 · 이유에 적힌 id의 편집본 표현 |
| `check_outline` | facts로 서술하는 일화에 core가 하나도 없으면 경고. 형식 오류 · 게이트와 관계없고, `verify_plan → plan.checks`로 검증에 감 |
| `run()` | 최종 판정에 목차 생략과 편집 생략을 나눠 넘김. `04_omission_review.json` 기록. `plan.omission_review` · `plan.protected_omissions` |
| `verify_message` | 두 입력의 설명 추가 |

- 상태 체계는 그대로입니다: 미해결 fix → code_gate attention → `needs_revision`. 사람 검수 경로도 그대로입니다.

  - 불확실성 번짐 · 감정 변형 · 제목 불일치 · 유보된 인과는 지시문과 검증 몫이라 코드 테스트로 효과를 볼 수 없습니다.

## 추가 보완 (2026-10-29) — 당시의 경험과 지금의 회고
- 같은 v7 파일 다섯 개에 문구만 더했습니다. 새 판, 코드, 출력 키, source · certainty의 뜻, 누락 판정은 바꾸지 않았습니다.
- 단계별 추가 문구:
  - 분석: 당시의 감정 · 판단과 지금의 해석을 나눕니다. 해석이 어느 일에 관한 것인지 메모에 드러나게 하되, 원문이 잇지 않은 사건과는 잇지 않습니다. 영향은 화자가 말한 경우에만 남기고, 회고라는 이유만으로 view로 두지 않습니다.
  - 목차: 핵심 일화는 깊게 쓰고, 다른 일화는 배경 · 연결 · 대조를 맡깁니다(빼지 않음). 연결 지점은 role에 적습니다. 회고를 일화마다 끝에 되풀이하지 않고, 같은 교훈으로 해석하지 않습니다. 당시의 감정 · 지금의 회고는 core로 고를 수 있지만 자동으로 넣지는 않습니다.
  - 장 집필: 그때의 나와 지금 돌아보는 나를 구분합니다. "그때는 몰랐지만 지금은 안다"는 원문 근거가 있을 때만 씁니다. 회고가 없으면 사건과 당시의 감정으로 맺어도 됩니다. 상처로 남은 일을 성장 · 화해로 맺지 않습니다. 영향 · 깨달음은 원문이 말했을 때만 쓰고, "영향이 있었던 것 같다"의 유보는 지킵니다.
  - 편집: 장의 중심과 다르다는 이유만으로 회고를 덜지 않습니다. 같은 뜻의 회고만 모으고, 시점 · 대상 · 감정이 다르면 중복이 아닙니다. 당시 → 지금의 관계를 확인하고, 성장 · 화해 · 용서 · 감사를 덧붙이지 않습니다. 다음 세대에게 한 말은 살리되 부풀리지 않습니다.

- 검증: 지시문 로딩 테스트에 단계마다 새 문구 하나씩 확인을 더했습니다. 전체 309개 통과, 외부 호출 시도 0회입니다.
