# 단위 8P — 책다운 자서전을 위한 구조 재설계안 (v5 설계, 구현 전)

- 작성 2026-10-26 · 근거 자료: v3 C(073058Z) · v4 한 장 2회(081430Z · 083021Z) · v4 C 전체(083510Z) · 지시문 v4 다섯 개
- 이 문서는 **분석과 계획만** 담는다. 코드 · 지시문 수정, Gemini 호출 없음. v1~v4 자료 · 결과는 그대로
- 목표를 바꾼다: 인터뷰 요약 · 발언 연결문이 아니라 **독자가 책의 한 장으로 읽는 담백한 1인칭 회고 수필**

## 0. 요약
1. 나열은 모델 한 단계의 버릇이 아니라 **계약 전체가 만든 결과**다. 분석은 턴마다 사건을 만들라고, 목차는 모든 사건을 빠짐없이 나눠 담으라고, 장 집필은 문장마다 근거를 달고 연결어를 쓰지 말라고, 편집은 순서를 바꾸지 말라고, 검증은 완성도를 보지 말라고 지시한다. 모델은 그 지시를 잘 따랐다
2. 그래서 구조를 바꾼다: 분석은 **사실 장부 + 기억 단위**, 목차는 **책 설계도(장의 중심 · 문단 계획 · 선택과 생략)**, 장 집필은 **문단 단위 서사**, 편집은 **구성을 바꿀 수 있는 편집자**(바뀐 곳은 코드가 계산해 추적), 검증은 **사실 + 독자 기준 채점**(코드가 느슨한 채점을 되돌림). 다섯 번 호출 구조는 그대로
3. 모델 적합성: 분석 · 목차의 문제는 계약 원인이 우세하다. 검증은 모델 한계가 일부 보인다(분명한 들은 말 오류를 놓침). **집필 · 편집은 계약과 모델이 섞여 있어 지금 자료로는 가를 수 없다** → 같은 입력으로 계약 × 모델을 바꾸는 작은 비교 시험(호출 9~10회)을 제안
4. 다음 품질 시험은 전체가 아니라 **큰언니와 재봉틀 한 장**. 연결형과 서사 재구성을 가르는 8항목 기준 + 블라인드 비교로 판정

- 읽는 법: **v4 C 전체는 39턴을 하나도 빼지 않고(39/39), 83%를 턴 하나 = 문장 하나로, 91%를 인터뷰 순서대로 옮겼다. 잇는 문장은 다섯 결과 모두 0이다.** "원문 그대로 0%"(v4 지표)는 정확히 같은 글이 아니라는 뜻일 뿐 나열이 아니라는 뜻이 아니었다
- 사람이 사건을 묶어 준 한 장 시험도 크게 다르지 않다(2차 1:1 대응 11/15). 계획만으로는 풀리지 않는다 — 장 집필 계약 자체가 원인의 하나

## 2. 원인 — 문제 여섯 가지

### 2.1 분석이 39턴을 35개 사건으로 쪼갠다
- 증거: 여러 턴 사건 3개뿐. 개업(21 · 25)과 가게 정리(2 · 35)도 나뉨
- 계약 원인: 「사건은 실제로 일어난 일 하나 … 한 때 · 한 자리의 일」, 「그 안의 따로 떠올린 장면은 따로 둡니다」, 「모든 사용자 발언 턴은 어느 사건의 turns … 에 들어가야 합니다」. v3 의 합침을 막으려고 넣은 규칙이 반대쪽 극단을 만들었다. **"무엇이 일어났나(사실)"와 "책에서 한 덩어리로 읽힐 기억(서사 단위)"을 한 칸에 담은 것**이 근본 원인
- 모델: 규칙을 정확히 따랐다(부산 두 방문 · 두 죽음 분리 성공). 계약 원인 우세

### 2.2 분석의 사건이 그대로 집필 단위가 된다
- 증거: 목차 events = 분석 events, 장 입력 event_packets = 사건마다 턴, 장 지시문 「사건 묶음 순서대로 쓰세요」 → 사건 하나 ≈ 문장 하나
- 계약 원인: 분석과 집필 사이에 **"이 기억들로 어떤 문단을 만들 것인가"를 정하는 층이 없다**

### 2.3 목차가 사건을 나눠 담는 데 그친다
- 증거: 목차 출력은 장마다 사건 목록 · 근거 턴 · 짧은 메모. 장의 흐름 · 문단 계획 · 생략 판단이 없다. ch-2 셋째 문단(딸 결혼 · 아들 · 남편 별세)은 남은 사건 모음
- 계약 원인: 「analysis의 모든 사건은 어느 장의 events나 left_out 중 한 곳에 꼭」 → 사실상 전부 넣기(left_out 0). 「실제 시간 순서와 인과는 바꾸지 마세요」 → 재배치를 못 함. 장의 role 은 한 문장 메모뿐

### 2.4 장 집필이 발언을 순서대로 옮긴다
- 증거: 위 표. 잇는 문장 0, 문장당 턴 1.1
- 계약 원인
  - 문장 항목마다 turns(그 문장의 모든 주장) — 가장 쉬운 정답은 "한 문장 = 한 턴"
  - 「원문에 없는 "그래서", "덕분에", "그 후"를 쓰지 마세요」 · editorial 은 「필요할 때만」 — 문단을 잇는 말을 사실상 금지
  - 「보존할 것」 목록이 길어 모델이 원문 표현을 가까이 붙든다
  - 「사건 묶음 순서대로」 + 사건 = 턴
- 모델: 사람이 짠 계획으로도 1:1 대응이 높았다. 그러나 위 계약이 그대로였으므로 **모델 한계인지 가를 수 없다**

### 2.5 전체 편집이 구조를 바꾸지 않는다
- 증거: v4 C — 장 합치기 0, ch-2 글자 그대로, ch-1 문단 하나 이동(시간 역행), edit_notes 0
- 계약 원인: 「새로 나누거나 순서를 바꾸거나 목차에 없는 장을 만들지는 마세요」 · 할 일 목록 = 코드 경고(checks, 이번엔 0개) → 할 일이 없으면 거의 베낀다. 책 전체를 한 번에 다시 쓰는 출력(약 2,700 토큰)이라 베끼는 쪽이 안전
- 모델: 미확인

### 2.6 검증이 완성도를 보지 못한다
- 증거: v1~v4 실제 실행 모두 issues 0(v1 A3 포함). v4 C 에서 해요체 · 시간 역행 · 들은 말 13 · 폐업 중복 · 나열 모두 놓침
- 계약 원인: 「사람: 주제의 완성도, 흐름, 문학적 완성도. 당신의 pass는 품질 승인이 아닙니다」 — 일부러 맡기지 않았다. 구성 문제는 「보이면 적는다(보통 warning)」 → verdict 에 영향 없음. 코드가 찾은 문체는 「다시 적지 않아도」
- 모델 원인(일부 확인): 들은 이야기를 기억처럼 쓴 것(13)은 지시문 A-2 에 **명시된** source_mismatch 인데 놓쳤다. 같은 계열 모델이 자기 글을 채점하는 관대함도 있다

## 3. 책다운 자서전의 기준 → 확인 가능한 형태

| 기준 | 어떻게 확인하나 |
|---|---|
| 장마다 독립된 서술 목적 · 중심 소재 | 목차의 장 설계(중심 · 서술 질문)와 실제 첫 문단 · 끝 문단 (사람 · 검증 채점) |
| 책 전체의 자연스러운 흐름 | 장과 장의 연결 문장, 처음 · 끝 (사람) |
| 시간 재배치 가능, 근거는 명확 | 재배치한 자리마다 시간 표지가 있고 그 표지가 원문 시점과 맞는가 (코드 신호 + 검증) |
| 흩어진 기억의 통합 | 여러 회차 문단 비율 · 여러 턴 문장 (지표, 목표치 아님) + 사람 |
| 문장 · 문단 · 장의 적극적 재설계 | 1:1 대응 · 턴 순서 유지 지표(신호) + 편집 전후 diff (코드 계산) |
| 담백한 1인칭 ~다 | style_mix (코드) |
| 감정 · 교훈을 억지로 만들지 않음 / 창작 없음 | 검증 A + 사람 대조 (필수) |
| 들은 이야기 · 직접 기억 구분 | 원문 표지(~대요 · ~다고 하더라고요 · 들었)가 있는 턴을 쓴 문장에 전언 표지가 있는가 (코드 신호, 새로) |
| 불확실성 유지 | 원문 표지(~인가 · ~나 · 쯤 · ~ㄹ 거예요 · 것 같)가 있는 턴의 사실을 단정했는가 (코드 신호, 새로) |
| 질문 · 답의 흔적 없음 | answer_trace · stop_phrase (코드) + 블라인드 독자 |

## 4. 다섯 단계 역할 재정의 (호출 수 그대로: 분석 1 · 목차 1 · 장 N · 편집 1 · 검증 1)

### 4.1 분석 → 「기억 지도」
- 두 층으로 나눈다
  - **사실 장부**(facts): 원문 턴에서 나온 사실 단위 — 무엇 · 언제 · 누가, 그리고 `source: experienced | heard`, `certainty: stated | approx | uncertain`. 정정은 정정 뒤 값만 + 정정 턴. 장부가 사실 검증의 기준이 된다. 서로 다른 해의 방문 · 서로 다른 사람의 죽음은 장부에서 반드시 다른 항목(v4 의 분리 규칙은 여기로 옮긴다)
  - **기억 단위**(episodes): 독자가 하나의 이야기로 읽을 덩어리 — 같은 시기 · 같은 자리에서 이어진 일, 같은 일을 여러 회차에서 보탠 말(예: 가게를 연 일 21~26). 사실 여러 개를 묶는다. 단위마다 시점 · 사람 · 무게(main / minor) · 화자가 직접 이은 말
- 끈(threads)은 그대로 + **화자가 직접 이은 근거**(예: 38 이 공장 소리와 언니를 직접 잇는다)
- 들은 말 · 불확실성 표지는 모델에 맡기지 않고 **코드가 원문에서 먼저 찾아** 턴별 표시로 넘긴다(결정적 · 시험 가능 · 토큰 절약). 모델은 표시를 고치거나 보탤 수 있다
- 출력 상한 5,000 → 8,000 검토(v4 C 실측 4,887 로 상한에 붙음)
- 코드 검사: 모든 턴이 장부 · 제외 · not_in_events 중 한 곳 / 기억 단위 대부분이 한 턴짜리면 경고(목표치 아님) / 한 기억 단위 안에 서로 다른 해가 둘 이상이면 경고(v4 규칙 유지)

### 4.2 목차 → 「책 설계도」
- 책: 중심 소재 · 처음 장면 · 끝 장면 · 장 사이 흐름
- 장마다
  - `center`: 이 장의 중심 소재와 서술 질문(이 장이 독자에게 들려주는 것) — 다른 장과 겹치면 안 됨
  - `paragraph_plan`: 문단마다 {하는 일(내부 메모), 쓸 기억 단위 · 사실, 시간 표지, 앞 문단과 이어지는 근거(턴 또는 "중립 연결")}. 문단 수는 정하지 않는다
  - `reorder`: 시간 순서를 바꾼 자리와 이유(근거 턴) — 바꾼 자리에는 본문에 시간 표지가 필요
  - `omit`: 이 책에서 쓰지 않는 사실 · 턴과 이유. **"모든 사건을 어딘가에" 의무를 없앤다** — 단, 무게 main 인 기억 단위 · 마지막 중요 발언 · 정정은 빠뜨리면 실패
- 장 수 1~5 그대로. 남은 것을 모은 장 · 문단은 금지(코드 경고: 문단의 기억 단위가 장 center 의 끈과 하나도 닿지 않으면)

### 4.3 장 집필 → 「문단 단위 서사」
- 입력: 장 설계도의 문단 계획 + 그 기억 단위의 원문 + 사실 장부(전언 · 불확실 표시 포함). 사건 묶음(event_packets)은 쓰지 않는다
- 계약 변경
  - 문장 항목의 turns 는 유지(추적성) — 대신 **한 문장이 여러 사실 · 여러 턴을 종합하는 것을 기본**으로 안내
  - **연결 문장을 정식으로 허용**: `link_time`(시간 연결 — 원문 시점으로 확인되는 것만, 근거 턴 필수) · `link_thread`(끈으로 잇기 — 근거 턴 필수) · `editorial`(새 사실 없는 중립 연결). 금지는 **원문에 없는 인과**("그래서 · 덕분에" 를 원문이 말하지 않았을 때)로 좁힌다
  - 전언 표시 사실은 전언으로("…했다고 들었다"), 불확실 표시 사실은 그대로 흐리게("…였던 것 같다", "…쯤")
  - 쓰는 법 안내(수치 강제 없음): 장 center 의 구체적인 장면 · 물건에서 열기, 끈이 다시 나오는 자리에서 잇기, 원문 화자의 말로 맺기, 모든 세부를 쓰지 않기
- 버리는 것: 「사건 묶음 순서대로」, 「문장 항목 하나에 문장 하나」(근거를 문장마다 다는 장점은 turns 로 이미 있다 — 나열 쪽으로 미는 효과가 더 컸다)

### 4.4 전체 편집 → 「구성 편집자」 (목차를 바꿀 수 있다)
- **목차의 초기 구성은 제안으로 본다.** 편집이 할 수 있는 일: 장 합치기 · 나누기 · 순서 바꾸기, 문단을 다른 장으로 옮기기, 문단 다시 쓰기, 문장 덜어 내기(생략 목록에 이유), 연결 문장 넣기. 장 수 1~5
- 출력 순서를 강제해 진단을 먼저 하게 한다(호출은 한 번): `diagnosis`(책 전체의 문제 3~5개, 위치) → `revised_outline`(바뀐 장 설계와 이유) → `chapters`(개정 본문) → `omitted` → `checks_resolution`
- 입력에 코드 신호를 준다: 장마다 1:1 대응 · 턴 순서 유지 · 연결 문장 수 · 전언/불확실 신호 · 시간 역행 신호 — "이 장은 발언 나열 신호가 있다"를 할 일로
- **추적성은 코드가 지킨다**: 바뀐 곳(옮김 · 합침 · 덜어 냄 · 다시 씀)을 초안과 편집본의 문장 · 근거 턴 대응으로 **코드가 계산**해 `04_edit_trace.json` 에 남긴다. 모델의 edit_notes 는 이유 설명용(없어도 실패 아님) — v4 C 처럼 바꾸고 기록하지 않는 일을 막는다
- 코드 검사(편집 뒤): 근거 턴이 입력에 있는가 · 제외 재등장 · main 기억 단위와 마지막 발언이 남았는가 · 재배치 자리의 시간 표지 · 전언/불확실 신호 · 문체 — 지금의 code_gate 에 더한다
- 출력 상한 8,000 은 Seed C 규모(장 2~3, 약 2,500자/장)에 충분. 더 큰 자료에서는 장 수 상한과 함께 다시 본다

### 4.5 검증 → 「사실 대조 + 독자 기준 채점」
- A 사실(지금과 같음, blocker) — 사실 장부와 대조. 들은 말 · 불확실성은 코드 신호가 가리킨 문장부터 본다
- B **독자 기준 채점**(새로): 아래 6절 Q1~Q6 를 0 · 1 · 2 로, 항목마다 근거 위치 필수
- verdict: A blocker 없음 **그리고** B 기준 충족일 때만 pass
- **코드가 느슨한 채점을 되돌린다**: 근거 위치 없는 점수 무효, 나열 신호가 강한 장(예: 1:1 대응 60% 이상)에 「재구성 2점」을 주면 코드가 1점으로 내리고 기록. 이것도 approved 가 아니다 — human_review 는 그대로 사람 몫
- 같은 모델이 쓰고 채점하는 관대함은 7절 비교 시험에서 따로 본다

## 5. 출처 추적성은 어떻게 유지되나 (구조 변경이 커져도)
- 문장 항목의 turns 는 끝까지 남는다 — 편집이 문단을 옮기고 합쳐도 문장마다 근거 턴이 따라간다
- 사실 장부가 생겨 "이 문장의 사실이 어느 턴의 어떤 사실인가"를 검증이 장부 항목 단위로 본다
- 바뀐 곳은 코드가 계산(edit_trace). 모델의 자기 보고에 기대지 않는다
- 빠진 것은 `omit` · `omitted` 에 이유와 함께. main 기억 단위 누락은 코드가 막는다

## 6. 품질 시험 — 큰언니와 재봉틀 한 장

### 6.1 연결형과 서사 재구성을 가르는 기준 (사람 채점, 검증 채점도 같은 표)
| # | 항목 | 연결형 신호 (0) | 서사 재구성 (2) |
|---|---|---|---|
| Q1 | 장의 중심과 목적 | 첫 문장이 첫 턴, 끝 문장이 마지막 턴 | 중심 소재(발틀 · 언니)가 처음에 서고, 중간에 다시 나오고, 끝에서 닫힌다 |
| Q2 | 기억의 통합 | 회차마다 따로, 사건마다 한 문장 | 다른 회차의 말이 한 문단 · 한 문장 안에서 만난다(예: 4 · 26 · 27 · 35 · 38) |
| Q3 | 배치와 연결 | 인터뷰 순서 · 사건 목록 순서, 문단 사이 이음 없음 | 서술 순서에 이유가 있고, 넘어가는 자리마다 근거 있는 시간 · 끈 표지 |
| Q4 | 선택 | 받은 턴을 거의 다 씀 | 장 중심에 맞는 것만 고르고, 생략이 뜻을 왜곡하지 않는다 |
| Q5 | 문장의 종합 | 원문 한 턴의 말끝만 바꾼 문장이 이어짐 | 문장이 여러 사실을 엮고 화자의 목소리로 다시 짜였다 |
| Q6 | 목소리 | 해요체 · 질문/답 흔적 · 안내문 | 담백한 1인칭 ~다, 인용은 꼭 필요한 곳만 |
| Q7 | 사실 충실 (필수) | 창작 · 전언을 기억으로 · 불확실을 단정 · 근거 턴 오류 | 위반 0 — 사람이 문장마다 원문 대조 |
| Q8 | 독자 시험 | — | 블라인드로 읽은 사람이 "책의 한 장"으로 받아들이고 기준선보다 낫다고 고른다 |

- 1점은 둘 사이. 항목마다 근거 위치를 적는다
- **통과**: Q7 위반 0 · Q1~Q5 가운데 2점이 넷 이상이고 0점 없음 · Q6 2점 · Q8 에서 읽은 사람 3명 중 2명 이상이 새 결과를 고름
- 수필체이거나 문체가 통일됐다는 것(Q6)만으로는 통과하지 않는다 — Q6 는 필요조건일 뿐
- 지표(1:1 대응 · 턴 순서 유지 · 여러 회차 문단)는 채점 참고로 옆에 둔다. 맞추려고 고치지 않는다
- 기준선: v4 한 장 2차(083021Z). Q1 1 · Q2 1 · Q3 1 · Q4 0 · Q5 0 · Q6 2 · Q7 2(p5/s1 확인) 로 본다(제안) — 기준 미달

### 6.2 블라인드 비교 방법
- 결과마다 근거 턴을 지운 본문만, 무작위 이름(가 · 나 · 다 …)으로
- 읽는 사람: 팀원 2~3명(Seed C 원문을 먼저 읽지 않은 사람 1명 이상). 질문: "책의 한 장으로 읽히는가", "어느 쪽이 더 낫나", "질문과 답이 느껴지는 곳"
- 사실 대조(Q7)는 따로 — 원문을 아는 사람이 문장마다

### 6.3 시험 입력
- 한 장 시험은 v5 계약으로 다시 짠 **계획**(장 center · 문단 계획 · 생략 — 각 160자 이하 메모)과 원문만 넣는다. 예상 정답 수필은 넣지 않는다(trial_plan 의 거부 규칙 유지). 계획은 사람이 짜므로 집필 · 모델만 따로 본다

## 7. 모델 적합성 — 계약 한계와 모델 한계 가르기

### 7.1 지금 자료로 판단할 수 있는 것
| 단계 | 증상 | 계약 원인 | 모델 원인 근거 | 판단 |
|---|---|---|---|---|
| 분석 | 과분절 | 강함(2.1) | 규칙을 정확히 따름 | 계약 |
| 목차 | 나눠 담기 | 강함(2.3) | — | 계약 |
| 장 집필 | 발언 나열 | 강함(2.4) | 사람 계획으로도 나열 | **가를 수 없음** |
| 편집 | 구조 무변경 | 강함(2.5, 금지 조항) | 거의 베낌 | **가를 수 없음** |
| 검증 | issues 0 | 강함(2.6) | 명시된 오류(13)를 놓침 | 둘 다 |

- flash-lite 가 잘한 것: JSON 계약 · 근거 턴 · 제외 · 문체 규칙을 매번 지켰다(6호출 32초 · 입력 6.2만 토큰). 규칙을 따르는 변환에는 충분하다
- 확인되지 않은 것: 여러 사실을 엮어 문단을 짜는 글쓰기, 책 전체를 다시 짜는 구성, 자기 글에 대한 비판적 판단

### 7.2 비교 시험안 (승인 뒤, 무료 등급에서만)
같은 입력으로 **한 번에 한 가지만** 바꾼다. 온도 0.3 그대로.

| 시험 | 입력 | 계약 | 모델 | 호출 |
|---|---|---|---|---|
| A 기준선 | v4 한 장 계획 | v4 | flash-lite | 0 (083021Z 재사용) |
| B | v5 한 장 계획 | v5 장 집필 | flash-lite | 2 (같은 입력 2회 — 흔들림) |
| C | v5 한 장 계획 | v5 장 집필 | 상위 Gemini 모델 1종 | 2 |
| D | v4 한 장 계획 | v4 | 상위 모델 | 1 (옛 계약에서 모델 효과만) |
| E 편집 | v4 C 장 초안(083510Z 저장분) | v5 편집 | flash-lite / 상위 모델 | 2 |
| F 분석 · 목차 | Seed C 전체 | v5 분석 · 목차 | flash-lite | 2 (사람 계획 없이 기억 단위 · 설계도가 서는지) |

- 합계 9회(C · D · E 상위 모델 5회 포함). 상위 모델은 **정확한 모델 ID · 무료 등급 제공 여부 · 한도를 실행 전에 AI Studio 에서 확인**하고, 무료로 안 되면 그 칸은 하지 않고 보고한다. 유료 호출은 승인 없이 하지 않는다
- 판단 규칙
  - B 가 6.1 통과 → 모델 유지, 계약이 원인이었다
  - B 미달 · C 통과 → 집필 · 편집에 상위 모델(분석 · 목차 · 검증은 flash-lite 유지 가능 — 단계별 모델 설정은 이미 있는 `MEMOIR_PIPE_*` 에 단계별 모델 이름만 더하면 된다)
  - B · C 모두 미달 → 계약을 더 본다(모델 탓으로 돌리지 않는다)
  - D 가 A 보다 확연히 낫다 → 모델 효과가 크다는 보조 근거
  - E: 편집이 실제로 구조를 바꾸는지(edit_trace 로 측정)와 사실 위반을 같이 본다

## 8. 진행 순서 (각 단계 승인 뒤)
1. **이 설계 검토 · 승인** — 4절 계약, 6절 기준, 7.2 시험안
2. 구현(호출 없음): v5 지시문 다섯 개(v1~v4 보존) · 사실 장부/기억 단위/설계도/편집 계약 · 코드 신호 4.6 · edit_trace · 검증 채점 검사 · 한 장 시험 v5 계획 파일 · 테스트. 평가 문서 seed-C-evaluation 7항의 "해요체" 문구를 ~다 기준으로 고침
3. 비교 시험 B → (상위 모델 무료 확인) C · D → 블라인드 비교 · 사실 대조
4. 편집 시험 E · 분석/목차 시험 F
5. 결과로 모델 · 계약 결정 → 그 뒤에 Seed C 전체 1회

## 9. 위험과 정할 것
- 구조를 바꿀 자유가 커지면 창작 위험도 커진다 — 사실 장부 · 코드 신호 · 사람 대조(Q7 필수)로 묶는다. Q7 은 한 번이라도 어기면 다른 점수와 상관없이 실패
- 사실 장부로 분석 출력이 커진다 — 상한 8,000 · 전언/불확실 표지는 코드가 먼저
- 편집 한 번에 책 전체를 다시 짜는 것은 책이 길어지면 무리다 — Seed C 규모에서 먼저 확인하고, 길어지면 장 수 상한과 함께 다시 본다
- 블라인드 비교에 사람 2~3명이 필요하다 — 누가 읽을지 정해야 한다
- 상위 모델이 무료 등급에 없으면 C · D · E 상위 칸을 할 수 없다 — 그때 결론은 "계약 시험(B)만으로 판단"
